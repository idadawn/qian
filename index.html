Qian 文档

Qian 平台基于 Kun 框架构建，前端使用 yue 组件库：组件一条命令装进任何项目，组合起来就是为 Agent 时代准备的多租户平台。

三条起步命令

命令与「开始」部分同源；S1 建设期内随任务陆续可用。

① 装一个组件

qian add identity authz files

在 ASP.NET Core 项目里装身份、鉴权、文件三个组件，不用部署 Qian 平台。30 分钟上手 →

② 配置你的编码代理

npx qian@latest --skill files

把组件的技能装进 Claude Code、Codex 等编码代理；代理先读仓库里的 AGENTS.md。详见下一节 ↓

③ 调一个模型 S1·P1

curl "$MODEL_GATEWAY/v1/chat/completions" \
  -H "Authorization: Bearer $MODEL_GATEWAY_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model": "chat-default", "messages": [{"role": "user", "content": "你好"}]}'

经模型网关的 OpenAI 兼容端点发一条请求，用逻辑模型名。模型网关 →

最新动态

  • 2026-10-16
    租户域 RBAC 判定、完整 Explain 与平台超管旁路（S1-AZ-003）

    qian.authz 按租户的真实角色、授权与当前策略版本判定权限，缺省拒绝：缺租户上下文、主体跨租户、未登记权限点或无匹配授权都拒绝，BatchCheck 与逐条 Check 结果一致。判定快照按租户授权修订缓存，授予或撤销后下一次判定即生效（R103）。组件经 ctx.Authz() 调 ExplainDetailedAsync，得到命中角色、授权定位与缺少的权限点。平台超管只能经显式旁路访问租户资源：放行前写入目标租户审计链（bypass = superadmin），审计写不进就拒绝。详见 Qian.Authz。

  • 2026-10-16
    审计哈希链、权限点注册表与默认角色（S1-AUD-001、S1-AZ-002）

    qian.audit 在命令的同一事务里按租户追加哈希链审计：查询默认不记，Audit = true 时记录；输入按 Schema sensitive 脱敏后再取哈希。qian.authz 从组件 metadata/permissions.json / roles.json 登记权限点（独立模式用 [Permission]），新租户开通时实例化默认角色；GET /api/authz/me/permissions 列出当前主体的有效权限及风险、step-up。详见 Qian.Audit、Qian.Authz；复核裁决 R101–R103 见关键决策。

  • 2026-10-16
    qian CLI 包管理器超时可配置（S1-RT-030）

    qian add / remove 调用包管理器的超时缺省 600 秒，可用环境变量 QIAN_PACKAGE_TIMEOUT（1–86400 的整数秒）调整，非法值在任何改动之前以结构化错误失败；预检还原允许并行下载。详见 qian CLI。

  • 2026-10-16
    出网检查缺省值：开发环境放行回环，缺省拒绝 K3s 集群网段（S1-DATA-007）

    数据连接连通测试的出网检查改了两处缺省值。宿主环境为 Development 时缺省放行回环，本机开发连本机数据库不用再改配置。K3s 缺省的 Pod 网段 10.42.0.0/16 与 Service 网段 10.43.0.0/16 并入缺省拒绝列表：原本连这两个网段内数据库的宿主，需要从 Egress.BlockedNetworks 移除对应项；集群改用了自定义网段时，同样移除这两项并追加实际网段。产品负责人已确认 R79，见决策清单与 Qian.Data。

产品能力

按用途找能力：每项一句话，正文只在一个部分写一次。

用 AI 构建

  • 模型网关：一个端点调所有模型，配额、回退、计量（S1·P1）
  • AI SDK：调模型与 Embedding，写 Agent 表面，声明工具副作用与策略
  • Agent 运行时对接：Qian 不写 Agent loop，运行时为 iClaw
  • MCP：组件的 .mcp.json 表面；每租户能力门面（S4）
  • 流程与自动化：审批内核与触发器（S2）
  • 沙箱：隔离执行不可信或 Agent 生成的代码（S4）

构建应用

  • 宿主与框架：独立模式、platform profile、React + yue、与 Kun 的关系
  • Kun 框架：Qian 的底座，.NET 10 微服务框架的模块地图、指南、安全与 API
  • 组件与 qian add：一条命令安装，装上即可用
  • 能力与函数：能力目录；function 表面（S2）
  • 事件与中间件：五种分发模式，waterfall 即环绕中间件
  • profile 与 patch：环境 = profile + 分层 patch
  • yue 与微前端：组件库、外壳与远程模块
  • 存储：文件与数据，租户隔离默认开启
  • 低代码：表单与列表（S2）

多租户平台

  • 租户：租户目录、隔离策略与生命周期
  • 身份与 SSO：OIDC 端点与双层账号
  • 鉴权：权限点注册表与租户域 RBAC
  • 权益：授权 v0；计费（S3）
  • 配置中心：Apollo 与热更新
  • 事件与消息：Outbox 可靠发布
  • 调度与实时：持久化作业与实时推送
  • 市场：上架、信任等级与签名（S3）

保护应用

  • 网关防护：强制认证、路由级限流、可信代理、出网 SSRF 基线
  • 发布保护：制品验签、修订回切、灰度开关
  • 审计：命令级哈希链与实体级同事务审计
  • 密钥：secretRef、按范围授权、轮换

部署与运维

  • GitOps 部署：Argo CD app-of-apps、Kustomize、digest 写回
  • 灰度发布：灰度开关 + profile 滚动更新
  • 修订回切：回到任一保留的修订
  • 可观测：OTel、租户 / 用户 / 插件 baggage、计量事件
  • 模型网关接线：GPUStack → Higress（S1·P1）
