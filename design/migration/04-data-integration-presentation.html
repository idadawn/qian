来源基线：D（数据 / 集成 / 消息 / 调度 / 门户 / 报表 / 打印 / 大屏 / 预览）。相关决策：ADR-004 数据库、ADR-007 Apollo 与密钥、ADR-008 事件、ADR-010 网关、ADR-011 元数据、ADR-015 模型网关、ADR-016 iClaw 边界、ADR-017 部署；PRD §07（S1 技术组件）、§08、§09（门户 / 报表 / 开放 API）、§10（S4 预留）。 口径与优先级标记同映射 01。术语：「数据接口」= 参考平台「数据集 / 数据服务」的统称，定义层带读写属性，消费侧叫「数据绑定」。

#0. 本域的迁移判断

本域子域多而同构，迁移的核心原则是横切能力只在内核实现一次：可发布元数据框架（草稿 / 发布 / 归档 + 生效指针 + 快照）、导入导出框架（判重策略、id 重映射、依赖重连清单）、引用登记、分享链接、预览票据、编码规则、控件注册表契约。参考平台在这些点上每个子域各写一遍（门户 / 报表 / 打印三套状态机命名不一、五种专有包后缀）。实现层面必须外置的进程内状态（WebSocket 连接池、公告延时队列、线程休眠重试、无集群配置的调度器）、必须收口的凭据（三处来源且明文）、必须关闭的任意 SQL / 任意 URL 代理 / 匿名上传，是本域最集中的「必须修正」。阶段上按补充裁决：数据连接与类型系统、数据接口契约、通知、调度、实时推送、凭证引用在 S1；数据建模、接口设计器、打印、文件预览在 S2；门户设计型、报表、开放 API、分享链接在 S3；大屏延后且不复用参考平台大屏源码；AI 中心除模型服务网关外全部 S4。

  2. 模型服务网关的阶段：基线 D 把模型目录与按用途路由列 S2 必做，决策 D18 把「S1 是否含模型网关底座接线」列为可选、D3 标 qian.model-gateway 可选、K 基线标 S1 底座 / S3 门户。本文件按 S1·P1 / S3·P0 写；S2 低代码表单的 AI 入口（S4）不依赖它，但 S2 若要做「模型目录 UI」需提前。
  3. 报表子集与配置路径型门户是否进 S2（已裁决 R16）：保持 S2 可选（P2）；S2 验收所需「可用首页」由应用默认首页（菜单 + 功能列表）满足，不依赖门户。
  4. 服务端 PDF 的技术路线：Q33 定 S3 可选，但归档（流程归档 S3）、邮件附件、Agent 自检都依赖它；无头浏览器在 K3s 的资源与冷启动成本需在 S2 末评估。
  5. 开放接口与 qian.gateway 的分工：开放分组登记到业务网关还是 Higress（MCP / 模型流量）？按 ADR-010 应登记到 qian.gateway，S4 MCP 面由 Higress 托管；需在 PRD §09 明确。
  6. automation 的交付归属（与映射 03 同列）：触发器与动作跨数据、消息、流程三域，由哪个团队交付需明确。
  7. 凭证库选型：K8s Secret 还是 Infisical 作运行时权威（D17 提到 Infisical 注入未接通）；影响 ISecretResolver 实现与连接器插件的凭据字段。
  8. 输入缺口：消息中心（公告、模板、发送配置、接收配置、监控）、任务调度、集成助手的手册分卷未在调研输入内，界面级规则在 PRD 撰写时需补读。
