记录对读者可见的变化：新文档与新规格、新组件与命令、破坏性变更。按日期倒序，每条一个二级标题 ## YYYY-MM-DD 标题，下面一两行说明并链接到详情。文档站首页「最新动态」取最近 4 条（docs-site.md §2a.1）。

#2026-10-25 身份适配器与数据组件的登记先后不再影响能力执行（S1-KUN-017）

Kun 升到 2026.10.25：数据约定与实体审计不再以匿名兜底占住框架当前主体端口，宿主先登记数据组件、后登记身份适配器时能力照常执行（此前一律 403 AUTHZ_DENIED），参考应用、测试宿主与联调栈的绕开写法已撤销。能力宿主的框架当前主体端口若仍解析为匿名兜底，启动即失败并写明改法；只装数据组件、没有身份适配器的宿主照常可用，审计与删除主体写 null。详见 Qian.Plugin.Sdk、Qian.Data。

#2026-10-24 网关路由共享限流（S1-GW-002）

网关 支持 IP、租户和用户三策略及 Redis 共享固定窗口，超限返回带 Retry-After 的 429，Redis 故障返回 503。路由现在必须显式填写 rateLimiterPolicy；仓库配置已迁移，自定义宿主与 profile 需补充该字段。

#2026-10-24 身份客户端可从私有源安装（S1-IDP-015）

qian.identity.client 钉定已发布的 Qian.Identity.Client 0.3.0 及归档摘要，移除骨架标记。真实 qian add identity 安装门校验包源、版本、摘要、表面与 lock，再由宿主按清单挂载 Identity 服务并撤销；发行方与客户端标识由宿主显式配置。

#2026-10-24 通用契约 v0 冻结（S1-AGT-005）

contracts/v0 的六份 Schema 按 R53 / R80 / R119 统一标记为 frozen，后续只接受向后兼容增量，破坏性变更进入 v1。现有字段与约束保持不变；data/v1 引用草稿信封的例外随之解除。

#2026-10-22 输入 Schema 的租户字段检查覆盖 properties 之外的写法（S1-AGT-004）

工具文件与能力契约的输入 Schema 不再只看属性名：required、dependentRequired、dependentSchemas 里出现租户名、propertyNames 用 const / enum 列出租户名，或 patternProperties 的模式能匹配租户名（含 ^[a-z_]+$ 这类通配；超出 ECMA-262 可移植子集、无法判定的模式也算），都会被拒绝，顶层同样适用。开放的映射（没有关闭的嵌套 object）不点名字段，照常通过。此前能通过的组件可能因此装载失败，按错误里的 pointer 修改即可。规则见 packages/Common。

#2026-10-16 租户域 RBAC 判定、完整 Explain 与平台超管旁路（S1-AZ-003）

qian.authz 按租户的真实角色、授权与当前策略版本判定权限，缺省拒绝：缺租户上下文、主体跨租户、未登记权限点或无匹配授权都拒绝，BatchCheck 与逐条 Check 结果一致。判定快照按租户授权修订缓存，授予或撤销后下一次判定即生效（R103）。组件经 ctx.Authz() 调 ExplainDetailedAsync，得到命中角色、授权定位与缺少的权限点。平台超管只能经显式旁路访问租户资源：放行前写入目标租户审计链（bypass = superadmin），审计写不进就拒绝。详见 Qian.Authz。

#2026-10-16 审计哈希链、权限点注册表与默认角色（S1-AUD-001、S1-AZ-002）

qian.audit 在命令的同一事务里按租户追加哈希链审计：查询默认不记，Audit = true 时记录；输入按 Schema sensitive 脱敏后再取哈希。qian.authz 从组件 metadata/permissions.json / roles.json 登记权限点（独立模式用 [Permission]），新租户开通时实例化默认角色；GET /api/authz/me/permissions 列出当前主体的有效权限及风险、step-up。详见 Qian.Audit、Qian.Authz；复核裁决 R101–R103 见关键决策。

#2026-10-16 qian CLI 包管理器超时可配置（S1-RT-030）

qian add / remove 调用包管理器的超时缺省 600 秒，可用环境变量 QIAN_PACKAGE_TIMEOUT（1–86400 的整数秒）调整，非法值在任何改动之前以结构化错误失败；预检还原允许并行下载。详见 qian CLI。

#2026-10-16 出网检查缺省值：开发环境放行回环，缺省拒绝 K3s 集群网段（S1-DATA-007）

数据连接连通测试的出网检查改了两处缺省值。宿主环境为 Development 时缺省放行回环，本机开发连本机数据库不用再改配置。K3s 缺省的 Pod 网段 10.42.0.0/16 与 Service 网段 10.43.0.0/16 并入缺省拒绝列表：原本连这两个网段内数据库的宿主，需要从 Egress.BlockedNetworks 移除对应项；集群改用了自定义网段时，同样移除这两项并追加实际网段。产品负责人已确认 R79，见决策清单与 Qian.Data。

#2026-10-16 qian add / remove / list 从 GitHub Packages 真实安装（S1-RT-011）

qian add <组件>… 经签名市场把表面复制到 .qian/plugins/<id>/、按组件清单钉精确版本从 GitHub Packages 还原代码包、写 profile patch 与 .qian/lock.json，qian remove 逆序撤销、qian list 列出来源；未通过校验器或验签时以一行结构化错误失败且不留残留。真实源 E2E 用 data / events / config 三个组件（R98），PRD 7.2.3 的表面目录、patch 路径与钉版措辞按规格 §9 改写（R100）；收口项见 S1-RT-035。用法见 qian CLI README。

#2026-10-16 Qian 包族 0.1.0 发到 GitHub Packages，SDK 源生成器与清单漂移门（S1-RT-014）

Qian.* 35 个包以 0.1.0 锁步发布到 GitHub Packages（随公开仓库可见，安装需 GitHub 令牌，R93）；Qian.Plugin.Sdk / Qian.Plugin.Sdk.Generators 从 [QianPlugin] / [Capability] 派生 inject / provides / runtime 与 tools/*.json，qian-plugin check 在 CI 比对 qian.data / qian.events / qian.config 的清单与代码；PluginEnabledMiddleware 对未挂载组件返回 404。SDK 范围的 S1 收敛与后续见 R94 与 S1-RT-033；安装方式见 SDK 文档。

改了任务文件只提交任务文件。pm/index.html、pm/tasks.json、pm/STATUS.md 不再提交，PR 也就不会再因它们互相冲突。集群看板由看板 Pod 按 main 自行生成；CI 把生成的看板上传为工作流产物；本地 pm.py build 照常可用，新增 --out；pm.py check-fresh 已删除。见 pm/README.md。

#2026-10-15 执行入口拒绝超出 decimal 范围的数（S1-RT-024）

通用执行入口的请求体里有绝对值超过 decimal 范围（约 7.9e28）的数时返回 400 BAD_REQUEST，不再返回 500；输入 Schema 的 enum / const 取值含这类数的能力在登记阶段以新规则 unsupported-number 拒绝。详见 Qian.Capabilities。

#2026-10-15 执行入口补不可重放码，参考应用能力标为 pii（S1-RT-021）

聚合 OpenAPI 为写类能力列出 409 CAPABILITY_REPLAY_UNAVAILABLE 及其两种 reason。参考应用的 customer.create、customer.list、customer.get 响应含客户名称，dataClassification 改为 pii：经通用执行入口带同一幂等键重放 customer.create 改为返回 409（data_classification）。运维手册新增「部署步骤：平台宿主装配」（platform 宿主必须调用 AddQianCapabilities()）与「过期幂等回执清理」两节。详见 Qian.Capabilities。

#2026-10-15 能力登记期契约检查与幂等回执上限（S1-RT-020）

平台宿主调用 AddQianCapabilities() 后，ctx.ProvideCapability 在登记时生成目录条目并预编译输入校验器，不合格的契约（输入含租户字段、Schema 无法可靠校验等）以 CapabilityContractException 拒绝，组件挂载失败。通用执行入口的幂等回执按数据分级与组件配置 receiptMaxBytes（默认 64 KiB）决定是否保存响应体，不保存时同键重放返回 409 CAPABILITY_REPLAY_UNAVAILABLE；Qian.Capabilities 新增迁移 InvokeReceiptLimits。Qian.Data 新增「迁移执行与 RLS 核查」一节（迁移必须经迁移器执行，附核查 SQL），运维手册新增「部署步骤：数据库迁移」。详见组件规格 §9.5 与 Qian.Capabilities。

#2026-10-15 数据契约冻结、组件元数据与文档预算整改（S1-QA-010）

data/v1 契约 按 R80 明确 frozen 状态、修订规则和已知例外，统一 $id 前缀并补结构测试；yue manifest 的属性元数据（含嵌套）递归取自 TS 注释，不存在的属性拒绝导出；文档站预算 按 R55 调为 120 MB，#95 合并时实测 96.2 MB。

#2026-10-15 数据连接连通测试的出网约束与凭据错误（S1-DATA-005）

  • 连通测试先解析目标主机并逐个检查地址：缺省拒绝回环、链路本地（含云元数据）、100.100.100.200、未指定、组播与广播地址。运维可经 QianDataConnectionOptions.Egress 追加拒绝网段或限定放行网段；被拒返回 DATA_CONNECTION_TARGET_DENIED，不连接也不读取密钥，放行时只连检查过的地址。
  • 租户密钥不是 UTF-8 文本时，PG 方言返回 DATA_CONNECTION_CREDENTIAL_INVALID，不再是 500。见 Qian.Data。

#2026-10-14 能力目录信封契约、别名 Link 头与通用执行入口规范化（S1-RT-019）

GET /api/capabilities 的响应冻结为 contracts/v0/capability-catalog（items、ttlMs、cacheScope），ttlMs 来自组件配置 catalogTtlMs；/api/kernel/capabilities 别名同时返回 Deprecation 与 Link: <后继路径>; rel="successor-version"；POST /api/capabilities/{plugin}/{name}/invoke 先按条目 inputSchema 校验（400 INPUT_INVALID），写类能力支持 Idempotency-Key（24 小时内重放返回首次响应并带 Idempotent-Replayed: true）；Qian.Capabilities 随包提供 EF 迁移（偏好表、回执表，经 Qian.Data 生成器带 RLS）。详见组件规格 §9.5 与 PRD 7.2.1。
