本章分两部分：16.1 是各阶段的退出准则——直接采用 ADR-018 的表述并细化为可测项，每项写明测法与 PASS 条件，是进入下一阶段功能开发的门禁；16.2 是各阶段的可量化 KPI——用于衡量做得好不好，不构成门禁。原则：能用自动化测试或真实环境证据证明的才算指标；采用数量类指标一律给「待定」或由 §04 的填写责任人填入，不编数字。

#16.1 阶段退出准则

#S1 技术底座

ADR-018 表述：开发人员用代码在 Qian 上写出一个多租户应用：登录 / SSO、鉴权、数据存储、文件上传、配置、网关、事件、审计全部由平台提供；一个官方 module 插件能独立出修订、逐租户迁移、回切。ADR-020 §6 新增末句：在空白项目里 qian add identity authz files 后 30 分钟内跑通登录、权限检查与上传。

#可测项测法 / 环境PASS 条件
E1-1参考应用（§06 S1 Demo）由一名未参与运行时开发的 .NET 开发者按文档独立完成计时记录；staging 集群从 qian init 到两个租户开通并验证 ≤ 4 工作小时
E1-2参考应用源码不含租户过滤、权限判断、审计写入、Outbox 代码静态扫描 + 代码评审相关模式命中 0 处
E1-3跨租户渗透测试第三方或独立安全角色执行；范围含 HTTP API、gRPC（含流式）、消息消费、Saga、Outbox 发布、调度回调、文件下载；用例含请求头伪造、默认租户回退、跨租户句柄、RLS 绕过0 漏洞（高 / 中危均为 0）
E1-4集成测试覆盖多副本消费≥ 2 副本的消费端与 Outbox 发布器；注入 ≥ 10,000 条含租户的事件，期间随机重启副本0 丢失；重复全部被幂等吸收；消费端租户上下文恢复率 100%；Outbox / Saga 无双发
E1-5登录与 SSO 端到端密码 + TOTP、短信验证码、通用 OIDC 连接器、企业微信连接器（扫码与工作台免登）；refresh 轮换；后通道登出；强制下线全部用例 PASS；会话失效传播 ≤ 5 s；OIDC 一致性测试基本档通过
E1-6鉴权强制契约 lint；权限判定 API；权限变更传播无权限点的写命令 CI 失败；check / explain 返回原因与命中策略；权限变更经 identity_revision 推送在 ≤ 3 s 内对新请求生效（与 §08 授权界面验收口径一致）
E1-7网关加固未认证请求、路由级限流、密钥热轮换未认证请求 100% 被拒；限流按路由生效；轮换期间 0 次 5xx
E1-8审计完整性抽样 ≥ 1,000 条命令；哈希链校验工具100% 可追到主体链、能力 ID、契约版本、来源通道；哈希链完整性 100%
E1-9修订、逐租户迁移与回切一个官方 runtime.form: module 平台插件发布 v+1 修订；对 N 个租户中的子集升级（租户 scope patch）；再回切未升级租户不受影响；回切后功能恢复；升级钩子重复执行结果一致（幂等）；全程无半升级态
E1-10配置热更新安全Apollo 下发非法配置保留上一份有效值并告警，服务不中断
E1-11部署基线发行 profile（可部署单元 = profile，ADR-020）：出镜像的 platform / gateway / identity 三个，standalone / minimal 不出镜像全部具备 /healthz /readyz；default-deny NetworkPolicy 与 ResourceQuota 存在；发布事件按 digest 可追溯；RabbitMQ 集群内运行；每个 profile 的 qian --profile <p> --dump-config 与基线快照一致
E1-12平台插件 TCKplatform profile base 组合包内全部平台插件（原「18 个系统插件」口径，ADR-020）三套 TCK（运行时语义 / 独立模式 / 组件一致性）通过率 100%；清单与代码一致性、文档新鲜度、依赖图断言、dump-config 漂移 CI 门禁启用（§14 C3 / C18–C20）
E1-13追踪与计量一条跨网关 → 服务 → 事件总线的请求trace 完整可见；带 tenant / plugin / principal-kind 标签；覆盖率 ≥ 95%
E1-14Kun 关键缺口修复实证针对 ADR-001 列出的每一项缺口的回归测试每项缺口对应至少一个失败→通过的测试
E1-15一键安装（独立模式，ADR-020 §6）空白 ASP.NET Core 项目；qian add identity authz files；由未参与运行时开发的开发者按各包 README 操作并计时；不部署 Qian 平台从 qian add 到首个登录 / 权限检查 / 上传请求成功的中位时长 ≤ 30 分钟（建议值）；独立模式 TCK 通过；dump-config 不含 qian.registry / qian.lifecycle / qian.capabilities

#S2 低代码构建

ADR-018 表述：跑通「建应用 → 建表单与列表 → 走审批 → 授权给租户用户使用」；同一应用包在两个租户分别安装、各自配置、独立升级互不影响。

#可测项测法 / 环境PASS 条件
E2-1搭建者不写代码完成 §06 S2 Demo非开发背景测试者按文档操作；计时全流程完成；时长记录为后续基线
E2-2同一应用包在两个租户独立升级互不影响自动化：租户 A、B 安装 v1；B 做租户层定制；发布 v2；A 升级、B 升级A 全量升级；B 冲突项列清单并按选择处理；两租户数据、配置、权限互不影响；升级前快照可回滚
E2-3Schema Migrator 对非空表安全对含数据的实体新增 / 改名 / 改类型字段；生成迁移计划并审核0 数据丢失；每步可重放；不出现「删表重建」
E2-4动态数据引擎 SQL 安全注入测试（字段名、运算符、值、排序、分组）0 漏洞；所有 SQL 参数化；标识符全部经白名单
E2-5鉴权唯一入口三段式绕过设计器勾选、篡改客户端菜单 / 流程参数、直接调用 Records API100% 被拒；拒绝带结构化原因
E2-6数据权限与字段权限属性测试「同角色 AND / 跨角色 OR / 全部数据放开」；字段读投影 / 写白名单属性测试通过；API 层返回不含无权字段；写入无权字段被拒
E2-7审批最小集回归集：或签 / 会签（人数、比例）/ 依次；退回 × 撤回 × 拒绝 × 子流程交叉；超时催办全部通过；会签阈值不可达时发 node.stalled 转人工；兜底链不落全局管理员
E2-8元数据版本化任意两个版本 diff；回滚；校验失败diff 可读；回滚后运行时读旧快照；校验错误带 JSON Pointer
E2-9元数据即能力新建实体能力目录自动出现 CRUD 能力；qian.record.changed.v1 事件发出且带 Schema
E2-10一套引擎lint / 依赖检查平台后台 CRUD 与低代码运行时复用同一表单 / 表格 / 弹层引擎；不存在第二套引擎（CI 门禁）
E2-11Operation 统一审批待办与导入导出共享同一状态机与收件箱；input_required 携带 JSON Schema
E2-12表达式与脚本边界公式 / 规则 / 联动全部经 DSL 解释器或隔离沙箱；eval / new Function 0 处（CI 门禁）
E2-13打印与预览模板、版本、数据绑定、浏览器打印；文件预览提供者用例通过

#S3 面向客户

ADR-018 表述：租户能从应用市场选购并开通应用，自助配置 IdP 与品牌。

#可测项测法 / 环境PASS 条件
E3-1租户自助申请到首个管理员登录端到端走查无运营人工介入（或按套餐自动通过）；状态机事件齐全
E3-2租户自助配置 IdP企业微信 / 钉钉 / 飞书 / 通用 OIDC 任一 + SAML / CAS / LDAP 任一；域名验证；HRD端到端登录通过；凭据不回显；令牌仍由平台签发
E3-3品牌Logo、主色、登录页即时生效；对比度单测通过
E3-4市场闭环目录 / 详情 / 安装向导 / 试用 / 升级中心 / 审核台反向权限逐项批准；含新增权限的升级必须同意；冲突预检报告可见；升级前快照
E3-5权益生命周期试用到期、续订、席位到期后不可用、数据保留、续订恢复；席位超限返回结构化错误
E3-6高隔离档ApplicationSet 生成独立命名空间 + 独立 PostgreSQL / Redis全部 TCK 通过；与共享档使用同一制品
E3-7不可信 UI 沙箱第三方 ui 插件渗透测试无法读取宿主令牌、无法越权调用；0 漏洞
E3-8工具描述哈希钉死插件更新改变能力描述 / Schema触发复审；旧授权失效
E3-9计量可拆分计量报表按 tenant / app / plugin / principal-kind 拆分
E3-10managed 应用防导出市场购买的 managed 应用导出被拒并审计
E3-11私有化交付整套 overlay 在隔离集群部署；离线包 + 授权文件全部 TCK 通过；无 AGPL / 商业许可依赖

#S4 AI 原生 Agent 平台

ADR-018 表述：Agent 能发现、调用、编排乃至生成平台能力与应用。
