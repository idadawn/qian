#§12 能力边界

Markdown 链接

状态：草案 v0（2026-10-06；组件模型 v2 已定稿，2026-10-07）。依据：docs/decisions/key-decisions-v0.md（D1–D18 与补充裁决，2026-10-06 全部获认可；D20 组件模型 v2 为同日方向修正新增，ADR-020 已于 2026-10-07 Accepted、§7 待确认项全部拍板，其边界条目见 12.2 的 C 块与 12.9）。本章只回答「某个阶段结束时，平台承诺做到什么、长期不做什么」；功能细节在各功能规格章，安全规则在 §13，验收方法在 §14。

阅读约定：

  • 阶段口径见 ADR-018：S1 技术底座 → S2 低代码构建 → S3 面向客户 → S4 AI 原生 Agent 平台。
  • 「明确支持」每条写成可判定的能力陈述：阶段退出评审时能对它回答「是 / 否」，并能指出证据（§14 的用例、门禁或演示）。写不成这种句子的条目不进本章。
  • 「过渡态（2026-10）」标注的是 Kun 当前缺口造成的临时状态，不是产品承诺；过渡态的消除是 S1 退出条件之一（ADR-001）。
  • 被借鉴的商业低代码产品一律称「参考平台」，本章只引用其做法作为正反例，不引入其代码。

#12.1 边界的三种语气

语气含义变更方式
明确支持（按阶段）该阶段退出前必须可验收；写作「能……」「必须……」只能经阶段评审调整阶段归属，不能悄悄删除
安全底线（S1 起生效）原本可以放到后期的安全与多租户设计，被提前到 S1，因为后补代价不可接受不可降级；新增需 ADR
明确不支持分「长期承诺不做」与「本期不做、可重议」两档，每条附理由长期承诺的改变必须新开 ADR 并在本章记录被推翻的原文

#12.2 S1 技术底座：明确支持

S1 退出标准（ADR-018；ADR-020 §6 新增末句）：开发人员用代码在 Qian 上写出一个多租户应用，登录/SSO、鉴权、数据存储、文件上传、配置、网关、事件、审计全部由平台提供；一个官方 module 插件能独立出修订、逐租户迁移、回切；在空白项目里 qian add identity authz files 后 30 分钟内跑通登录、权限检查与上传。

租户与隔离（ADR-004、ADR-003）

  1. 运营人员能在运营后台创建租户、选择隔离策略（默认共享库 + tenant_id 行过滤 + PostgreSQL RLS 双保险）、设置有效期与用户配额、指定单个租户管理员；租户号与隔离策略创建后不可修改。
  2. 租户具备最小状态机（待激活 / 正常 / 禁用 / 到期宽限），每次状态迁移发出事件并联动该租户会话吊销。
  3. 租户上下文只来自已校验令牌中的 tenant_id；HTTP、消息消费、Saga、Outbox 发布器、定时作业五类入口都能正确恢复租户上下文；解析不到即拒绝。
  4. 租户对插件 / 应用的开通是白名单（租户 → 插件 → 版本）；「未启用」在网关路由、SDK 入口、前端外壳三处同时被拦。
  5. 平台表按 schema-per-service 划分；缓存键与存储路径带租户维度；在线 DbContext 必须继承多租户基类（CI 检查）。
  6. 可选：schema-per-tenant 策略经真库集成测试验证（不作为 S1 退出条件）。

身份与 SSO（ADR-005） 7. qian.identity（OpenIddict）是平台唯一 issuer，提供 OIDC 授权码 + PKCE、refresh 轮换、client_credentials、后通道登出、JWKS 轮换；每环境一个规范 issuer。 8. 账号模型为 Person（全局自然人）+ Membership（租户成员）；一个人命中多个租户时先签 5 分钟选择令牌再换正式令牌；切换租户即重新签发令牌。 9. 登录方式：账号密码（Argon2、策略化锁定 / 延时、图形验证码按策略开关）、短信验证码（依赖 S1 必做的短信渠道）、TOTP 二次因子（Q18：S1 做）。 10. 上游连接器 SPI 可用，并交付两个连接器：通用 OIDC、企业微信（扫码与工作台免登）。第三方身份绑定需显式确认，同租户内唯一。 11. 会话中心：服务端会话表 + 用户 → 会话索引、强制下线、单端 / 并发上限（默认 5）、空闲与绝对超时、在线用户列表、登录审计；改密 / 停用 / 锁定 / 租户冻结 / 权限变更即时失效。 12. 密码策略（强度、锁定、初始密码强制修改）与 CSRF 防护上线即生效。 13. 平台与官方插件以内置 client 接入；外部系统只能用应用级客户端凭据（client_credentials），不存在用户级 AppSecret 与「公有」免鉴权接口（补充裁决 Q35）。

鉴权（ADR-006） 14. Kun.Authorization 端口（IPermissionChecker Check / BatchCheck / ListAllowedActions、IDataPermissionFilter、IFieldPolicy）与 qian.authz 内置实现可用；权限点由插件清单声明，自动登记为可授权项与 OAuth scope 目录。 15. 租户域 RBAC：内置角色（平台超管、租户 Owner / Admin / 开发者 / 使用者）+ 自定义角色；角色可授予用户、组织、岗位、用户组；插件自带默认角色模板。 16. 每个 API 端点声明所需权限点并在服务端强制校验，缺省拒绝；gRPC 一元与流式调用同样受检。 17. 权限不进令牌；令牌携带 identity_revision（网关只转发此 claim），权限变更经推送失效后 ≤ 3 秒内对新请求全部生效（R7）。 18. 每次判定可解释（命中规则 / 缺少权限）并入审计；平台超管旁路在策略中显式声明并审计。 19. 数据权限的契约（Filter AST、系统变量目录、「同角色 AND / 跨角色 OR / 任一全部数据则放开」）在 S1 定稿；编译器与字段权限在 S2 交付。

数据、文件、配置（ADR-004、ADR-007、ADR-011） 20. qian.data：PostgreSQL 16 为唯一一等数据库；RLS 拦截器与模型缓存键在装配时强制挂载（不再 opt-in）；基准数据类型与 PG 方言、数据连接（凭证只存引用）、数据接口 SQL 契约、值翻译、引用登记可用。 21. qian.files：文件上传（分片 + MD5 秒传）、存储路径策略、预览票据由内核签发并服务端校验；文件不以匿名 URL 直出。 22. qian.config：Apollo 作为平台 / 服务级非敏感配置权威，自研 .NET provider（长轮询、启动校验、失败保留上一份有效值并告警）；插件配置以 JSON Schema 声明，敏感项只能填 secretRef；租户级配置由 qian.tenancy 承载、不进 Apollo。 23. Filter AST JSON Schema 与「运算符 × 字段类型」矩阵定稿，供数据过滤、高级查询、数据权限、启用规则、流程条件五处共用。 24. 可发布元数据框架（草稿 / 发布 / 归档 + 当前生效指针 + 不可变快照）、导入导出框架（dry-run、逐行结果、异常导出）、编号规则 API、字典、i18n 资源机制可用。

网关、事件、审计、可观测（ADR-008、ADR-009、ADR-010） 25. 三层网关就位：Traefik（北向入口，不做鉴权）→ qian.gateway（强制认证、路由级限流、可信代理、私钥热轮换、Cookie 会话换 S2S、按 cluster 的 audience）→ Higress（只管模型与 MCP 流量）。 26. RabbitMQ 在 K3s 上运行；Outbox 不丢消息、消费端至少一次（处理成功后标记）、Redis 幂等、多副本锁默认开启、退避重试；事件信封字段 version / event_id / subject / occurred_at / tenant_id / payload；事件目录（稳定 ID + JSON Schema）是能力目录的一部分。 27. 审计只有一套：命令级 AuditEntry 哈希链持久化到 PostgreSQL；实体级 AuditLog 与业务同事务写入并经 Outbox 发事件；actor_type 含 agent，记录 on_behalf_of、capability_id、contract_version、来源通道；IAuditReader 可查。 28. 每个服务提供 /healthz、/readyz；traceparent 与 baggage（含 tenant_id）贯通 HTTP、gRPC、消息；计量带租户 / 插件 / 主体类型维度。

插件机制、SDK、授权 v0（ADR-002、ADR-003、ADR-014） 29. （清单在 v2 为唯一一份 .qian-plugin/plugin.json，文件名与 JSON 格式已由 ADR-020 §7 第 2 条拍板，见 C 块）qian-plugin.yaml 清单 v1 Schema + 校验器 + 源生成器：宿主不执行插件代码即可生成路由、权限点、菜单、Apollo namespace 骨架、OpenAPI 聚合与 NetworkPolicy 片段；CI 比对清单与代码，漂移即失败。 30. （租户级 Enabled ⇄ Disabled 经 ADR-020 改为租户 scope patch，见 C3；注册表与生命周期控制器为普通插件 qian.registry / qian.lifecycle）插件注册表与两层生命周期（平台级 Draft → … → Retired；租户级 Available → Entitled → Provisioning → Enabled ⇄ Disabled → Upgrading / Uninstalled → Purged）可用；租户级钩子逐租户、幂等、可重试、结果入库。 31. （「18 个」与「预装并按租户开关」经 ADR-020 修订，见 C2 / C3）18 个系统插件全部按 tier: system 清单交付，预装并按租户开关；其中任一 module 插件能独立出修订、逐租户迁移、回切到旧修订。 32. 制品按 digest 引用、全部签名、未签名直接安装失败；插件包作为 OCI artifact 推 Harbor。 33. SDK：源生成器 + CLI + TCK；TCK 覆盖清单校验、契约兼容性、生命周期钩子幂等性、跨租户越权探测、性能基线。 34. 授权 v0：qian.entitlement 存「是否买了」，Apollo 开关存「是否灰度开」，两者分开；bundle 包格式 v0、安装 / 升级引擎、id 重映射表定稿。 35. 能力目录（命令 / 查询 / 事件 / 实体四类注册表 + JSON Schema）经鉴权、按权限过滤后可查询；它不是公开 OpenAPI。 36. 所有写操作走带 JSON Schema 的命令，命令元数据含 sideEffect、idempotencyKey、dryRun；inputSchema 中不出现租户字段。

组件模型 v2（ADR-020，Accepted；对上一块第 29–31、34 条的修订，条目编号 C 以别于 B / T / N）

  • C1. 组件库只依赖 Qian.Runtime（.NET）/ @qian/runtime（TS），不依赖 qian.registry / qian.lifecycle 等插件；CI 断言依赖图（取代 ADR-019 的「不依赖 Qian.Kernel」断言）。
  • C2. 可部署单元 = profile：S1 随发行版交付 platform / gateway / identity / standalone / minimal；原 18 个系统插件成为 platform profile 的 base 组合包内容（规范术语「平台插件」，R30），各自按 seam 三角色拆包，数量由组合包定义而不是决策；qian --profile platform --dump-config 能打印整棵插件树，打印出的任何条目都能被 patch 替换。原可部署单元 ↔ profile / 组合包的定稿映射见 ROADMAP S1 核心交付与 prd/README 命名约定（R31：qian-shell 不是 profile，为 platform 的 shell 组合包；qian-model-gateway-adapter 为 model-gateway 组合包，默认挂 platform、可选独立 profile）。
  • C3. 租户启用一个插件 = 在租户 scope 挂载其配置条目（patch，存数据库、与文件 patch 同格式同校验器）；qian.entitlement 的授权状态机只管「买没买」；二者分开存、分开审计（§11.1.6「授权与开关分开可见」不变）。
  • C4. 声明式表面（skills / agents / commands / hooks / MCP、元数据、patch）S1 支持运行中重载；代码插件 S1 不承诺热装卸，走滚动重启（collectible AssemblyLoadContext 不进 S2 核心交付、S2 内 RT 领域 5 天 spike，ADR-020 §7 第 5 条已拍板）。
  • C5. 第三方代码不进共享进程保持不变（N1 / N2），映射到 policy.tier 与 policy.sandbox；private / community 组件只允许声明式表面与沙箱形态。
  • C6. 一键安装与目录市场：qian add / remove / list / doctor / dump-config / init --template 可用；官方市场仓库与 .qian/marketplace.json 就绪；空白项目 qian add identity authz files 后 30 分钟内跑通登录、权限检查与上传。
  • C7. skill / agent / command / hook / MCP 五种表面的解析器与校验器 S1 交付；模型可见的一切注册在 ctx.Tools 等注册表并受 scope 过滤；配置目录、模块图、事件图、seam 图由代码生成并设 CI 新鲜度门禁。

前端 yue 与外壳（ADR-013；详见专题 spec《yue 组件库》） 37. @yue/tokens 三层令牌、明暗两态、WCAG AA 对比度单测；@yue/core 51 个基础组件；@yue/shell 单一侧栏布局外壳（后端菜单 → 路由、menuTypeRegistry、租户切换器、兜底页）；DataTable 基础版、SchemaForm 基础版、Upload、组织 / 用户 / 角色选择器、认证页族可用。 38. 外壳以 Module Federation 2 运行时加载官方插件 UI，带版本号的插槽注册表；共享依赖 singleton。 39. 元数据契约草案（FormSchema / ListSchema，含 device、auth 字段）、控件注册表契约、SSE 事件 JSON Schema、权限码目录格式发布；分层依赖 lint 进 CI。

部署（ADR-017） 40. Qian 运行在独立命名空间 qian-<env>，专属 PostgreSQL / Redis；业务命名空间带 default-deny NetworkPolicy 与 ResourceQuota；Argo CD app-of-apps + Kustomize，按 digest 写回，迁移 Job 先行；K3s 开启 Secret 静态加密。 41. 生产与 iClaw 共用集群但独立节点池（Q16）；多租户拓扑默认共享，高隔离与私有化为可选档。

模型服务网关（ADR-015，S1 可选） 42. GPUStack 以 OpenAI 兼容上游注册进 Higress；Provider Adapter 完成模型发现、健康与生命周期；model-capabilities 契约填写；接入范围先 LLM + Embedding（Q17）。

#12.3 S2 低代码构建：明确支持

S2 退出标准：跑通「建应用 → 建表单与列表 → 走审批 → 授权给租户用户使用」；同一应用包在两个租户分别安装、各自配置、独立升级互不影响。

元数据与动态数据（ADR-011）

  1. 元数据（实体 / 字段 / 视图 / 表单 / 流程定义）以版本化聚合存储，草稿 / 发布双版本 + 不可变快照，可校验、可 diff、可回滚到任意版本。
  2. qian.dynamic-data：每个实体一张物理主表（系统列 tenant_id、软删、审计列、乐观锁），多值 / 子表用 JSON 列或关联表；统一 Filter AST → 参数化 SQL + 标识符白名单；强制注入租户与软删谓词；不走 EF 模型。
  3. Records API（列表 / 详情 / 新增 / 修改 / 删除 / 批量 / 导入导出 / 发起流程 / 关联查询）在唯一入口做「资源 + 动作 + 行级」三段式鉴权，PC、移动、API、流程回调、外链、Agent 六类通道共用。
  4. Schema Migrator：元数据 diff → 迁移计划 → 审核 → 逐租户分批执行 → 记录；「扩展 → 迁移数据 → 收缩」三步，不承诺自动回滚；不出现「改表 = 删表重建」。
  5. 泛型命令 CreateRecord / UpdateRecord / DeleteRecord / QueryRecords 注册一次、按元数据分派；通用信封事件 qian.record.changed.v1；服务端 before / after Hook。
  6. Field Type Catalog 与控件注册表是单一事实源；值翻译用按需批量 Resolver，不做全量缓存。
  7. 数据接口 SQL 文本模式开放，但作为高级权限：只读数据库账号、超时与行数上限、参数化、审计（Q32）。

表单、列表、发布（ADR-011、ADR-013） 8. 表单设计器（三栏、单一 Schema + device 可见性、结构化校验错误 + 定位）与表单运行时（编辑 / 只读 / 单元格三种呈现由注册表提供）交付 S2 控件集：基础输入、选择、日期、上传、组织类、子表、下拉树与弹窗选择、关联表单、公式、系统控件、六种布局容器。 9. 联动三层：声明式动作 → 可序列化表达式 DSL → 服务端 Hook；前端 QuickJS 沙箱为可选兜底；不提供自由 JS 按钮（补充裁决 Q18）。 10. 列表设计器与运行时：「一份语义 + 端覆盖」，普通表格 / 左树右表 / 树形表格必做，分组 / 卡片 / 行内编辑可选；查询字段派生、固定按钮、导入导出、审批按钮矩阵、权限四开关产出可授权项。 11. 功能发布拆成编译 → 迁移 → 切流 → 挂载的可重放幂等步骤并记发布日志；功能状态机 未发布 → 已发布 → 已修改 → 已发布；运行时只读当前生效版本。 12. 功能编码采用「租户.应用.功能」命名空间化稳定编码 + id 重映射表；一个功能只归属一个应用，其他应用经「跨应用引用」挂菜单（Q20）。 13. #12.4 S3 面向客户：明确支持

S3 退出标准：租户能从应用市场选购并开通应用，自助配置 IdP 与品牌。

  1. 市场（ADR-014）：私有目录型市场（目录 / 详情 / 安装向导 / 试用 / 升级中心 / 审核台）→ ISV 入驻、席位、Plan / Seat / Meter / Trial、评分；上架闸门 = TCK 全绿 + 签名 + 权限清单展示；工具描述哈希钉死；发布者撤销与黑名单自动卸载。
  2. ISV 可上架的形态只有 package / function / connector / 受限 ui；第三方 service（任意代码容器）不上架（Q9）。
  3. 租户自助（ADR-005）：自助申请 → 审核 → 开通；多管理员与邀请；租户自助配 IdP（每租户多连接、按邮箱域 HRD、域名验证、「仅企业 IdP 登录」服务端强制）；SAML / CAS / LDAP 连接器（先代理 IdP 后原生）；Passkey；SCIM Server 与国内目录同步；应用安装即建 client；自助注销与数据导出。
  4. 租户生命周期完整状态机：待激活 → 试用 | 正常 → 宽限 → 只读 → 冻结 → 注销（数据销毁）；套餐 = 预定义白名单 + 配额；品牌与自定义登录域（只换登录页宿主，不改 issuer）。
  5. 高隔离档：独立库（DatabasePerTenant）作为付费选项；高隔离租户独立命名空间 + 独立 PG / Redis 由 ApplicationSet 生成；私有化客户整套 overlay 复制；不承诺隔离策略在线迁移。
  6. 权限高级模式（可选、可开关）：组织角色 / 岗位角色、逐级递减授权、身份（权限分区）、互斥 / 基数 / 先决约束；OpenFGA 插件处理资源实例共享与市场授权；Explain 工具。
  7. 不可信 UI 沙箱：partner / private / community 的 ui 走 Worker 远程渲染或 iframe；CSP 由清单生成。
  8. 门户与报表：门户设计器与运行时、表格报表（实体、版本、数据集、XLSX 导出）、通知抽屉、面向客户工作台；开放 API；分享链接与外链能力令牌（功能 + 动作 + 版本 + 过滤 + 有效期）。
  9. 流程 S3：拒绝后继续流转、归档、签收、委托 / 代理、撤销申请、协办、超时自动处置、决策流程（调用式）、自由流、批量审批；流程模板与决策表节点包作为市场商品；BPMN 只作导出器。
  10. 计量与成本：Plan / Seat / Meter；Higress token 限流与缓存；租户 / 应用预算与告警。
  11. 动态路由：qian.gateway 按租户 × 已安装应用动态路由；接线 Application 生成器。
  12. 可选：大屏（只消费内核数据接口，不复用参考平台大屏源码）、服务端 HTML → PDF、多布局与偏好抽屉、H5 / PWA 工作台与审批、小程序与 App 以壳嵌 H5。

#12.5 S4 AI 原生 Agent 平台：明确支持

S4 退出标准：Agent 能发现、调用、编排乃至生成平台能力与应用。本期（S1–S3）只做防返工设计，不交付 S4 功能。

  1. 每租户一个 MCP 逻辑门面（Higress 托管），工具定义由插件清单 capabilities 机械生成，暴露经 agent.expose 策划，按调用者权限过滤工具列表。
  2. Agent 主体（有归属人、可吊销）与委托链：RFC 8693 令牌交换带 act；有效权限 = 委托人权限 ∩ 授予 scope；Check / ListAllowedActions / Explain 以工具形式暴露。
  3. Agent 生成应用 = 生成 package，经校验 + TCK + 差异审阅 + 人工确认后落库；代码只落 function 沙箱；记录 generatedBy / promptHash。

#12.6 安全底线（从后期提前到 S1）

下列设计原本在参考平台或多数低代码产品中属于「上线后再补」，Qian 把它们全部提前到 S1 生效。理由只有一个：多租户隔离与可信计算基的缺陷无法事后修补——数据一旦串读、审计一旦断链、令牌一旦被当作权限载体，后续所有插件与应用都会建立在错误假设上。细则见 §13。

#底线原本阶段提前理由
B1租户上下文只来自已校验令牌，fail-closed；生产禁用请求头兜底与 default 回退；非 HTTP 入口显式回灌Kun 现状为 opt-in跨租户串读是最高风险（ADR-004）
B2权限不进令牌；令牌只含身份、tenant_id、membership_id、scope、identity_revision常见做法是把权限塞进 JWT权限变更即时失效与审计都依赖它（ADR-006）
B3API 层强制鉴权，缺省拒绝；前端裁剪只是体验层参考平台恒 true鉴权分散到控制器后无法收口
B4所有写操作走带 JSON Schema 的命令，含 sideEffect / idempotencyKey / dryRunS4 Agent 需要事后补「后门写入」的权限与审计几乎不可能
B5inputSchema 禁止租户字段；契约 lint 强制S4跨租户越权的典型入口
B6统一主体模型 user / service / agent 与委托链字段S4每个服务后补「这是不是 Agent 调的」
B7审计防篡改且含主体链、能力 ID、契约版本、输入哈希、来源通道S3/S4无法回答「哪个 Agent 以谁的名义做了什么」（ADR-009）

B16可解释、可预检的权限判定 API（Explain 数据结构 S1 定，UI 可后置）S3排障与 Agent 盲调 403 的共同解
