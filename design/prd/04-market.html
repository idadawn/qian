Apollo 的边界只存平台 / 服务级非敏感配置与密钥引用；租户级配置不进 Apollo；需新增 MySQL；自研 .NET providerADR-007
模型接入不自建GPUStack 作为 OpenAI 兼容上游注册进 Higress；Qian 只做 Provider Adapter 与 model-capabilities 契约；租户 / 配额 / 计量在平台侧ADR-015
与 Agent 运行时的分工Qian = 能力提供方 + 业务主数据权威；外部 Agent 运行时 = Agent loop + AI 资产控制面；共用 Kun 与 HigressADR-016

#4.2 产品形态按阶段

阶段对外形态一句话
S1 技术底座Qian.Runtime + 一组 NuGet / npm 组件包 + qian CLI（qian add 一键安装）+ 官方目录市场（marketplace.json）+ TCK + 部署物料（profile 镜像）+ 后台控制台「开发者用它半天写出一个多租户应用；空白项目 qian add identity authz files 30 分钟跑通」
S2 低代码构建在 S1 之上的设计器（表单 / 列表 / 审批）与运行时，应用可打包「搭建者不写代码建出带审批的应用并授权给租户用户」
S3 面向客户私有目录型市场 → 开放 ISV 与在线交易；租户自助（IdP、品牌、套餐）「租户自己从市场选购、开通、升级」
S4 AI 原生 Agent 平台每租户 MCP 门面、Agent 主体与委托链、元数据生成闭环「Agent 能发现、调用、编排乃至生成平台能力与应用」

#4.3 客群画像按阶段

阶段首要客群次要客群他们要解决的问题他们怎么衡量我们
S1平台开发者（本团队）与 内部项目的 .NET 开发者兄弟系统（Agent 运行时）的开发者每个新项目都在重复做租户、登录、鉴权、文件、配置、审计；多副本下多租户漏洞频发从空仓库到可部署的多租户应用需要多久；安全默认值是否强制；TCK 是否能一次跑通
S2企业 IT 部门的业务搭建者、实施伙伴平台开发者（扩展控件 / 节点）表单、审批、列表类需求多且变化快，纯代码交付跟不上一个带审批的业务应用几天能上线；改表是否安全；权限是否能精确到字段与行
S3中型企业租户（共享 SaaS）与 对隔离有要求的企业（高隔离档 / 私有化）ISV（把行业应用上架）想用现成应用而非从零搭；需要国内 IdP 联邦、品牌、独立数据市场里有没有想要的应用；开通是否自助；升级是否不破坏定制；数据是否隔离
S4已有租户中的 Agent 使用者；外部 Agent 平台 / 编码 Agent 用户ISV（上架 Agent 资产）希望 Agent 能用现有业务系统、能生成应用草稿且受控Agent 调平台能力是否与人同权；生成物是否可审、可回滚、可解释

画像中不写客户名与数量；目标数量级见 4.5。

#4.4 交付方式

档位适用隔离拓扑身份市场起始阶段
共享 SaaS中小租户、试用、ISV 分发的主流形态同一命名空间；共享 PostgreSQL，RLS + 行级过滤双保险；共享 Redis / RabbitMQ平台唯一 issuer；租户可挂外部 IdP 连接器（S3 自助）在线目录（marketplace.json）；第三方只允许声明式表面、package / function / 受限 ui 与为某个 seam 提供 Provider 的组件（原 connector），不进共享进程S1 底座 · S3 对外
高隔离租户对数据隔离、合规或性能有要求的企业租户独立命名空间 + 独立 PostgreSQL / Redis（ApplicationSet 生成）；独立库作付费选项同上；可选租户自定义登录域名（S3）同共享 SaaS；可叠加专属部署的 runtime.form: service 组件（运维行为）S3
私有化政企、高校、对离线有要求的客户整套 overlay 复制到客户集群；离线包 + 授权文件绑定租户 ID；内网市场镜像同步平台 issuer 部署在客户侧；S3 起 SAML / CAS / LDAP 连接器离线目录 / 镜像同步S3（S1 起保证可私有化：无 AGPL / 商业许可依赖）

共同约束：三档共用同一套 profile 镜像与组件制品、同一份清单（.qian-plugin/plugin.json）与同一条发布流水线；不以 per-tenant namespace 为默认拓扑；生产与兄弟系统共用集群但独立节点池，达到一定租户数再拆（ADR-017）。

市场形态（ADR-020 D20.8，ADR-014 据此修订）：S1 起即有目录市场——git 仓库里的一份 .qian/marketplace.json，条目只写来源与策略，qian add 据此安装，官方市场、租户私有市场、社区市场并存；S3 的商业市场（授权、计费、审核、ISV 入驻）叠在同一格式之上，不另起格式；私有化档的「离线目录 / 镜像同步」即同步市场仓库与代码制品。

#4.6 明确不做的形态

  • 不做协作套件内嵌型（依附 IM 的组织与消息底座）；国内 IM 只作为 IdP 连接器与消息渠道接入。
  • 不做纯零代码业务搭建的消费级产品；S2 的搭建者面向企业 IT 与实施伙伴。
  • 不做自建 Agent 运行时、沙箱、记忆与技能引擎（复用兄弟系统，ADR-016）。
  • 不做自研模型代理层（复用 Higress / GPUStack，ADR-015）。
  • 本期不做原生移动 App；移动端以 H5 / PWA 为主，S2 只做 PC 响应式并预留端覆盖。
