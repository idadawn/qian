# 15. 演进路线（指针）

> 状态：草案 v1 · 更新日期：2026-10-06 · 决策引用：ADR-018 · 上级索引：[README](README.md)

**阶段、里程碑与退出标准的唯一真相源是 [`/docs/ROADMAP.md`](../ROADMAP.md)。** 本章只保留阶段总览表与指针，避免双向维护；任何对阶段内容的修改只在 ROADMAP 进行，本章随之更新表格而不新增叙述。

## 15.1 阶段总览

| 阶段 | 名称 | 一句话目标 | 退出标准（摘要，全文见 ROADMAP） | 状态 |
|---|---|---|---|---|
| S1 | 技术底座 | 开发者用代码在 Qian 上写出一个多租户应用 | 登录 / SSO、鉴权、数据存储、文件上传、配置、网关、事件、审计全部由平台提供；一个官方 module 插件能独立出修订、逐租户迁移、回切 | ⬜ |
| S2 | 低代码构建 | 搭建者不写代码建出带审批的应用并授权 | 跑通「建应用 → 建表单与列表 → 走审批 → 授权给租户用户使用」；同一应用包在两个租户分别安装、各自配置、独立升级互不影响 | ⬜ |
| S3 | 面向客户 | 租户自助选购、开通、配置 | 租户能从应用市场选购并开通应用，自助配置 IdP 与品牌 | ⬜ |
| S4 | AI 原生 Agent 平台 | Agent 发现、调用、编排、生成平台能力 | Agent 能发现、调用、编排乃至生成平台能力与应用 | ⬜ |

状态符号：✅ 已完成 · 🚧 进行中 · ⬜ 未开始。

S1 起生效、否则 S4 返工的设计清单（带 Schema 的写命令、统一主体模型、可解释权限、一份契约多处生成、租户只来自令牌、审计含主体链、追踪与计量贯通、事件契约化、插件包签名与反向权限审批）写在 ROADMAP「跨阶段约束」节与 §02 第二组原则中，本章不重复。
