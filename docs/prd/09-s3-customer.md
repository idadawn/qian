### 9.0 目标与退出标准

#### 9.0.1 目标

把 S2 的「平台运营方帮租户装应用」变成**租户自助**：租户能从应用市场选购并开通应用、自助配置身份源与品牌；ISV 能上架；平台能计量计费。市场形态按 ADR-014 演进：S3 初私有目录型（M2）→ S3 中开放 ISV 与在线交易（M3）。

#### 9.0.2 退出标准（ADR-018）

1. 一个新租户从自助申请 → 审核通过 → 自动开通 → 租户管理员登录 → 在应用市场选购一个 `managed` 应用 → 试用 → 开通 → 应用在该租户可用，全程无平台运营方人工介入（审核可自动）。
2. 该租户管理员自助配置一个企业 OIDC 身份源（含邮箱域 HRD）与品牌（LOGO、名称、登录页主题），其成员用企业账号登录并看到租户品牌。
3. 市场中至少一个受邀 ISV 的应用经审核台上架；应用升级时，已安装租户收到升级中心的冲突预检报告并完成升级或回滚。
4. 计量：租户当月的席位、API 调用、模型用量（若接入）在用量视图可见，与账单脚本输出一致。

#### 9.0.4 S3 的横切约束

- 市场、权益、隔离三者中，**包格式与可定制性契约、升级与冲突处理、授权与权益 API** 在 S1/S2 已定且之后几乎改不了（ADR-014）；S3 只在其上加 UI 与交易，不改契约。
- 所有面向客户的入口（市场、自助、工作台、开放 API、分享链接）都走 §07 的统一鉴权与审计；匿名访问只能经能力令牌，没有免鉴权资源类型。
- 第三方代码永不进共享进程（ADR-002）；对第三方生效的运行时强制点（独立工作负载身份、独立 schema 与数据库角色、事件主题 ACL、出口 NetworkPolicy、CSP）在 S3 首次被真实第三方触发，S1 的规范在此验收。
- 租户主数据权威归 Qian（Q15）；凡与 iClaw 共用的设施（Higress、运维侧 Authentik）只共用数据面与运维面，不共用租户模型。

### 9.1 应用市场：私有目录型 → ISV 开放（P0 · S3）

#### 设计理念

市场本身是普通插件，但它依赖的「包、授权、隔离」在 S1/S2 已进内核（ADR-014）。S3 初先做私有目录型（租户自助浏览与安装、受邀 ISV 线下结算），S3 中再开放 ISV 自助入驻与在线交易。第三方任意代码容器（`service`）本期不上架，只开放 `package / function / connector / 受限 ui`（Q9）。

#### 范围与边界

**目录与详情（M2，P0）**
- ✅ 分类/标签/搜索/精选；详情页：截图、示例数据预览、**权限清单**（反向权限 `permissions.platform/data/egress/secrets`）、外发域名、兼容性（`engines` 区间）、版本日志、价格结构、ISV 信息、评分（M3）。目录 API 机器可读（S4 Agent 检索）。
- ✅ 自营应用与平台能力包（流程模板、决策表节点包、打印模板包）同样作为商品上架，走同一流水线（补充裁决 Q27）。

**安装向导与试用（P0）**
- ✅ 安装向导：依赖包展示与自动安装、所需反向权限逐项批准、外发域名确认、成员与数据范围初始授权；安装到租户复用 §08 8.10 链路。
- ✅ 试用：按包配置天数一键开通，到期自动降级或停用；「先在沙箱租户试装」P2。
- ✅ 三种开通方式（M2）：免费 / 联系销售 / 授权码（线下）；在线支付与订阅为 M3。

**升级中心（P0）**
- ✅ 新版本提示与更新日志；**三方合并冲突预检报告**（旧包 × 新包 × 租户层，列出冲突项，租户按「保留我的 / 采用新版 / 手工合并」处理）；升级前快照；计划升级窗口；失败回滚（修订回切 + 前向兼容数据）。
- ✅ 升级同意规则：新增反向权限或付费模式变更 → 必须租户管理员重批；无新增 → ISV 可推送（全部 / 灰度 / 指定租户），官方插件借 Apollo 灰度 + 租户批次。
- ✅ 禁止复制/导出 `managed` 应用（ISV 知识产权保护选项，P2）。

**审核台与发布者认证（P0 / M3 P1）**
- ✅ 平台运营审核台：自动扫描结果（清单校验、依赖、安全扫描、TCK、性能基线）、人工审核清单、驳回理由模板、复审触发（权限扩大、付费变更）；分级审核（免费元数据模板快审，带代码走安全审查）。
- ✅ 发布者认证（M3）：企业/个人实名、开发者协议、命名空间预留、开发租户与沙箱、CLI 发布流水线（构建 → 自动校验 → 提交审核 → 上架；上架后版本不可改）。
- ✅ **工具描述哈希钉死**：注册表保存已批准能力的「名称 + 描述 + 规范化 inputSchema」哈希，变更即下线待复审（防 rug pull）；强制验签不变。
- ✅ 发布者撤销与黑名单自动卸载；强制下架与安全补丁强制升级。

**席位与权益（M3，P0 模型 / P1 交易）**
- ✅ `Plan / Entitlement / Seat / Meter / Trial` 完整模型（S1 v0 升级）：免费、买断、按组织年付、按人年付、试用、线下授权；席位双轨（平台席位 + 应用席位），按部门或用户组动态分配；权益 API（有效、席位、功能开关、用量额度）与变更事件（开通、续费、到期、退款、席位变化）；Entitled 与 Enabled 继续分开存。
- ✅ ISV 侧：定价配置（改价与付费模式变更复审）、版本安装分布与升级失败视图、安装量/活跃度/收入分析；分成规则、对账单、结算周期（细则属产品决策，本章不裁决）。
- ✅ 评分评价只对真实安装/购买的租户开放；工单直达 ISV。
- ❌ 第三方任意代码 `service` 上架（Q9）；充值/兑换码；私有化租户的离线包 + 授权文件（P2，随私有化交付方案）；质量徽章/广告位/伙伴分级（P2）。

**三方视角清单（范围核对用）**

| 视角 | S3 初（M2，私有目录型） | S3 中（M3，交易型） | 后置 / 不做 |
|---|---|---|---|
| 租户侧 | 浏览与发现、详情页、试用、三种开通、安装向导、升级中心（冲突预检/快照/回滚）、托管包允许范围内的定制、卸载前导出与数据保留期 | 在线购买与订阅、席位管理（部门/用户组动态分配）、订单与续费、评价与工单 | 沙箱租户试装（P2）、发票与退款仲裁（P2）、私有化离线包 + 授权文件（随私有化方案） |
| ISV 侧 | 受邀入驻（线下协议与结算）、开发租户、CLI 打包/校验/发布、包校验器、授权 API 与权益事件 | 自助实名入驻、命名空间预留、发布流水线与版本状态（开发中/审核中/已上架/已下架，上架后不可改）、定价配置、推送升级范围、安装分布与升级失败视图、数据分析、分成对账 | 支持义务与伙伴等级 SLA（P2） |

#### 技术落点 / 插件化定位

`qian.marketplace`（可替换）+ `qian.entitlement` + `qian.billing`；注册表形状对齐 iClaw 的 Package / Release / Publication / Installation 四层与 `pending → approve/sign → active`（ADR-016）；S3 预留 `server.json` 兼容字段，S4 市场兼任私有 MCP registry（「应用上架」与「MCP Server 发布」合成同一 publish 动作）。

#### Agent 契约

市场 API 返回机器可读包摘要（能力清单、权限、价格结构、试用、兼容性、评分）；Agent 只能**提议**安装/升级，付费与权限动作永远需要租户管理员确认。

#### 验收标准

- [ ] 租户管理员在目录搜索到应用 → 详情页看到完整反向权限与外发域名 → 安装向导逐项批准 → 试用 7 天 → 到期自动停用 → 输入授权码开通恢复。**测法**：端到端 + 时钟注入。
- [ ] ISV 发布 v2（新增 `egress` 域名）：无重批的租户升级被阻止；已有租户定制与新版冲突 3 项在预检报告中列出，选择「保留我的」后升级成功且可回滚。**测法**：两租户脚本。
- [ ] 修改已上架能力的 `inputSchema` 而不发新版：能力自动下线并进入复审队列。**测法**：注册表接口。
- [ ] 席位 10 人的应用第 11 人分配被拒并返回 `SEAT_EXCEEDED`；权益到期事件触发应用 Disabled 且三处拦截（网关/SDK/外壳）同时生效。**测法**：接口 + 时钟。
- [ ] 上传含 `service` 组件的第三方包被审核台拒绝并说明策略。**测法**：坏样例。

### 9.2 租户自助（P0 · S3）

#### 范围与边界

- ✅ **开通编排**：创建主档 → 选隔离策略（默认共享库 + RLS；高隔离档见 9.3）→ `ITenantProvisioner` 幂等开通 → 执行已开通插件迁移脚本 → 创建租户管理员 → 下发套餐白名单 → 通知；失败由编排层回滚，不靠数据库事务。
- ✅ **完整生命周期状态机**（S1 最小态升级）：`待激活 → 试用 | 正常 →(到期)→ 宽限 → 只读 → 冻结 →(保留期满)→ 注销（数据销毁）`，任一状态可被运营方 Suspend/Resume；每次迁移发 `tenant.*` 事件并联动会话吊销；删除 = 软删 + 保留期 + 到期销毁任务，文案与行为一致。
- ✅ **套餐**：= 预定义白名单（插件/应用/版本）+ 配额集合（用户数、存储、API 调用、模型用量）；批量下发；与市场订单打通；配额口径：平台超管不计入、租户管理员计入（补充裁决 Q12）。
- ✅ **多管理员与邀请**：多管理员、转移；邀请链接/二维码含机器可读 payload（租户、应用、角色、有效期）；「加入」= 绑定目标租户已有账号；切换租户按 Membership 重签令牌。
- ✅ **自助申请/审核**：申请 → 审核（可自动，规则：邮箱域、企业信息完备度）→ 开通 → 通知；参考平台未交付该部分，由 Qian 自行设计（补充裁决 Q13）。
- ✅ **自助配 IdP 与 HRD**：租户级多个上游连接器（通用 OIDC 必做；企微/钉钉/飞书 ISV 模式见 9.10；SAML/CAS/LDAP 先用代理 IdP 连接器，P2）；按邮箱域 HRD；域名验证（DNS TXT）；「仅允许企业 IdP 登录」在服务端策略层强制（参考平台只在前端跳转是反例）。
- ✅ **品牌与登录域**：LOGO、系统名称、登录页主题（yue 令牌由服务端按租户下发 `data-theme/data-brand`）；自定义登录域只换登录页宿主，不改 issuer（单 issuer，Q4）；白标域名 P2。
- ✅ **SCIM 2.0 Server**（核心 schema + Qian 扩展：岗位、主管、成员身份）：入站按外部稳定 id 映射、删除只置禁用、冲突策略、对账报告；出站推送 P2。
- ✅ **Passkey**（P2，认证因子插件；TOTP 已在 S1）；短信/微信 OTP P2。
- ✅ **自助注销与数据导出**（PIPL 合规）：注销 = 停用 + 脱敏 + 导出；管理员禁止自助注销。
- ✅ 租户运营后台 S3 完整分组：套餐、审核、审计看板、用量统计、健康看板。
- ❌ 每租户 issuer（Q4）；租户托管身份（S3 可选，并存时以邮箱/手机验证后的显式合并为准，补充裁决 Q2）；隔离策略在线迁移（是否作付费服务待拍板）。

#### 验收标准

- [ ] 自助申请到可登录全程 ≤ 10 分钟且无人工介入；开通失败在任一步重试后收敛到一致状态。**测法**：故障注入。
- [ ] 租户到期后进入宽限：新登录被拒、已登录会话在 60 秒内吊销；只读期写请求返回 `TENANT_READONLY`。**测法**：时钟 + 接口。
- [ ] 配置企业 OIDC + 邮箱域 HRD + 「仅企业 IdP」：成员输入企业邮箱直接跳转 IdP；用密码接口登录被服务端拒绝。**测法**：接口测试。
- [ ] SCIM 推送 1000 用户与 50 组织；删除事件只置禁用；对账报告差异为 0。**测法**：SCIM 客户端模拟。
- [ ] 邀请链接过期或角色不存在时加入失败并返回结构化错误。**测法**：接口测试。

### 9.3 高隔离档（P1 · S3）

#### 范围与边界

- ✅ **独立库**（`DatabasePerTenant`，ADR-004 付费选项）：开通编排建库 + 迁移 + RLS 仍作兜底；Kun 的 `DatabasePerTenantProvisioner` 不建库、`Deprovision` no-op，Qian 补齐并补真库集成测试。
- ✅ **独立命名空间**：高隔离租户独立 ns + 独立 PG/Redis，由 ArgoCD ApplicationSet 生成租户 overlay（ADR-017），default-deny NetworkPolicy 与 ResourceQuota；不以 per-tenant namespace 为默认。
- ✅ **接线 Application 生成器**：从租户主档 + 已安装插件清单生成该租户的 Kustomize/Helm 片段（服务实例、连接串 secretRef、路由），写入 GitOps 仓库由 ArgoCD 收敛；按 digest 写回。
- ✅ **动态路由**：`qian.gateway` 的 `IProxyConfigProvider` 按「租户 × 已安装应用 × 部署拓扑（共享/专属）」生成 routes/clusters；域名 → 租户解析；专属实例的路由与共享实例隔离。
- ✅ 私有化客户：整套 overlay 复制（第三档），离线包与授权文件随私有化交付方案。
- ❌ 共享库租户在线迁移到独立库（评估是否作付费服务）；跨租户数据同步。

#### 验收标准

- [ ] 为租户 H 开通独立库 + 独立 ns：ApplicationSet 生成的 overlay 被 ArgoCD 收敛，H 的请求经动态路由到达专属实例，共享租户请求不受影响；H 的 PG 中无其他租户数据。**测法**：部署脚本 + 流量断言。
- [ ] 应用升级对 H 的租户迁移在其专属库执行，日志按租户归档。**测法**：迁移日志比对。

### 9.6 开放 API、应用级客户端凭据与分享链接（P1 · S3）

#### 范围与边界

- ✅ **开放接口分组**：把若干数据接口/能力打包为开放分组，系统生成路径前缀，自动产出 OpenAPI 3.1 文档 + scope，登记到 `qian.gateway`（业务 API 边界，ADR-010；Higress 不承担业务 API）。
- ✅ **凭据模型**（补充裁决 Q35）：废弃用户级 AppSecret，统一为**应用级客户端凭据**（`client_credentials`，由 `qian.identity` 客户端注册表签发；应用安装即建 client、卸载吊销）；取消「公有」免鉴权——匿名访问只能经分享链接的能力令牌；IP 白名单、有效期、配额与限流按分组配置；调用日志。
- ✅ **分享链接 / 能力令牌**（内核横切 `qian.share-link`）：目标类型与 id、令牌、可选密码、有效期、租户边界、访问计数与审计；服务端签发并校验「功能 + 动作 + 版本 + 过滤 + 有效期」；用于报表/打印文件/门户外链/匿名填单与公开查询（§08 8.15 延期项在此落地）；控件白名单（匿名上下文只能访问不依赖身份的数据源，「匿名可用」标志）。
- ✅ 短链（点击即失效 / 最大点击数 / 有效小时）归消息域复用。
- ❌ 自建对称加密的 enCode 方案；部署级共享密钥；匿名上传与任意 URL 代理。

#### 验收标准

- [ ] 为应用 X 创建开放分组并签发客户端凭据，外部系统用 `client_credentials` 换令牌调用成功；凭据吊销后 401；无凭据请求 401（无「公有」旁路）。**测法**：接口测试。
- [ ] 匿名填单链接只能写入白名单控件字段，到期后 410，密码错误 3 次后锁定链接。**测法**：接口 + 时钟。

### 9.11 服务端 PDF 与大屏（P2 · S3）

- **服务端 PDF（P2，补充裁决 Q33）** ✅ 无头浏览器或 PDF 库做 HTML→PDF 作为 `qian.print` 的服务端渲染提供者（归档、邮件、Agent 自检需要）；K3s 资源与冷启动成本在 S3 评估后决定是否启用；服务端出图只用跨平台图形库并有失败告警。❌ 把浏览器打印下线。
- **大屏（P2，补充裁决 Q31）** ✅ 若做：React 栈重新选型，集成宽松许可的开源大屏或自研轻量查看器；只消费内核数据接口与分享链接；组件配置 = 声明式绑定 + 受限表达式（禁函数字符串）；地图数据走 `qian.geo` 平台级共享；分享与访问密码走 `qian.share-link`。❌ **不复用参考平台大屏源码**（许可证高风险）；大屏自有数据库数据源与任意 SQL；用户自写 Vue/HTML 代码组件（HTML 仅 iframe 沙箱 + 声明式参数可选）。

### 9.12 计量计费（P0 模型 · S3）

#### 范围与边界

- ✅ **计量事件**（S1 `qian.observability` 计量事件规范的 S3 落地）：统一以**租户 / 项目双键**计量——`tenant_id` 必填、`project_id?` 可选（对齐 iClaw S2S claim 形状，ADR-016），再细分 `plugin_id / principal_kind(user|service|agent) / capability_id`；计量维度：席位（用户数）、存储、API 调用、Operation 运行、模型用量（§10.5 的消费者用量按租户归集）。
- ✅ **聚合与账单**：计量事件进时序/日志栈 → 按天聚合 → 与套餐配额比对 → 预算告警 → 周账单/月结；Usage Ledger 是否与 iClaw 共用待 S3 拍板（Q15），本章先按「Qian 自有 Ledger + 对账接口」写。

- ✅ **结算**：ISV 分成规则、对账单、结算周期；在线支付与发票对接 P2（国内增值税发票流程属推断，待产品决策）。
- ❌ 充值与兑换码；按用户级 AppSecret 计量。

#### 验收标准

- [ ] 租户 T 当月 API 调用 12,345 次、模型 token 1.2M：用量视图、计量事件聚合、账单脚本三者一致（差异 < 1%）。**测法**：注入已知流量后对账。
- [ ] 项目维度计量：同一租户两个 `project_id` 的用量可分别查询，缺省无 project 的调用归入租户级。**测法**：接口测试。
- [ ] 超出套餐 API 配额后按策略返回 429 并发告警事件。**测法**：压测。

### 9.14 待确认

1. **Usage Ledger 与租户 API Key 是否与 iClaw 共用**（Q15 默认「待 S3」）：影响 9.12 计量落点与 §10.5 模型用量归集；本章按 Qian 自有 Ledger + 对账接口写。
