# ADR-018 阶段切分与 S1 范围

## 1 背景与问题（Context）

七份基线都以同一阶段口径分级，但对若干能力的阶段归属有分歧：流程内核原语归 S1 还是 S2；企微 / 钉钉 / 飞书连接器 S1 必做、可选还是 S2；refresh 令牌与单点登出；审计路径；Wasm `function`；打印；工作台；短信渠道；公告；DTCG 令牌；MF2 运行时（基线汇编 §3.5）。基线 W 的裁决原则是「按阶段退出标准分级」：S1 验收是开发人员能用技术组件写出一个多租户应用，不需要审批流；S2 验收才需要（基线 W §0.2）。基线 P 的 P11 原则是「每阶段独立交付，插件化不以牺牲阶段退出标准为代价」（基线 P §1.1）。

S1 的两座大山（自建身份核心与鉴权引擎）互为前置且都是其他插件的前置，工期与安全预算必须显式列出（基线 K §7.1 第 1 条）。基线 P §8.3 列出了 16 条「S1 到 S3 必须提前做对、否则 S4 返工」的设计。iClaw 的 PRD 体例（功能项标题带阶段、验收三件套：checkbox / YAML 用例 / 阶段退出准则、「实现与目标态差异 + 日期」过渡态块、「明确不支持」固定小节）可直接套用（基线 K §4.1）。

## 2 决策（Decision）

- **D18.1 四段顺序认可**（Q1）：S1 技术底座 → S2 低代码构建 → S3 面向客户 → S4 AI 原生 Agent 平台；「低代码构建」单独成 S2 并先于「面向客户」。
- **D18.2 S1 技术底座**。退出标准：开发人员用代码在 Qian 上写出一个多租户应用——登录 / SSO、鉴权、数据存储、文件上传、配置、网关、事件、审计全部由平台提供；一个官方 `module` 插件能独立出修订、逐租户迁移、回切。核心交付：18 个系统插件（ADR-003）、SDK（源生成器 + CLI + TCK）、部署物料、Kun 缺口修复、能力目录与清单 v1、授权 v0、yue 令牌层 + 基础组件 + 后台壳。
- **D18.3 S2 低代码构建**。退出标准：跑通「建应用 → 建表单与列表 → 走审批 → 授权给租户用户使用」；同一应用包在两个租户分别安装、各自配置、独立升级互不影响。核心交付：元数据注册表、动态数据引擎、Schema Migrator、表单 / 列表 / 审批流设计器与运行时、流程内核、控件注册表、数据权限与字段权限、Operation/Task；Wasm `function` 运行时不计入核心交付，为 S2 可选（P2，见 D18.7）。
- **D18.4 S3 面向客户**。退出标准：租户能从应用市场选购并开通应用，自助配置 IdP 与品牌。核心交付：私有目录型市场 → ISV 开放、权益与计费、门户、报表、租户自助、高隔离档、不可信 UI 沙箱。
- **D18.5 S4 AI 原生 Agent 平台**。退出标准：Agent 能发现、调用、编排乃至生成平台能力与应用。核心交付：每租户 MCP 门面、Agent 主体与委托链、元数据生成闭环、与 iClaw 运行时对接。
- **D18.6 S1 起生效的防返工设计**（否则 S4 返工）：所有写操作走带 Schema 的命令（含副作用等级、幂等键、`dryRun`），UI 也不例外；结构化、可被模型自我纠正的错误（ProblemDetails 扩展：错误码、字段、允许值）；统一主体模型 `user / service / agent` 与委托链字段；可解释、可预检的权限判定；一份契约多处生成（OpenAPI / MCP 工具 / 权限点 / yue 表单）；租户上下文只来自令牌，`inputSchema` 禁止租户字段；审计含主体链与来源通道；追踪与计量贯通、协议端点无状态；事件契约化（稳定 ID + JSON Schema）；能力目录 ≠ 公开 OpenAPI（经鉴权、按权限过滤）；插件包签名、内容哈希、兼容范围与反向权限审批；出网 SSRF 基线分两步——平台自有出网点（OIDC 发现、企业微信、SMTP、短信、Apollo、对象存储）S1 必做，低代码连接器与第三方出网点 S2。
- **D18.7 补充裁决的阶段归属**：企业微信连接器 S1 必做，钉钉 / 飞书 S2 必做，ISV 第三方应用模式 S3；refresh 令牌与单点登出 S1 必做；短信渠道 S1 必做；令牌三层结构 S1 必做、DTCG 导出 S1 可选；Module Federation 2 运行时 S1 必做；Wasm `function` 运行时 S2 可选（公式与规则先用 JSON AST，ABI S2 中期拍板，Wasm 在 ISV 函数插件前落地）；打印 S2 必做（模板、版本、数据绑定、浏览器打印），打印设计器 S2 后期；工作台 S3 必做（S2 只有审批四列表 + 应用入口）；公告 S3 可选；自动化 S2 可选、S3 必做；决策引擎 S3 可选；门户与报表 S3，配置路径型门户与报表子集 S2 可选；大屏 S3 可选；视图 S2 可选；Operation/Task S1 可选、S2 必做；流程整体 S2，S1 只交付前置。
- **D18.8 S1 是否含模型网关底座接线**：作为可选项（ADR-003 D3.4、ADR-015 D15.8）；不计入 S1 退出标准。
- **D18.9 「必做 / 可选 / 不做」口径**：必做 = 阶段退出标准依赖；可选 = 有余力即做、不阻塞退出；不做 = 附原因并写入 PRD「明确不支持」小节。
- **D18.10 验收方式**：每个功能项标题带阶段标记；验收三件套（checkbox / YAML 用例 / 阶段退出准则）；与现状有差异处写「实现与目标态差异 + 日期」过渡态块。
- **D18.11 S1 显式预算**：OIDC 一致性测试、渗透测试、Kun 缺口集成测试、安全补丁节奏进入 S1 计划。

## 3 理由（Rationale）

- 以退出标准分级而非以「重要程度」分级，是七份基线能对齐的唯一尺度（基线 W §0.2）。
- 「低代码构建」先于「面向客户」：没有可打包分发的应用，市场无物可卖；S2 的两租户验收正是 S3 市场的前置（基线 P §7.2 M1）。
- 防返工清单放在 S1 是因为这些设计的成本在 S1 几乎为零、在 S4 则是全量改造（基线 P §8.3）。
- 把补充裁决的阶段归属集中写在一处，避免 PRD 各章各说各话。

## 4 备选方案与放弃原因（Alternatives）

- **跳过 S2 直接做市场**：市场缺少可分发的应用形态与包格式验证。放弃。
- **先做 Agent 再做低代码**：没有能力目录与元数据，Agent 无物可发现、可生成。放弃。
- **S1 与 S2 并行**：S2 的元数据层依赖 S1 的租户 / 身份 / 鉴权 / Filter AST 契约，并行会产生两套契约。放弃（允许 S1 末提前 Elsa PoC 与流程内核 API 设计）。

## 5 后果与代价（Consequences）

- 正面：每阶段有可验收的退出标准；PRD 各章按同一阶段口径引用；防返工清单使 S4 成本可控。
- 负面：S1 工期长且外部可见价值低（没有低代码界面），需要用「开发者用代码写出多租户应用」的 demo 对外证明；S1 两座大山的安全预算必须真实投入。
- 配套：阶段路线写入 `PRD §15`，成功指标写入 `PRD §16`；每阶段结束做一次 ADR 复审。

## 6 对各阶段的影响

- **S1**：D18.2 全部 + D18.6 全部 + D18.7 中标 S1 的项目；模型网关接线可选。
- **S2**：D18.3 + D18.7 中标 S2 的项目；流程域为主线（3–4 人数个迭代）。
- **S3**：D18.4 + D18.7 中标 S3 的项目；每阶段复审 S3 可选项是否升级。
- **S4**：D18.5；S4 不放松任何 S3 的安全边界。

## 7 待确认事项

- S1 是否包含模型网关底座接线（决策清单 D18 需拍板项，Q1–Q18 未直接覆盖；本 ADR 标为可选）。
- 已裁决（R2）：Wasm `function` 运行时统一为 S2 可选（P2），不列入 S2 核心交付，ABI 在 S2 中期拍板；决策清单 D18 表格已同步修订。
- S1 工期与安全预算的具体数字（PRD §15 / §16）。
- 每阶段结束的 ADR 复审机制。
