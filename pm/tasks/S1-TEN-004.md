## 背景

`ITenantSettings.Get<T>(pluginId, key)`：值按插件 `config.schema`（`scopes: [tenant]`）校验、变更审计、缓存键带租户前缀；平台默认值来自 Apollo，租户覆盖即租户 scope patch（存 PG `scope_patches`，与文件 patch 同格式同校验器）；`GET/PUT /tenants/{id}/settings/{plugin}`、`GET /tenants/{id}/quota`；单管理员 + 用户配额（不计平台超管、计租户管理员，Q12）。登录策略、密码策略、文件配额都是它的客户。

## 验收

- [x] UT + IT（R97 改写）：租户配额存于主档 `quotas`，`GET /tenants/{id}/quota` 返回限额与用量（用量经 Identity 的计数端口，缺席时只返回限额并标明）；配额判定端口对「用户配额 5、当前已 5 人」返回结构化错误 `CARDINALITY_USER_LIMIT`，平台超管不计入、租户管理员计入（Q12）；成员创建时的拦截 IT 归 S1-IDP-003
- [x] IT（R97 改写）：经 `PUT /tenants/{id}/settings/{plugin}` 写入租户级登录策略覆盖后，变更出现在审计链，另一宿主的 `ITenantSettings.Get` 在 ≤ 5 s 内读到新值且无需重启；「下一次登录即生效」在 S1-IDP-006 验收第 3 条
- [x] UT：不符合插件 `config.schema` 的租户覆盖值被拒绝并带 JSON Pointer
- [x] IT（R97 改写）：注册表 tenant scope 合成视图（`GET /api/registry/scopes/{scopeKey}/entries` 与运行时合成器）中该插件条目的 `config` 与 `ITenantSettings` 读到的值一致；CLI `qian dump-config --scope tenant:<id>` 的打印归 S1-RT-012 验收第 4 条
