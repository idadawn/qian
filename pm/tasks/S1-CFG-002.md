## 背景

`secretRef://k8s/<ns>/<name>#<key>` 解析（Infisical 后端 P2 抽象位）；疑似密钥键名 / 值扫描拦截；分工表写进开发手册（部署级引导项 → Kustomize；平台 / 服务级非敏感 → Apollo；密钥 → K8s Secret；租户级在线设置 → `ITenantSettings`；前端 → `window.__APP_CONF__`）。全部需要凭据的组件（连接器、渠道、文件 Provider、信任根）依赖它。

复核口径（S1-DEC-019 R67，2026-10-13）：公开引用以组件规格 §11.3 为准（`secretRef://platform|tenant|dev/...`），`secretRef://k8s/<ns>/<name>#<key>` 只作可信引导的底层定位；「CI 门禁」是 `dotnet` 工作流对仓库全部 profile 的生效配置执行 `Qian.Secrets.Tool --profiles`（门禁自测含注入明文的反例），线上 Apollo 值由 Kun 运行期逐 namespace 拒绝明文、发布前用 `--apollo` 扫描候选；分工表在 `docs/ops/configuration-runbook.md`，迁移手册 §8 不含此表。

## 验收

- [x] UT：`secretRef://k8s/...` 解析到 K8s Secret 文件；无法解析时返回结构化错误而非空值
- [x] UT：`config.schema` 中标 `sensitive` 的键若在 Apollo 填了非 `secretRef://` 值，CI 门禁失败
- [x] UT：疑似密钥键名 / 值（如 `password`、`secret`、长随机串）进入 Apollo 非 secretRef 值时被扫描拦截
- [x] 文档：分工表入开发手册
