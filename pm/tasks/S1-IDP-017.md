## 背景

S1-DEC-033 D5：成员管理最小集提前到 S1。产品负责人 2026-11-11 确认「按推荐提前」（R145，PRD 7.4.3 已回写），本任务不再等该决策任务。

现状：目录接口（`/api/directory/**`）能列出成员、读写档案与归属、启停、批量禁用和删除，但没有「新增成员」的 HTTP 入口。成员只能由运营开户（管理员）、连接器登录时的 JIT 建号（缺省关闭）、自助申请和开发种子建立，租户管理员没有办法给自己的租户加人。端口 `IIdentityAccounts.CreatePersonAsync` / `CreateMembershipAsync` 已有。

范围：租户管理员在本租户内新增成员。手机号或用户名已对应自然人时绑定为本租户成员，否则新建自然人并设初始密码、首登改密；受用户配额约束。新成员的初始授权口径（默认是否授予 `tenant.user`、由哪个组件授予）开工时与 S1-AZ-005 对齐并写进 README。邀请链接、自助加入与退出、多管理员不在范围（S3）。

## 验收

- [x] IT：租户管理员新增成员后，该成员能登录本租户，初始授权符合写明的口径；初始密码首登必须修改；响应与日志不含明文密码
  - `DirectoryMemberAddTests.管理员新增成员_新号码新建自然人_首登强制改密后能登录本租户_响应日志与事件不含明文密码_同事务发出member_created`：登录先得 `password_change_required`；改回初始密码被拒（`PASSWORD_REUSED`，初始密码已进密码历史），改成新密码后进入本租户、`/me` 是新成员、拿到授权码；响应 no-store 且没有密码字段，Outbox 与日志不含初始密码。
  - 初始授权口径见 R158（`tenant.user`），由 CRM 参考宿主的 `IdentityAuthzTests.新增成员能力经真实授权与审计执行_…` 在真实 Authz 下验证：新成员有 `customer:read`，没有 `customer:write` 与 `member:create`。
- [x] IT：号码或用户名已对应自然人时绑定为成员而不新建自然人；同一自然人在同一租户重复新增返回结构化冲突错误
  - `DirectoryMemberAddTests.号码或用户名已对应自然人时绑定为成员不新建也不改凭据_同一自然人重复新增与已停用已删除成员返回结构化冲突`：E.164 号码与大小写混写的用户名都绑定到原自然人，凭据不变。
  - 重复新增，以及加已停用、已从目录删除的成员，都返回 409 `DIRECTORY_MEMBER_EXISTS`（指针 `#/identifier`），无写入。
- [x] IT：达到用户配额返回 `CARDINALITY_USER_LIMIT` 且无写入；平台身份、停用或锁定的账号不能被加为成员（与 Q12 同口径）
  - `DirectoryMemberAddTests.达到用户配额返回CARDINALITY_USER_LIMIT且无写入_平台身份停用锁定账号不能加为成员`：新建与绑定两条路径都返回 422，自然人、标识、成员、修订与事件计数都不变；只剩一个名额时 3 个并发请求恰好 1 个成功。
  - 平台身份、停用、锁定的账号返回 422 `DIRECTORY_MEMBER_INELIGIBLE`，恢复启用后可以加入。
- [x] IT：非管理员成员调用被拒且无写入，另一租户看不到本租户成员；平台身份调用被拒且无写入（R158 ②，原为「平台超管经旁路操作写平台审计链」）
  - `DirectoryMemberAddTests.非管理员与平台会话调用被拒且无写入_缺防伪与带租户字段被拒_另一租户看不到本租户新成员_并发新建同一号码只有一个自然人`：以下请求都无写入——非管理员 403、平台会话 403、匿名 401、缺防伪 400、带 `tenant_id` 400、表单编码 415。
  - 同一用例：另一租户的管理员在列表、按 id 批量与归属接口里都看不到新成员；两个租户并发加同一个新号码，只建一个自然人，两边各有一个成员。
  - 能力入口的非管理员（持有权限点也不行）、Identity 管理员但没有 `member:create`（未授任何角色）与跨租户作用域，在 CRM 用例里验证，都无写入。
- [x] UT：能力标 `write` + `confirm`，权限点登记进组件的权限目录，HTTP 契约快照与端点一致
  - `DirectoryMemberContractTests.新增成员能力标write与confirm且不对Agent暴露_权限点与默认角色登记进组件目录_发布表面与代码派生一致`：代码派生的 `directory.member.add` 是 write、confirm、pii、`agent.expose=false`；`member:create` 以中风险进 `metadata/permissions.json`，默认角色只给 owner / admin；`tools/` 与代码派生一致。
  - `DirectoryMemberContractTests.成员管理契约与实际端点一致_…`：`contracts/identity/v1/directory-members.openapi.json` 与实际端点、请求体绑定、响应序列化逐字段一致，`Membership` 与查询契约是同一定义。
- [x] 新增成员写审计（操作人、成员、租户）；成员变更事件与 S1-IDP-010 的 `directory.member.*.v1` 对齐
  - 审计：CRM `IdentityAuthzTests.新增成员能力经真实授权与审计执行_…` 读甲方审计链，actor 是管理员，载荷带成员 id 与自然人 id。新建、绑定各有开始与成功记录，失败各有开始与失败记录，任何记录都不含初始密码。
  - 事件：身份用例断言同一事务恰好发出一条 `directory.member.created.v1`，actor 是管理员；失败与被拒的请求不留事件。
