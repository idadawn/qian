## 背景

S1-QA-012（#168）交付了本机租户运营手测环境：`scripts/dev-tenant-ops.sh up` 起 PostgreSQL 与运营宿主，`walkthrough` 用 curl 走查运营契约 8 个路径、11 个操作，本机 36/36。

它的问题是只在 CI 里编译，走查从没在 CI 里跑过。手测宿主照搬集成测试的平台装配，Tenancy、Authz、Registry、Lifecycle 等的装配一变，它就可能在运行期失效而没人发现。

S1-DEC-024 又要求 S1-TEN-005 的「页面可用」检查优先复用这个入口，所以它需要持续可用。本任务在托管 runner 上原样执行同一组命令，把它变成一道 CI 冒烟。不改产品代码，也不改走查的业务期望。

## 验收

- [x] 脚本加 `smoke` 子命令：后台起环境 → 等运营宿主就绪（有超时）→ `walkthrough --yes` → 停宿主。退出码即走查结果，失败时打印宿主日志。本机与 CI 执行同一条命令。
- [x] `status` 子命令的退出码有意义：运营宿主在运行时为 0，否则为 1。
- [x] 新增 CI 工作流，在 ubuntu-latest 上跑 `smoke`：
  - 与 dotnet 的「构建、门禁与测试」并行，不挤占它的时长预算；
  - 失败时上传宿主日志；
  - 用路径过滤跳过只改文档与任务的 PR，取舍写进进度日志。
- [x] 证明这道门禁能拦住问题：临时注入一处会让走查失败的改动，`smoke` 非零退出并打印宿主日志；撤掉后恢复通过。
- [ ] README 与 AGENTS.md 写明 CI 冒烟与本机复现方法；PR 上新工作流与原有检查全绿。
