## 背景

组件 `qian.config`（`Qian.Config.Abstractions` / `ctx.Config` + `Qian.Config.Apollo`）：公开 HTTP 协议 `/configs`、`/notifications/v2` 长轮询（hold 60s）、AccessKey HMAC-SHA1、本地缓存文件、集群内直连 ConfigService；配置源顺序 appsettings → Apollo（`qian.common.*` → `qian.plugin.<id>` → `application`）→ K8s Secret 文件 → 环境变量 → 命令行；启动时无网络且无缓存 → 关键配置缺失则启动失败；失败降级矩阵 L0–L4 入运维手册；独立模式可只用标准 `IConfiguration`。官方 .NET 客户端只作 PoC 对照。

## 验收

- [ ] IT：在 Apollo 修改 `qian.plugin.sample.pageSize` 后，宿主 ≤ 60s 内 `IOptionsMonitor` 值更新且不重启
- [ ] IT：Apollo 不可达且本地缓存存在时宿主用缓存启动；缓存也不存在时关键配置缺失导致启动失败并打印明确原因
- [ ] UT：配置源叠加顺序以单测固定；`Apollo__AppId/Env/Cluster/ConfigServer__0/Label/CacheDir/AccessKey` 引导项即可启动
- [ ] 文档：失败降级矩阵 L0–L4 写入运维手册
