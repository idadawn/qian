## 背景

2026-11-11 产品负责人问「需要先完成哪些内容才能初步可用：多租户、管理后台可用，然后模型服务可用」。主会话盘点后给出最短路径，产品负责人回复「建任务并重排」。本任务登记里程碑的范围与顺序、盘点发现的缺口，以及据此新建、拆分与重排的任务。

盘点结论（按 main 82b5d43095 核对）：

- 多租户与平台控制台的代码已验收（租户生命周期、运营开户、自助申请与审核、登录与选租户、外壳、平台控制台），但只在本机联调环境（`scripts/dev-shell.sh up`）与集成测试里装配。`hosts/` 只有网关宿主，没有业务镜像，集群上没有部署。
- 管理后台只有平台运营一侧（租户管理、开通申请）。租户管理员一侧没有页面；目录接口能查询成员、启停、调整归属，没有「新增成员」的 HTTP 入口。
- 模型服务在 Qian 侧只有组件目录与配置 Schema（清单标 `x-skeleton`）。
- 拆分部署还缺一段跨宿主的接力，此前没有任务。identity 组合包带 Tenancy 与开通申请组件，不带 Authz / Registry / Lifecycle；base 组合包带 Tenancy / Authz / Registry / Lifecycle 与 Identity.Client，不带身份服务。开通编排第 05 步（建管理员成员）经进程内的身份端口，端口缺席时记 `identity_unavailable` 等续跑；第 03、07 步要 Lifecycle 与 Authz。身份账号端口只有 Identity.Server 的进程内实现。已验收的装配里各宿主共用一个运行时，所以这条路径没有在两个进程下跑过。

D1 由产品负责人的指示直接决定，D2 已于 2026-11-11 选 A，两项登记为 R143。D3–D7 是主会话的推荐口径，产品负责人逐条确认或改裁后登记进 `docs/decisions/key-decisions-v0.md`；依赖本任务的新任务在裁决前不开工。

- D1 里程碑与顺序（产品负责人 2026-11-11 指示）：先让多租户可用，再让管理后台可用，然后模型服务可用。里程碑期间看板优先级按这条路径排：路径上的任务为 P0，不在路径上的原 P0 任务降为 P1（清单见下节）。这只改先后，不改 PRD 7.0.3 对 S1 退出标准的口径；里程碑达成后复核降级清单。
- D2 staging 首次部署的形状（已裁决：产品负责人 2026-11-11 选 A「平台身份同进程」，R143，写入 ADR-017 §10）。推荐 A：照联调环境与集成测试已验收的同进程形状，平台与身份同一个进程，网关独立；数据层用 S1-DEP-001 的专属 PG / Redis，清单手写，镜像按 digest（S1-DEP-011）。这样不需要跨宿主接力、S1-IDP-012 与 RabbitMQ 就能跑通登录、开户与审核。代价：staging 暂不满足 ADR-005 的「身份独立安全边界」与 PRD 7.17 的三镜像形状。它不替代 S1-DEP-005 的发布门（S1-DEC-016、ADR-017 §9 不变），拆分部署仍是生产目标。备选 B：直接按三宿主拆分部署，前置加 S1-DEP-010、S1-TEN-023、S1-IDP-012、S1-DEP-008 与 RabbitMQ（S1-DEP-002）。
- D3 拆分部署下开通编排与审核接口的落位（S1-TEN-023）。候选有三：身份服务提供远程的成员开户端口，由平台宿主调用；编排在平台宿主跑到第 04 步后由身份宿主续跑；审核接口随开通申请组件留在身份宿主，或移到平台宿主。主会话暂不推荐。选 A 时这一项不挡里程碑，在生产拆分前定。
- D4 自助注册的短信。推荐：里程碑内先只开运营开户与审核；自助注册的发码在通知渠道（S1-NTF-001 / S1-NTF-003）就绪前照 S1-DEC-032 D5 返回 503 `SIGNUP_UNAVAILABLE`。备选：先做一个只发验证码与审核结果的短信发件实现（实现 `ISignupMessenger`），自助注册随里程碑可用。
- D5 成员管理提前到 S1（S1-IDP-017 / S1-IDP-018）。PRD 7.3 把「加入 / 退出与邀请 UI」、7.4.3 把「通讯录页面」放在 S3。推荐只提前两件：租户管理员直接新增成员（新建账号或绑定已有自然人，受用户配额约束），以及成员管理页（列表、启停、组织与岗位归属）。邀请链接、自助加入与退出、多管理员仍在 S3。页面并入身份组件的 UI 表面还是另立组件，随本项一并定。
- D6 模型服务。S1-MGW-001 提前。S1-MGW-002 拆成两段：先行段 S1-MGW-003（上游入 git、租户 consumer、OpenAI 兼容面调用），计量与限流留在 S1-MGW-002（等 S1-AUD-004 与 S1-DEP-005）。现网 GPUStack 上只有烟测用的对话模型和 Embedding、Reranker，业务对话模型上线是 S1-MGW-003 的仓外前置。ADR-015 §7 的 GPU 归属与 adapter 维护方仍待定。
- D7 与 2026-10 框架细化备忘录的先后。备忘录尚未入库，它的 v0 顺序把 Agent 入口排在前、S1-MGW-001 排在后。推荐本里程碑先行，备忘录的待拍板项另行处理。

运营接口（`/api/tenancy/**`、`/api/signup/applications/**`）并入平台宿主还是独立宿主，由 S1-DEC-026 裁决，S1-DEP-009 开工前要定，本任务不重复。
