## 背景

开通编排由 `qian.lifecycle` 承担（R13），`qian.tenancy` 只装配其租户级 `Provision` 入口：创建主档 → `ITenantProvisioner.ProvisionAsync`（Shared + RLS）→ 对每个平台插件与租户 scope 已挂载组件执行 `tenantProvision` 钩子 → 创建租户管理员 Membership → 写初始授权 → 发通知；失败按 `tenant_provision_steps` / `lifecycle_runs` 步骤表重试，不靠事务、不用 Saga。

## 验收

- [x] IT：开通中途在第 3 步注入失败，重试后从第 3 步继续，前两步不重复执行（`tenant_provision_steps`）
- [x] E2E：参考应用在租户 A、B 分别开通，`lifecycle_runs` 各有一条成功记录；重复开通幂等
- [x] IT（R96 改写）：Shared + RLS 策略下开通后 GUC 与策略就绪；租户管理员指针（`tenant_admins`）与 tenant.owner 初始授权已写入（管理员主体由编排输入给出，经 `Qian.Authz.Abstractions` 的授予端口）；管理员登录复验归 S1-IDP-003（R81 同口径）
- [x] IT（R83，自 S1-RT-009 移交；R91 更正）：真实开户流程在 `qian.tenancy` 上下文派发进程内事件 `tenant/provisioned` 后，`hooks.json` 桥接的能力被触发且审计记录 `channel = hook`，S1-AZ-002 的内置角色监听共用这一派发；集成事件 `tenant.created.v1` 由 S1-TEN-002 的状态机经 Outbox 发布，不经 S1-EVT-002 转成进程内事件
