### A. YUE 机器契约（验收第 3 条）

现状：`packages/yue/core/scripts/export-manifests.mjs` 第 26 行只遍历 `item.props.properties` 顶层，第 29–31 行遇到 TS 里不存在的属性时静默删 description。目录里 Accordion（`value.items` / `defaultValue.items`，约第 2823–2834 行）、Drawer（`snapPoints.items`，约第 2270 行）、Toast（`toast.{id,title,description,type}`，约第 4061–4077 行）、Notification（`toast.{id,title,description}`，约第 4192–4203 行）、Breadcrumb（`items[].{key,label,href}`，约第 4543–4554 行）、Descriptions（`items[].{key,label,children}`，约第 5099–5110 行）的嵌套子 Schema 仍是 `"title": "id"` 与「Button 的 id 属性。」一类模板句（16 行 description、27 处异常）。

- A1 脚本递归：把顶层循环改成递归函数，覆盖对象的 `properties`、数组的 `items`（含 tuple 形态）、`anyOf` / `oneOf` / `allOf` 各分支；每个属性节点 `title` 设为属性名，`description` 取对应 TS 符号的 JSDoc（`getDocumentationComment`），无注释则删除该键。嵌套类型用 `checker.getTypeOfSymbolAtLocation` 沿属性链下钻，数组取元素类型（`Array<T>` / `ReadonlyArray<T>` 的类型参数），联合类型取非 null / undefined 的分支。
- A2 不存在的属性报错：`prop` 为 undefined 时抛错并列出「组件.属性路径」，不再静默。先跑一遍拿到清单（预期 36 个：Empty / Result / Pagination / BackTop / FullScreen 的 `id` / `title` / `aria-*` / `children`，`PinInput.children`，`Breadcrumb.children`，`Icon.title`），逐个处理：实现里确实透传到 DOM 的，在 TS props 类型里显式声明（如复用 `TestIdProps` 或 `React.HTMLAttributes` 的对应字段）；不透传的从目录删除。PR 正文列出每个属性的处理方式。
- A3 重生成并提交：`pnpm --filter @idadawn/yue-core manifest:generate`，再 `manifest:check` 无差异；提交后 `grep -c "的 [A-Za-z]* 属性。" packages/yue/core/src/manifest-catalog.json` 必须为 0。
- A4 断言递归：`packages/yue/core/src/catalog.manifest.test.ts` 第 28–31 行的遍历改成与 A1 相同的节点集合，每个节点断言 `title === 属性名`，有 description 时不匹配正则 `/^.+ 的 .+ 属性。$/`；再加一条断言嵌套节点确有被处理（例如 Toast `toast.id` 的 description 来自 Base UI 注释、Breadcrumb `items[].href` 的 title 为 `href`）。
- A5 文档：`.changeset/qian-manifest-metadata.md` 补「嵌套子 Schema 同样来自 TS 注释」；`packages/yue/core/README.md` 第 78 段同步。
