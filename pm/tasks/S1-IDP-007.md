## 背景

`IIdentityConnector { Descriptor; BeginChallengeAsync; HandleCallbackAsync; ExchangeImplicitAsync }` 与 `connector.manifest`（协议、终端、配置 Schema、密钥只填 secretRef、回调模板），连接器以 `provides[]` + `policy.egress` 声明（R31）、只依赖 `Qian.Identity.Abstractions`；`/connect/callback/{connectorId}` 由本体统一校验 state / nonce；绑定流程（未绑定 → 引导登录并显式确认）归本体；首批 `qian.identity.connector.oidc`（企业 IdP / Authentik 作上游）；假连接器 TCK fixture。

## 验收

- [x] E2E：以 Authentik（运维侧）为上游，经通用 OIDC 连接器登录 Qian；首次登录进入「确认绑定」页，确认后 `ExternalIdentity` 建立，同租户内重复绑定被拒
- [x] TCK：用一个假连接器实现 SPI，连接器清单校验、state 篡改拒绝、回调幂等三项通过
- [x] CI：`Qian.Identity.Connector.Oidc` 不依赖 `Qian.Identity.Server` 实现包
- [x] UT：连接器凭据只接受 secretRef，详情接口不回传密钥

  - SPI 与清单：在已有 `ConnectorDescriptor` 上扩展（`ConnectorTerminals`、固定回调模板 `/connect/callback/{connectorId}`），`ConnectorManifest.Check / Validate` 统一校验，敏感配置只能是 secretRef（`x-qian-sensitive` + string + `^secretRef://` pattern）。连接器经 `ctx.IdentityConnectors().Register(name, connector)` 登记为 `Identity.Connectors:<name>`（R38），租户 scope 遮蔽全局项，restriction 过滤与不存在不可区分。方法名沿用规格 §6.3 的 `BeginSignInAsync / CompleteSignInAsync`（注释注明与 PRD 的 `BeginChallengeAsync / HandleCallbackAsync` 对应），`ExchangeImplicitAsync` 在可选的 `IImplicitIdentityConnector` 上；`ConnectorContext` 增加 PKCE `CodeVerifier`。
  - 统一回调与绑定（Qian.Identity.Server）：迁移 `IdentityConnectorFlows`（`connector_flows`，只存 state 与浏览器密钥的哈希，`tenant_id` 可空、不受 RLS，原因是回调时租户未知；`login_tickets` 增加 `connector` 用途与 `reason`）。state 篡改、换浏览器、换连接器、重复参数一律 422 `AUTH_CONNECTOR_STATE_INVALID` 且流程不受影响；条件更新抢占保证回调幂等；302 到 `/login/connector/{connectorId}?flow=`。确认绑定：流程租户内新鲜认证 + 显式确认（5 分钟窗口），冲突 409 `AUTH_BINDING_CONFLICT` 不泄露对方，票据 10 分钟 `AUTH_BINDING_EXPIRED`；JIT 缺省关闭（租户设置 `connectors:jitProvisioning`，读不到即关闭），受配额约束。会话一律经统一流水线以服务端一次性连接器票据签发，amr 含 `fed`。
  - 通用 OIDC 连接器（新包 Qian.Identity.Connector.Oidc）：授权码 + PKCE S256，发现文档 issuer 逐字一致，id_token 只收 RS / PS / ES 签名并校验 iss / aud / azp / exp / nonce，RFC 9207 的 `iss` 参数，未知 kid 刷新 JWKS（至少间隔 30 秒），凭据只接受 secretRef、换码时现取。只依赖 Identity.Abstractions、Config.Abstractions 与 IdentityModel。
  - 错误码与契约：`AUTH_CONNECTOR_STATE_INVALID` / `AUTH_CONNECTOR_DENIED` / `AUTH_BINDING_CONFLICT` / `AUTH_BINDING_EXPIRED` 在 `IdentityErrors` 定义（owner `qian.identity`）。按 `contracts/v0/README.md`，组件码不进与 `PlatformErrors` 逐字节一致的 `error-codes.json`；登记为 `error-detail.valid.json` 三个样例 + `error-catalog.valid.json` 四码导出样例，测试比对后者与 `IdentityErrors` 的实际导出。
