## 背景

S1-DEC-024 / R109 自 S1-YUE-009 拆出的 `@yue/biz` 基础版：ApiSelect / `useRemoteOptions`、DictSelect、OrganizeSelect、UserSelect、RoleSelect、菜单 / 按钮授权树、IconPicker，全部经注入的 `PlatformClient`（S1-YUE-009）取数，文案走 i18n key。OrganizeSelect 与授权树建在 `@yue/data` 的 Tree / TreeSelect（S1-YUE-008）上，不另做一套树（yue 规格 D3）。本任务对 `@yue/sdk` 的 mock 中间件验收；真实目录数据的 E2E 在 S1-IDP-010，角色授予的 E2E 在 S1-AZ-005。

## 验收

- [x] UT（原 S1-YUE-009 验收 3）：`@yue/biz` 组件不直接发请求，只经注入的 `PlatformClient`；i18n 全部走 key——`packages/yue/biz/src/acceptance.browser.test.tsx`（4 例：屏蔽 fetch / XMLHttpRequest / WebSocket / EventSource / sendBeacon 后，七个组件的请求全部经注入客户端的 mock 中间件并带租户头；换客户端随之改道，新客户端数据到达前界面不沿用旧客户端的结果；三语言包 key 集合一致；伪语言包下逐个渲染正常、已选多项、无匹配、空、加载中、错误与重试、成员截断各状态，界面只剩 key、业务数据与图标名，且 biz 语言包每个 key 都至少渲染过一次）、`remote-options.browser.test.tsx`（3 例：关键字或 reloadKey 变化后，晚到的旧请求结果与失败都不采纳）与 `biz.ssr.test.tsx`（5 例：SSR 首帧不发请求；源码扫描只有 `api.ts` 调 `client.api()`、无直接网络 API 与硬编码 URL、用到的 `biz.*` key 都已登记、注释以外没有中日韩文字且 JSX 文本与可读属性不写死文字）；主会话第一轮复核的 18 处单点突变与自查补充的 6 处全部被抓住
