## 背景

S1-RT-023（[idadawn/qian#112](https://github.com/idadawn/qian/pull/112)）调查时用临时探测确认：条目的 Apply 尚未结束（例如异步 Apply 正在 await）时，另一线程替换或撤销它注入的键，`InvalidateDependents` 只处理 Ready 条目，Applying 的条目不受影响；Apply 结束后的依赖可见性自检失败，条目永久 Failed（.NET 报「在 Apply 期间改变了自身依赖的可见性」，TS 报「Apply 期间改变了自身依赖可见性」），不会重试（探测结果 state=Failed、applies=1）。

规格 §5.1 与 T25 要求：依赖的键被替换或撤销时，以 inject 依赖该键的条目与撤销后再登记一样回到 Pending 并重新 Apply。表面热重载（文件监视线程经注册句柄替换目录项）、Registry 刷新租户 scope 的 restriction，都可能发生在依赖者异步 Apply 的中途。那项自检的本意是拦住插件自己的注册或 restriction 改变自身依赖的可见性（否则 Ready 后立刻自我失效、反复重来），这种情况仍应 Failed。本任务叠加在 S1-RT-023 之上：复用它给共用 TCK 加的闸门操作，并修改同一个协调循环。

## 验收

- [x] UT：确定性复现。consumer 注入 X，异步 Apply 停在 gate 上；Apply 进行中另一线程替换 X，放开 gate 后本次 Apply 作废：先撤销已登记的效果与注册，再以新实例重新 Apply 并 Ready，无失败记录。撤销 X 时条目回到 Pending（不是 Failed），X 再就绪后重新 Apply（`LifecycleTests.Replace_during_Apply_…`、`Revoke_during_Apply_…`；撤销用例放行后再解析 X 抛异常，覆盖失败路径；修复前两项均失败）
- [x] UT：插件在 Apply 中用自己的 restriction 隐藏所注入的全局注册，仍然 Failed（不放宽自检）（`Hiding_its_own_dependency_during_Apply_still_fails`，修复前后均通过）
- [x] 修复：两侧装载器的依赖失效同样作用于 Applying 条目，判据与 Ready 条目相同（从其它条目的视角看依赖已变）；本次 Apply 无论成败都作废，撤销后回到 Pending。插件自身造成的可见性变化仍 Failed；其余断言不放宽（去掉失败路径作废判断的变异被 .NET 单测与两侧场景抓到）
- [x] TCK：共用场景覆盖 Apply 期间替换、撤销与自身隐藏三种情形，.NET 与 TS harness 读同一 YAML 通过；场景格式新增的操作写入 `tck/runtime/README.md`（`invalidate-during-apply.scenario.yml`；新增 Apply 动作 `wait` / `inject`、`mount` 的 `idle: false`、`revoke` 步骤与 `state` 的 Applying；修复前两侧均失败）
- [x] 规格：§5.6 写明 Apply 期间依赖失效的处理，修订历史补记
- [x] 门禁：dotnet 全量构建与测试（带 `QIAN_BUF_PATH` / `QIAN_OASDIFF_PATH`）、`check_deps`、门禁自测、`check_docs`、`pm.py validate` / `build` / `check-fresh`、`pnpm --filter ./packages/qian-runtime test` 通过（本机全量 736/736 零跳过；CI 以 [idadawn/qian#115](https://github.com/idadawn/qian/pull/115) 全部检查通过为合并前提，且须先合 #112）
