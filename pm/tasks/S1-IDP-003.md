## 背景

`Person`（标识集合、Argon2id 凭据与历史哈希、MFA 因子、状态）+ `Membership`（person × tenant、显示名、是否租户管理员、`profile` 预留）+ `ExternalIdentity` + `Client` + `Session` + `LoginAudit`；`ISignInPipeline` 所有方式同一 `LoginInput` 同一签发路径；错误阈值 → 锁定或延时；初始密码强制修改不可取消；多 Membership → `selection_token`（5 分钟）→ 正式令牌；切换租户 = 以选择令牌重签；图形验证码按策略开关。

## 验收

- [x] E2E：同一手机号在租户 A、B 各有 Membership，密码登录后出现租户选择，选 A 后令牌 `tenant_id = A`；在外壳切换到 B 时令牌重签且 `membership_id` 变化
- [x] IT：密码错误达到阈值触发锁定；初始密码账号登录后被强制跳转改密且不可跳过
- [x] UT：密码以 Argon2id 存储且历史哈希不可复用；`LoginAudit` 每次登录一条
- [x] IT（R81，自 S1-TEN-001 移交）：租户管理员经统一登录流水线登录后只看到本租户数据；以 A 的令牌直接请求 B 的记录 id 返回 404
- [x] IT（R95，自 S1-TEN-002 移交）：租户处于 pending / grace / suspended 时（按 `ITenantDirectory` 的状态）该租户的新登录被拒
- [x] IT（R97，自 S1-TEN-004 移交）：用户配额为 5 时第 6 个成员创建返回结构化错误 `CARDINALITY_USER_LIMIT`（经 S1-TEN-004 的配额判定端口），平台超管不计入计数、租户管理员计入
- [x] UT/IT：不同 Person 的 `sub` 不碰撞，含并发创建同一标识（只有一个成功）、并发创建不同账号（各得独立 `sub`）、主键冲突时换号重试而不覆盖既有账号；换绑标识不改写 `sub`（借鉴既有产品「稳定主体 id」的设计，实现自写，不复制其代码）
- [x] IT：解绑最后一个已验证标识被拒绝，返回结构化 `ErrorDetail`（`LAST_VERIFIED_IDENTIFIER`，422，经 `ErrorCatalog.CreateDetail` 渲染）；解绑后让账号没有任何标识同样被拒；对外投影只含掩码（借鉴既有产品的绑定守卫与 DTO 脱敏设计，实现自写）
