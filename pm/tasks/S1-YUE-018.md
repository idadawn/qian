## 背景

原型的「开通申请」「租户管理」在平台控制台里：侧栏有工作台、租户管理、开通申请等入口。现状下平台身份登录外壳后什么都拿不到：
- 网关 bootstrap 对平台身份不调任何下游，只返回代管上下文（`GatewayShellHosting.cs` 的 `BootstrapAsync`）；
- 能力目录的菜单与远程清单只认租户 scope（`NavigationService.cs` 的 `Subject`）；
- S1-YUE-002 裁决把这一现状写成「平台身份只显示代管横幅与会话卡片」。

结果是租户运营页在真实外壳里从未装载过，只能跑在独立开发页或联邦夹具里。S1-DEC-032 D8 改为：持平台超管角色的平台身份加载全局 scope 组件的页面与菜单，按超管角色的只读判定过滤；每次操作仍逐次经超管旁路并审计。

## 验收

- [ ] IT：能力目录对平台主体（全局 scope、`tenant_id` 为空）返回全局 scope 已挂载组件的远程清单与菜单，菜单只在主体持 `platform.superadmin` 时出现；判定只读、不写旁路审计；租户主体、Agent、无平台角色的平台主体拿不到全局菜单
- [ ] IT：网关 bootstrap 对平台身份返回全局 scope 的 remotes / navigation / permissions；无平台角色时仍是代管上下文；响应不含令牌
- [ ] E2E（`pnpm yue:auth` 真实栈）：平台运营登录后侧栏出现「租户管理」，打开即装载 `qian.tenancy` 远程并列出真实租户；租户成员看不到该入口；原「平台身份」用例改为新口径
- [ ] 联调栈（Dev.Shell）托管 `qian.tenancy` 与 `qian.tenancy.signup` 远程并把种子里的平台运营设为平台超管；README 同步
