## 背景

dotnet 工作流的作业「构建、门禁与测试」是每个 PR 的关键路径：单作业、4 vCPU、限时 20 分钟。2026-10-23/24 最近 8 次运行壁钟 765–1174 秒，测试步骤占 564–860 秒。以运行 40034799307 的 TRX 归因：

- 32 个测试模块、1570 条用例，测试步骤 642 秒，模块累计约 2070 模块·秒，同时只跑 4 个模块。
- Config、Sample.Crm、Identity.Server、Scheduler 四个模块占 63%；模块启动顺序每次不同，Scheduler 第 7.5 分钟才开跑。
- 测试镜像约 1.5 GB，拉取发生在测试步骤里，在关键路径上。
- 工作流没有路径过滤：最近 60 个已合并 PR 里 20 个只改任务文件或文档，也各跑一次全量。

本任务只改流水线（工作流与脚本），不改测试源码；测试结构的提速（Config 真实 Apollo 共用一套栈、CRM 拆类）是 S1-QA-017。PRD §14.2.1 要求 PR 级门禁 ≤ 20 分钟、超时优化测试而不放宽门禁：全部门禁与用例照跑，只改编排。

## 验收

- [x] 触发过滤：PR 只改 `pm/**`、`docs/**` 或根目录 `*.md` 时不触发，`docs/generated/**` 与测试读取的文档仍触发；push 到 main 不过滤（`dotnet-release.yml` 要求发布提交本身有通过的 push 运行）。
- [x] 过滤自检：门禁作业核对 .NET 源码以字面量引用的 `docs/`、`pm/` 文件都被过滤重新纳入，漏了即失败。
- [x] 镜像预拉：测试分片开头在后台顺序 `docker pull` 本分片用到的镜像，日志在 `$RUNNER_TEMP`；镜像名由脚本从 `tests/Qian.Testing.Containers` 的 `QIAN_TEST_IMAGE_*` 缺省值解析（环境变量覆盖优先），工作流里不另抄；测试前有界等待，超时不失败。
- [x] 拆作业：「构建与门禁」作业跑还原、构建（PublicAPI 门禁）、入口清单、明文密钥扫描、namespace 骨架、依赖图门禁、门禁自测。
- [x] 测试分片：三个分片作业各自还原、构建后只跑本分片的模块，环境变量与 doctor 客户端构建照旧；分片清单在脚本里，未登记的测试项目自动落入其余分片。
- [x] 汇总核对：汇总作业核对 Qian.slnx 里每个测试项目恰好跑了一次、无失败，少一个模块即失败；各分片结果合并为原名 `test-results` 构件。
- [x] 本 PR 的 CI：三个分片合计条数与同一份代码的 main 全量运行逐模块一致、无跳过（第一次运行 32 个模块、1574 条；1570 是更早提交的条数）；PR 说明列出与基线运行 40034799307 的作业与步骤时长对比。
- [x] 评估分片 a 的 `--max-parallel-test-modules 6`（任务书可选项）：按实测数据决定是否采用，结论与数据记入日志。
- [x] `tests/README.md` 的 CI 一节同步新的作业结构。
