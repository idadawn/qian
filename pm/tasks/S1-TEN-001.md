## 背景

组件 `qian.tenancy`（`Qian.Tenancy.Abstractions` / `ctx.Tenancy` + `Qian.Tenancy`）：`Tenant` / `TenantAdmin` 实体（租户号小写字母数字、创建后不可改；隔离策略创建时一次性决定）、`ITenantContext` 唯一实现（AsyncLocal + 中间件，claim `tenant_id`，生产模式禁头兜底与 `default` 回退）、`ITenantContextPropagator`（事件信封、作业参数、gRPC 元数据）、`ITenantDirectory.Get(code)`、`GET/POST /api/tenancy/tenants`、`PUT /tenants/{id}`（R85：这组 HTTP 运营接口归 S1-TEN-006，本任务的 tenancy API 指 `ITenantDirectory` 内部 API 与 HTTP 租户边界）；独立模式可换宿主 `ITenantContext` 或 `SingleTenant`。第 1 波可信计算基。

## 验收

- [x] UT：生产模式下无令牌、仅带 `X-Tenant-Id` 的请求与无 `tenant_id` 的消息都被拒绝
- [x] IT：以 A 的令牌直接请求 B 的记录 id 返回 404（R81：原 E2E 的运营后台创建租户归 S1-TEN-005、管理员登录归 S1-IDP-003；本任务只保留 HTTP 租户边界，cody 10-12 已交付严格 HTTP 租户边界，核对后勾选）
- [x] IT：`ITenantContextPropagator` 写入的 `tenant_id` 在 gRPC 对端 `BeginScope` 后可读（R81：消费端归 S1-EVT-002、作业执行器归 S1-SCH-002；gRPC 对端适配 cody 10-12 已随 PR #53 交付，核对后勾选）
- [x] UT：`inputSchema` 中不出现 `tenantId`；运营接口的目标租户是资源路径（R81：前半句由 S1-RT-020 的登记期契约检查 `tenant-field` 规则实现，引用 `CapabilityContractCheckTests` 勾选；后半句按内部 API 与 DTO 现状核对成立——写入口 `internal`、id 服务端生成、Create/Update 请求体拒绝 `tenantId` / `tenant_id` / `id`；HTTP 层复验随 S1-TEN-006，R85）
