## 背景

S1-RT-022 差分时发现，表面解析器在以下与代理项无关的情形两端诊断仍不同。错误码与指针相同，行号、文案或有效性不同：

1. YAML 未闭合的引号标量、制表符缩进：.NET（YamlDotNet）报标量或缩进开始的行，CLI（yaml 包）报检测到错误的行。例如双引号标量在第 1 行开始、到第 3 行读到文件末尾仍未闭合时，.NET 报第 1 行，CLI 报第 3 行。
2. 多个 YAML 文档：.NET 扫描完成后报「文件语法、大小、嵌套深度或值无效。」，在第 1 行；CLI 在第二个文档开始的行报 YAML 语法错误。CLI 的 parseDocument 不解析第二个文档，其中的 alias 与未成对代理项两端结论也不同。
3. JSON 嵌套深度：Utf8JsonReader 的 MaxDepth 为 64，拒绝第 65 层的空容器；CLI 的遍历只在第 65 层有子元素时才拒绝。两端都拒绝时，.NET 报所在行与「JSON 语法无效。」，CLI 报第 1 行与通用文案。
4. JSON 非有限数值（如 1e400）：行号相同，.NET 报「JSON 语法无效。」，CLI 报「文件语法、大小、嵌套深度或值无效。」。其后还有语法错误时，.NET 读到数值即停，CLI 先报全文的语法错误。
5. YAML 多行双引号标量的续行缩进不足（如续行与所在映射同缩进、上一行以转义的引号结尾）：.NET 报标量开始的行，CLI 报续行。
6. YAML 外层映射与其后的嵌套映射都有重复键时：YamlDotNet 构造节点时先报嵌套映射里的（文中靠后），CLI 按文中顺序先报外层的。
7. 未闭合的流式集合：S1-RT-022 起 .NET 不再抛 InvalidOperationException，按扫描停下的位置报；集合内有多行内容时，与 CLI 的行号不同。

应统一行号约定、深度阈值与检查顺序，并补表面 TCK 场景。差分做法同 S1-RT-022：把同一内容交给 SurfaceValidator.Parse 与 parseSurface，逐项比较有效性、指针、行号与文案。
