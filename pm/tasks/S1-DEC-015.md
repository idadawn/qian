## 背景

S1-KUN-004 要求用真实 qian-identity 完成 PKCE 联调，但提供真实身份服务的 S1-IDP-002 反过来依赖 S1-KUN-004，且还有 DATA/TEN/AZ 前置。Kun 客户端、会话、S2S 与编译门禁已可独立验证；不能用协议夹具冒充产品身份服务，也不能未经裁决改写现有验收。

## 已裁决

2026-10-11 产品负责人明确选择“分阶段验收（推荐）”。权威结论已写入 ADR-005 §9；SDK 阶段与真实身份服务联调分别由 S1-KUN-004、S1-IDP-002 承担，后者仍是身份服务完成与发布必过项。

## 复核备注（S1-DEC-019 R70，2026-10-13）

本文件与进度日志记载的「产品负责人确认 / 批准」只有 cody 的自述，仓库内没有产品负责人本人的留痕（PR review、评论或提交）。在产品负责人于本节补一行确认之前，本裁决按仓库惯例视为默认裁决：继续生效，不回退据此调整的验收；有异议时新建决策任务。

## 验收

- [x] 产品负责人选择验收归属与依赖处理方式
- [x] 按裁决同步 S1-KUN-004 / S1-IDP-002 的验收和相关 PRD 引用，保留产品联调门禁

## 已准备的证据

Kun 客户端已通过签名协议夹具、真实 HTTP 和 Redis 验证；本地整仓 852 项通过、2 项既有外部对象存储测试跳过，补充策略测试后 Identity 模块 61 项通过；原生程序实测匿名/吊销 401、有效会话 200。Qian 全仓 252 项与 35 项门禁通过。源码及本地测试包均已可评审，不把协议夹具当作真实身份服务。
