## 背景

7.1 第 10–13 项：`Kun.Configuration.Apollo` provider 基础与热更新「校验失败保留旧值并告警」、options JSON Schema 导出；`Kun.Authorization` 只放端口（`IPermissionChecker` / `IDataPermissionFilter` / `IFieldPolicy`）与三处集成；`ICapabilityRegistry` 注册时收 `JsonTypeInfo` 并可枚举；`Kun.Infrastructure` 死接口与旧线 `Kun.Storage` 废弃、`AddKunDapper` 瑕疵、`PerformanceBehavior` 阈值可配。

## 验收

- [x] IT：发布一份非法配置后 `IOptionsMonitor<T>.CurrentValue` 仍返回上一份有效值，且发出告警指标
- [x] UT：`AddKunOptions<T>` 可导出 JSON Schema 2020-12
- [x] UT：未注册实现时任何受保护端点缺省拒绝（fail-closed）；IT：Mediator 行为对标记了所需权限的命令在 handler 前调用 `Check`
- [x] UT：注册一个命令后，能力目录中出现其 ID、请求 / 响应 JSON Schema
- [x] UT：Qian 代码树引用 `Kun.Infrastructure.IRepository` 或旧线 `Kun.Storage.IFileStorage` 即编译错误（Banned API 分析器）
- [x] `KunExceptionHandler` 改走 `IProblemDetailsService`，不再直接 `WriteAsJsonAsync` ProblemDetails（contracts/v0/README.md §3.7 过渡态；否则 Kun 产生的错误体不会被 Qian 规范为 ErrorDetail）
