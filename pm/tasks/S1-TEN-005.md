## 背景

运营后台的租户页面（PRD 7.3「运营后台页面」，S1-DEC-024 / R110 收口）：

- 列表 / 筛选：DataTable 服务端分页，按状态与关键字筛选；
- 新建 / 编辑抽屉：SchemaForm，字段与校验取自 `plugins/qian.tenancy/contracts/http-v1.openapi.json`；
- 状态迁移：按 `GET /api/tenancy/meta/state-machine` 给出的合法动作做激活 / 冻结 / 恢复（S1-TEN-002 的端点）；
- 只读详情与配额：S1-TEN-004 的 `GET /api/tenancy/tenants/{id}/quota`。

页面只用 SchemaForm + DataTable，请求只经 `@yue/sdk` 的 PlatformClient，不出现第二套表单、表格或请求实现。页面是 `qian.tenancy` 的 `ui` 表面，源码作为 pnpm 工作区包交付并带独立开发入口；MF2 远程打包、`ui/manifest.json` 与外壳加载归 S1-YUE-001。后端顺手补列表筛选、排序、总数与状态机元数据的响应 Schema（S1-TEN-006 只交付了 `skip` / `take`），并把租户号与名称的约束写进契约、违反时的 400 带 `pointer`。

不在本任务：管理员维护、重置密码与「授权（调 7.14）」归 S1-TEN-010，角色授予归 S1-AZ-005（R109），登录页与令牌刷新归 S1-IDP-003 / S1-YUE-002。自助申请 / 审核 / 邀请为 S3。验收载体是 S1-TEN-006 的真实宿主与测试签发的平台超管令牌；IDP-003 与 TEN-010 交付前，新建表单的管理员按契约直填 `membershipId` / `subjectId`，开通第 5 步记 `skipped`（R96 既定行为）。
