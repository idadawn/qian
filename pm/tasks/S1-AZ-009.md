## 背景

R7（PRD §12.2 第 17 条）与 PRD 7.5 的链路是：授权变更 → `authz.grant.changed.v1` → 7.4 递增受影响主体的 `identity_revision` → 7.13 推送刷新。两端已交付：

- S1-AZ-004：同事务把授权事件写进 Outbox，并提供 PEP 修订下限 `subject_identity_revisions`。
- S1-IDP-004：提供 `IIdentityAccounts.BumpIdentityRevisionAsync`；身份侧对修订落后的旧令牌拒绝，refresh 换到新修订。

本任务补中间这段接线，是 S1-IDP-004 日志里登记给授权任务的接续项。S1-AZ-004 的验收只模拟了「更高修订出现」，没有调用身份端口。

接线侧、失败处理、触发范围、非 user 主体、PEP 下限与陈旧令牌响应码有六处设计分歧，提交 S1-DEC-027 拍板，见 [决策说明](../../docs/decisions/authz-identity-revision-wiring.md)。

## 验收

- [ ] 按 S1-DEC-027 的结论实现接线：授权授予变更提交后，受影响 user 主体在该租户的 `identity_revision` 递增；非 user 主体与无成员身份的主体按结论处理，不报错、不重试
- [ ] IT（Testcontainers，身份与授权同在真实宿主）：撤销授予后 ≤ 3 秒，修订递增；旧令牌在身份侧（userinfo / 会话校验）与 PEP 侧均被拒；refresh 拿到新修订的令牌并被 PEP 放行
- [ ] 结论里拆分部署（platform / identity 两个 Pod）未覆盖的部分登记到承接任务（S1-EVT-002 或新任务），本任务不宣称拆分部署已闭环
- [ ] `packages/Qian.Authz` 与 `packages/Qian.Identity.Server` 的 README / AGENTS 同步接线位置、宿主要求与失败口径；`docs/generated` 按最终源码重生成
