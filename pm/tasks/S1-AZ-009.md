## 背景

R7（PRD §12.2 第 17 条）与 PRD 7.5 的链路是：授权变更 → `authz.grant.changed.v1` → 7.4 递增受影响主体的 `identity_revision` → 7.13 推送刷新。两端已交付：

- S1-AZ-004：同事务把授权事件写进 Outbox，并提供 PEP 修订下限 `subject_identity_revisions`。
- S1-IDP-004：提供 `IIdentityAccounts.BumpIdentityRevisionAsync`；身份侧对修订落后的旧令牌拒绝，refresh 换到新修订。

本任务补中间这段接线，是 S1-IDP-004 日志里登记给授权任务的接续项。S1-AZ-004 的验收只模拟了「更高修订出现」，没有调用身份端口。

接线侧、失败处理、触发范围、非 user 主体、PEP 下限与陈旧令牌响应码有六处设计分歧，已由 S1-DEC-027 拍板（2026-10-22，全部按推荐），见 [决策说明](../../docs/decisions/authz-identity-revision-wiring.md)。本任务交付同进程宿主的闭环，拆分部署由 S1-IDP-012 承接。

## 验收

- [x] 授权侧：授予的增、改、撤提交后，在同一调用内对受影响 user 主体经身份端口递增该租户的 `identity_revision`，并把 PEP 修订下限同步抬到返回值（只增不减）。约束如下：
  - 瞬时故障退避重试，总时长 ≤ 3 秒；仍失败记警告与计数，不回滚授权变更。
  - 非 user、非 GUID、无成员身份的主体跳过，不重试。
  - `authz.role.changed.v1` 不扇出。
  - 身份组件不在本进程时跳过。
- [x] PEP：陈旧令牌在 HTTP 回 401 `UNAUTHENTICATED`、在 gRPC 回 Unauthenticated（命令管道同为 `UNAUTHENTICATED`），决策日志原因仍为 `identity_revision_stale`
- [x] IT（Testcontainers，身份与授权同在参考宿主）：撤销授予后 ≤ 3 秒，修订递增；旧令牌在身份侧（userinfo）与 PEP 侧均被拒（PEP 401）；refresh 拿到新修订的令牌并被 PEP 放行
- [x] 拆分部署（platform / identity 两个 Pod）的闭环登记为 S1-IDP-012（随 S1-EVT-002），本任务不宣称拆分部署已闭环
- [x] `packages/Qian.Authz` 与 `packages/Qian.Identity.Server` 的 README / AGENTS 同步接线位置、宿主要求与失败口径；`docs/generated` 按最终源码重生成
