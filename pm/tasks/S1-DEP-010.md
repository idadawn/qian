## 背景

S1-DEC-033 盘点发现的缺口。`hosts/` 只有 `Qian.Gateway.Host`。身份服务（Qian.Identity.Server）目前只在联调宿主（`tools/Qian.Dev.Shell` 的 `DevIdentity` / `DevSignup`，与参考应用同进程）和集成测试里装配，没有可发布的生产宿主；`deploy/images/README.md` 的缺口表也写着 qian-identity「可启动的唯一 issuer 宿主尚未交付」。S1-DEP-008 的 qian-identity 镜像以它为前置。

本任务交付 identity profile 的生产宿主：经 profile 与 `qian.bundle.identity-server` 装配，承载 OpenIddict 协议面、账号与会话接口、组织目录接口、连接器回调，经 `UseQianIdentityPages` 同源托管认证页族，并挂开通申请组件的申请人接口与公开页（S1-DEC-032 D2）。

开工时注意：

- identity profile 与组合包仍标 `x-skeleton`，`profiles/identity/qian.patch.yml` 为空；组合包里的 issuer、连接器与 Apollo 地址是占位值，环境值经 overlay 与 secretRef 提供。
- 生产不登记开发期发件箱、种子与 `/__dev/` 路由。`ISignupMessenger` 没有实现时发验证码返回 503（S1-DEC-032 D5、S1-DEC-033 D4）。
- identity 组合包不带 Authz，开通申请的运营接口在本宿主上按不存在处理；审核接口与开通编排在拆分部署下的落位见 S1-TEN-023。
- staging 首次部署若按同进程形状（S1-DEC-033 D2 推荐 A），里程碑不等本任务，优先级随之降为 P1；本任务仍是生产拆分部署与 S1-DEP-008 的前置。

## 验收

- [ ] 生产宿主入口经 identity profile 装配身份服务及其依赖（Data / Tenancy / Config / Events / Audit），独立 schema `identity`，运行期连接只用受限角色；签名密钥与连接器密钥只经 secretRef
- [ ] IT：discovery、授权码 + PKCE、refresh 轮换、userinfo、登出与后通道登出在本宿主上通过，issuer 取自配置且为 https；账号、会话、目录接口与联调宿主同一契约
- [ ] IT：认证页族由 `UseQianIdentityPages` 托管，`/login`、`/login/select-tenant` 与 `/login/assets/*` 的缓存与安全头与 S1-YUE-012 的断言一致
- [ ] IT：申请人接口与公开页在本宿主可用；没有发件实现时发验证码 503 `SIGNUP_UNAVAILABLE`；不存在 `/__dev/` 路由与开发期发件箱
