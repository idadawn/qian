## 背景

S1-IDP-014 实测发现：Kun 2026.10.14 的全部包都缺 IsTrimmable 元数据。Kun 的 `Directory.Build.props` 用两个条件 PropertyGroup 按 `IsAotCandidate` 打开（或显式关闭）`IsAotCompatible` / `IsTrimmable` / 三个分析器，但这个开关写在各项目的 csproj 里，求值晚于 props，条件永远不成立；`dotnet msbuild -getProperty` 实测 Kun.Identity / Kun.Identity.AspNetCore / Kun.Security 的 IsAotCompatible 与 IsTrimmable 都为空。Kun CI 的 aot-audit 矩阵用 `-p:PublishAot=true` 发布，兜住了分析器，但矩阵里有 Kun.Identity、Kun.Security，没有同样标了 `IsAotCandidate=true` 的 Kun.Identity.AspNetCore。后果：消费方只看包元数据会误判 Kun 包不兼容 AOT（Qian 的身份组件因此一度不能声明 `x-aot`，改以 Qian 侧 ILC 冒烟背书，见 S1-IDP-014），裁剪发布也不会按可裁剪程序集处理这些包。本任务只在 Qian 侧登记，代码改动去 kun 仓库提 PR（ADR-021），Qian 任务里只回链。

## 验收

- [ ] Kun：把 `Directory.Build.props` 里两个按 `IsAotCandidate` 条件的 PropertyGroup 挪到 `Directory.Build.targets`；`dotnet msbuild -getProperty:IsAotCompatible;IsTrimmable` 对 `IsAotCandidate=true` 的项目返回 true、对 `false` 的项目返回 false；打出的 nupkg 程序集带 `AssemblyMetadata("IsTrimmable", "True")`
- [ ] Kun：CI 的 aot-audit 矩阵补上 Kun.Identity.AspNetCore（核对全部 `IsAotCandidate=true` 的项目都在矩阵里），修复与矩阵改动随 kun PR 合并并发正式版
- [ ] Qian：升级 `KunVersion` 后 S1-IDP-014 的 NativeAOT 冒烟仍为 0 条 IL 警告；`docs/adr/` 或 `with-qian.mdx` 里凡写「Kun 包无 AOT 标记」的地方按新版本更正
