## 背景

2026-10-14 claude 复核 S1-RT-006（逐项验收对照 main 上的代码与测试，本机 Release 构建 0 警告、全量 630/630、Qian.Capabilities.Tests 7/7、Qian.Sample.Crm.Tests 28/28，共用过滤 TCK 五种情况目录 / 提示词 / 执行一致）。结论：代码与测试扎实，验收 1、2、4、5 成立，第 3 项只成立一半：「挂载不兼容组件被拒绝」只在测试手工用 `OpenApiContractPlugin` / `GrpcContractPlugin` 包装时发生，两者在 packages、samples、tools 内除自身外零引用，Registry 挂载路径不做包装。另有设计外新增的通用执行入口 `POST /api/capabilities/{plugin}/{name}/invoke`，PRD、规格、ADR-020 都未定义。

本任务收拢能在 Capabilities 范围内完成的整改；不属本范围的余项按「余项归属」登记到归属任务。相关裁决 R75–R77 见 `docs/decisions/key-decisions-v0.md`，产品负责人指派本任务即视为认可默认裁决，有异议时新建决策任务。接手时先认领：`python3 scripts/pm.py set S1-RT-019 --status doing --owner <名字> --by <名字> --note "开始"`。

## 验收

- [ ] 别名头：`GET /api/kernel/capabilities` 与 `/api/kernel/capabilities/openapi.json` 的响应同时带 `Deprecation` 与 `Link: <后继路径>; rel="successor-version"`（规格 §9.5）；IT 断言两个头的值；PRD 7.2.1 与 S1-RT-006 验收文字补上 Link
- [ ] invoke 规范化（R75）：规格 §9.5 的端点表加一行定义 `POST /api/capabilities/{plugin}/{name}/invoke`，PRD 7.2.1 同步；实现上请求体先按条目 `inputSchema` 用 JSON Schema 2020-12 校验，失败返回 ErrorDetail `VALIDATION_FAILED` 并带 JSON Pointer；读取 `Idempotency-Key`，同一键重放不重复执行（复用 Kun 的幂等行为，R63；若 Kun 侧需改动，另开 KUN 任务并在此记录）；Agent 主体仍需 `agent.expose` 且不开放 Actor 委托；README 第 22 行改为与实现一致，并说明 ApiExplorer 不列通用模板、聚合 OpenAPI 列具体路径的原因；IT 覆盖 schema 不符 400、幂等重放、Agent 主体三种情况
- [ ] 偏好表迁移：`CapabilitiesDbContext` 随包提供 EF 迁移（生成 ENABLE / FORCE RLS 与策略，与 `Qian.Data` 的生成器一致），`QianDataMigrator` 对该上下文不再因无迁移而跳过；IT 在真实 PostgreSQL 上经迁移器建表并断言 `pg_policies` 中存在该表的租户策略，不再依赖 `GenerateCreateScript`
- [ ] 目录信封契约：`GET /api/capabilities` 返回具名类型，`Produces<>` 声明与实际一致；`contracts/v0` 新增目录信封 Schema（`items`、`ttlMs`、`cacheScope`）与 fixture，按仓库规则同步 `Qian.Runtime.Errors` 的一致性测试；IT 按信封 Schema 校验整个响应
- [ ] 测试补强：独立重算 `schemaSha256`（RFC 8785 JCS + SHA-256）并与目录值相等；断言 `sideEffect / policyHint / requiredScopes` 的实际取值；`kind` 非法与 `q` 超长返回 400 ErrorDetail，`kind=query` 有正例；目录与 openapi 的匿名 401 断言 ErrorDetail 体（`code` 为 `UNAUTHENTICATED`）
- [ ] 文档口径：README 删除「保持 doing / PR 保持草稿」等过期状态句，改为引用任务编号；README 或 PRD 7.18 第 12 项注明目录枚举机制是 SDK 具名绑定与 Registry scope 视图取交集，而非 `AddRequestHandler` 收集；导航只接受 User / Service 主体而目录多接受 Agent 的差异及理由写进 README；PRD 7.2.1 第 145 行删除 `extension_points` 表（与第 147 行一致，扩展点是事件与可逆注册）；`check_docs.py` 通过
- [ ] 工程细节：`ttlMs` 从组件配置读取（`plugins/qian.capabilities/schemas/config.schema.json` 增加 `catalogTtlMs`，默认 1000）；buf 输出解析只取合法 JSON 行、其余按 stderr 记录而不是抛异常；Registry scope Reconciler 的 Apply 失败异常带插件 ID、修订与原因码（管理面出口归 S1-RT-005）
- [ ] S1-RT-006 收口（R76）：验收第 3 项改写为「机制完成；挂载路径的强制准入归 S1-RT-005」，`depends` 注明实际消费的是 S1-RT-004 / S1-AZ-003 已交付的端口；本任务转 review 后由 claude 复核，S1-RT-006 与本任务一起由产品负责人认可后才 done
