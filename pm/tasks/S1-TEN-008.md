## 背景

S1-TEN-006 四条验收成立（复核 claude，2026-10-16，R105），本任务收口复核发现的契约与测试缺口。`TenantManagementTests` 对 `tenantId` 的断言只检查 `requestBody` 的 `$ref` 原文，永远不含 `tenantId`，且未覆盖 PUT；S1-RT-020 的 `tenant-field` 规则只在能力契约编译器检查 `inputSchema`，OpenAPI 文档不经该规则。契约准入用例先断言已发布契约与候选相等再跑 oasdiff，是自比，证明不了破坏性变更会被拒。`POST` 的 `Location` 指向 `/api/tenancy/tenants/{id}`，而该路径没有 GET 处理器。`PlatformHttpContract` 只用于构建契约、不进租户可见聚合的排除逻辑没有任何用例。契约与行为不一致：`administrator` 在契约里可空、HTTP 却必填；`isolation` 枚举含 schema / database、实际只收 row；分页参数 `take` 1..100 / `skip` ≥ 0 不在 schema；契约无 4xx 响应与 `x-qian-permission`（生成器归 S1-AZ-004）。快照更新路径写出单行 JSON，PR #154（S1-TEN-002）已把仓库文件从缩进格式整文件重写为单行，diff 不可读；#154 / #155 又加入状态端点、`GET /api/tenancy/meta/state-machine`、设置与配额端点（行为分别归 S1-TEN-002 / S1-TEN-004 验收），本任务的契约检查覆盖全部端点。审计断言只查非空与 `bypass = superadmin`，未断数量与权限点、未断拒绝不写审计。端点丢弃超管旁路的拒绝原因（platform_role_not_configured / permission_not_registered / audit_unavailable 与 not_superadmin 在运维侧无法区分）。宿主接线（排除 TenantRequestBoundary、MapInboundClaims=false、ICurrentUser）全靠 README 文字，仓库内无真实宿主调用 `MapQianTenancy`。
