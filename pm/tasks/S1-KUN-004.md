## 背景

7.1 第 6、7 项：`ExchangeCodeAsync` 发送 `code_verifier`、校验 `nonce`、补 refresh / client_credentials / discovery 刷新、会话索引与后通道登出、日志只记 sid 哈希、CSRF、`SignInHelper` DI；三套签发器收敛为网关 `S2sTokenIssuer` 一套并对齐 iClaw S2S claim 契约，`exp − iat ≤ 300s`，约 30 处下游产品字样改为可配置。7.4 / 7.9 的前提。

## 验收

- [ ] IT：对强制 PKCE 的 IdP（用 7.4 的 `qian-identity` 本身）完成授权码换取；篡改 `nonce` 的 id_token 被拒绝
- [x] IT：吊销某用户全部会话后，其任一 sid 的请求返回 401
- [x] 代码审查：日志中不出现明文 sid（grep 门禁）
- [x] UT：Qian 代码树中引用废弃签发器即编译告警升错误
- [x] IT：网关签出的 S2S 令牌通过 iClaw `contracts/v0/s2s-jwt-claims` JSON Schema 校验
- [x] 代码审查：`Kun.*` 发布包中 grep 不到下游产品名的默认值

## 验收证据与阻塞

- 显式区分：真实 HTTP/RSA 协议夹具已证明 PKCE verifier 发送、nonce 篡改拒绝、state/到期/重放保护；它不是 Qian 身份服务，第一项验收保留未勾选。S1-IDP-002 依赖本任务，故提交 S1-DEC-015 裁决阶段划分。
- 真实 Redis 的原子续期/吊销/索引/重放测试通过；实际 HTTP 验证多会话吊销后均为 401，其他用户仍可访问；写请求缺防跨站令牌在 handler 前拒绝。异常含原始 sid 时，日志仍只有 SHA256 与异常类型。
- 网关按冻结 contracts/v0/s2s-claims.schema.json 验证五种主体/租户/角色组合，固定 aud/roles 数组、UUID、每跳 audience 和 1–300 秒寿命。旧签发 API 标记 KUNS2S001。
- Qian 编译负例引用当前 KunVersion 的真实发布包，两个旧签发器及旧注册方法被 RS0030 拦截，即使关闭一般警告升错仍失败；网关签发器正例通过。全仓 252 项测试和 35 项门禁通过。
- 本地五个测试包打包和默认值扫描通过；它们未发布到 feed。升级需规范身份投影、Redis 新键空间与重新登录、共享 Data Protection 密钥，详见上游 Identity 客户端指南。
