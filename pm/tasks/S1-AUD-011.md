## 背景

S1-YUE-015 裁决 ③（产品负责人 2026-10-24 选推荐项）：经外壳发起的能力执行，审计来源通道沿用能力登记时的 `api`，`ui` 的归因另立本任务。

ADR-009 D9.6 的来源通道含 `ui`。要让审计区分「外壳经网关 BFF 会话发起」与「外部 API 客户端带 Bearer 发起」，需要一个可信的通道来源，而现在两处都没有：

- S2S 冻结契约（`contracts/v0/s2s-claims.schema.json`，`additionalProperties: false`）不带通道，新增 claim 要改契约。
- SDK 的通道在 `AddQianCapability` 登记时固定（`CommandInvocation.Channel`），按调用取通道要改 SDK。

开工前先写方案交产品负责人拍板（承载方式如 S2S claim、网关按会话来源分路由、SDK 按调用取通道），再按裁决实现。

## 验收

- [ ] 方案与裁决记进任务文件；通道只取自网关的可信信号，请求头、正文与客户端提供的值都不是来源
- [ ] 按裁决实现：外壳经网关 BFF 会话发起的能力执行审计记 `channel = ui`，外部 Bearer 发起的仍记 `api`；IT 覆盖两种来源与试图伪造通道的请求
- [ ] 涉及的契约、文档与门禁同步
