## 租户可用（本批收口）

S1-TEN-004 转 review 前，在真实宿主（Kestrel + JwtBearer 验签 + 受限 PG 应用角色，复用 S1-TEN-001 的测试宿主）跑通下面六步并把证据写进 S1-TEN-004 的进度日志；不含登录、会话与页面：

1. 平台超管（专用平台登录、无租户上下文）`POST /api/tenancy/tenants` 创建租户 A、B：201，id 服务端生成，状态 pending；请求体带 `tenantId` / `id` 返回 400；租户主体的令牌 403 `AUTHZ_DENIED`，无凭据 401。
2. 开通编排跑完 `tenant_provision_steps`：主档 → `ITenantProvisioner`（GUC 与 RLS 策略就绪）→ 逐组件 `Provision(tenant, plugin)`（`lifecycle_runs` 各一条）→ 在 `qian.tenancy` 上下文派发 `tenant/provisioned`（`qian.authz` 建四个内置角色，hooks 桥接触发且审计 `channel = hook`）→ 管理员指针 + tenant.owner 初始授权 → 通知步因 `qian.notify` 缺席记 `skipped`；第 3 步注入失败后重试从第 3 步继续，前两步不重复；同一租户重复开通幂等。
3. pending 时 A 的业务命令被策略拒绝；`POST /api/tenancy/tenants/{A}:activate` → active，Outbox 有 `tenant.activated.v1`；之后同一命令 200。
4. `PUT /api/tenancy/tenants/{A}/settings/{plugin}` 写一个租户覆盖：经 configSchema 校验（非法值 400 带 JSON Pointer）、审计链有记录、另一宿主 `ITenantSettings.Get` ≤ 5 s 读到；`GET /api/tenancy/tenants/{A}/quota` 返回限额。
5. `:suspend` → 业务命令拒绝、`tenant.suspended.v1`；`:resume` → 回 active 恢复放行；到期扫描能力对 `valid_until` 已过的租户 → grace + `tenant.expired.v1`，业务入口拒绝；非法迁移返回结构化错误。
6. A 的令牌读 B 的记录 id → 404（S1-TEN-001 既有用例继续通过）。
