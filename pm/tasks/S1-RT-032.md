## 背景

S1-RT-009 四条验收成立、done 维持；复核（claude，2026-10-16）发现其背景范围里有几块无人承接，按裁决 R92 汇到本任务：`HookBridgePlugin` 只接受四个 serial 事件 × `plugin` 类型，其余一律 Apply 失败——连 R39 要求透传的 Agent 宿主事件（大驼峰，如 `PreToolUse`）也被拒装，静态合法的组件在服务端宿主装不上；`registry/entry-mounted` / `entry-disabled` 两个进程内事件已定义、桥接已监听，但 `qian.registry` 从不派发，事件图里没有生产方；静态校验器按 R41 允许 system / official 的受限 argv（`allowCommandHooks`），运行时却对 `command` / `http` 一律拒装，TCK 没有受限 argv 正例与 http 用例；PRD 7.2.2 列入 S1 的「`.mcp.json` 由 `qian add` 装进开发者 Agent 宿主配置」CLI 未做（只复制进 `.qian`）；TS 侧 `@qian/surfaces` 与 `qian` CLI 均 `private`、无发布流程，`@qian/runtime` 0.1.1 之后的公共 API 变更（`RegistrationHandle.replace`）未 bump，消费者拿不到 TS 热重载与 doctor；`MapQianSurfaceDiagnostics` 只被测试宿主接线，产品宿主没有映射。R92 已把 command / http 执行器与非 serial 分发模式定为 S2，本任务不做执行器。

## 验收

- [ ] IT：`HookBridgePlugin` 对 Agent 宿主事件（大驼峰）与矩阵内未桥接的 Qian 事件只忽略不拒装（R39 透传），`type: command` / `http` 的声明在 S1 以 `SURFACE_POLICY_DENIED` 级诊断拒装且与静态校验器同口径（R92）；TCK 补 official + `allowCommandHooks` 非 shell argv 的静态正例与 http hooks 用例，并直接喂入桥接断言拒装
- [ ] IT：`qian.registry` 在 scope 条目合入为挂载 / 禁用后派发进程内 `registry/entry-mounted` / `entry-disabled`（生产方 `qian.registry`，subject 为条目 id，serial），桥接可消费并审计 `channel = hook`；`docs/generated/event-graph.md` 为这两个事件与 `tenant/provisioned` 列出生产方，生成器识别桥接的 `ctx.On` 订阅
- [ ] E2E：`qian add` 把 `.mcp.json` 的 `mcpServers` 按 scope 过滤后写入开发者 Agent 宿主配置（PRD 7.2.2），`qian remove` 逆序撤销，宿主配置里不出现凭据
- [ ] 发布：`@qian/runtime` 发布含 `RegistrationHandle.replace` 的补丁版本并在 `packages/qian-surfaces` 钉住最低版本；`@qian/surfaces` 与 `qian` CLI 的发布形态定下来（发布到正式源，或在两包 README 写明私有并说明消费方式）；`packages/Qian.Surfaces/README.md` 与 `tck/runtime/README.md` 的过时句（TS 补丁待发布、hooks 验收待收尾）删除
- [ ] IT：platform 参考宿主映射 `MapQianSurfaceDiagnostics`（授权策略 + 以已验证租户为 source），`qian doctor --url` 对真实宿主可用；hook handler 内部再调用其它能力时的审计通道口径写进 README（当前按 (能力, scope) 精确匹配，嵌套调用记默认通道）
