## 背景

进 `platform` / `gateway` / `standalone` 的 RP 包：授权码 + PKCE 换取、`nonce` 校验、refresh、discovery 定期刷新、Cookie 会话 `qian.sid`、S2S 令牌验签（`aud` 绑定、禁透传）；独立宿主可只装 Client 对接任意 OIDC 发行方。网关与 `qian add identity` 的依赖。

## 验收

- [x] IT：对强制 PKCE 的 `qian-identity` 完成授权码换取；篡改 `nonce` 的 id_token 被拒绝（`tests/Qian.Identity.Client.Tests/RelyingPartyTests.cs`：真实账号模型与 OpenIddict，HTTPS 依赖方宿主经 `/auth/login` → 授权端点 → 回调换码建立 `qian.sid`；发行方私钥重签、只改 nonce 的 id_token 回 `OIDC_TOKEN_INVALID` 且不建会话，iss 不符、state 重放、发行方错误同样拒绝）
- [x] IT：S2S 令牌 `aud` 不匹配或透传上一跳令牌时下游拒绝（`S2sTests.cs` 用真实 Kun 网关签发器与 PEM 密钥：受众不符、第一跳把入站 Authorization 原样转给第二跳、多受众、用户访问令牌直打下游、契约逐条违约均 401；`RelyingPartyTests` 另验证会话规范主体经签发器铸 S2S 后下游接受、转给另一受众被拒）
- [x] E2E：独立宿主只装 `Qian.Identity.Client` 对接外部 OIDC 发行方完成登录（`tests/Qian.Identity.Client.Standalone.Tests`：Testcontainers 起 Dex，公开 PKCE 客户端、进程内会话，登录与登出走通；另断言依赖闭包只有 Client 及其 Runtime / Abstractions）

- 2026-10-22 claude：接缝记录。会话 Cookie 名 `qian.sid`（`IdentityClientDefaults.SessionCookieName`，值是 Kun 的 256 位不透明会话标识，永不当作 session_id）；与 IDP-003 / 004 的 S2S claim 形状：规范模式（配置 `Resource`）从已验签的访问令牌投影 `sub / principal_kind / tenant_id（平台身份 JSON null）/ membership_id / identity_revision / session_id（取发行方 sid）/ scope / amr / acr`，并核对与登录 id_token 同主体同租户；投影后的 ClaimsPrincipal 原样是 Kun `S2sTokenIssuer.IssueForAudienceAsync` 的输入（IT 已真实铸出并被下游接受）。`identity_revision` 透传：Kun `SessionData` 不带它，所以每个请求从当前访问令牌取，刷新后随新令牌更新；IDP-004 递增修订后，旧访问令牌在刷新前仍带旧值，由 PEP / 身份服务按修订拒绝（与 S1-DEC-027 / AZ-009 的 403-vs-401 待拍板项相关）。KUN-004 的 RP 原语（PKCE 事务 Cookie、nonce 绑定、refresh 主体核对、后通道 logout_token 验签）全部直接复用；后通道登出 IT 已验证身份服务吊销 → RP 本地会话失效；与 YUE-002 / auth-pages §4.7 的接缝：外壳回调态页面也叫 `/auth/callback`，BFF 下服务端回调与外壳页面不能同路径，`RedirectUri` 与 `PathPrefix` 都是可配置项，最终路径随 D5 定
