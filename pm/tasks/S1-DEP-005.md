## 背景

不可变发布事件（40 位 SHA、CalVer、`dry_run`）→ 验签 → 固定检出 → 构建推送 → 迁移 Job 先行（`--migrate-only`，advisory lock）→ `kustomize edit set image` 按 digest 写回 → Argo 收敛 → smoke（`/readyz` + 参考应用登录）；Argo Application `qian-platform`（L2）、`qian-integrations`（租户接线）；`prune: false` 起步；`Qian.Runtime` 与 profile 随 CalVer 发布。

## 验收

- [ ] E2E：从一次发布事件到 staging 三个 profile 镜像全部 `Ready`、外壳经 `gateway` 可访问、参考应用可登录，中间无人工步骤
- [ ] E2E：真实 `qian-platform` 在 staging 经实际协议与认证访问本环境 PG / Redis / RabbitMQ / Apollo，精确网络放行与应用就绪状态一致；记录工作负载镜像 digest、环境端点和脱敏结果。这是发布必过门，不能以诊断 Pod、同名标签、共享服务或仅 TCP 连通代替（DEC-016）
- [ ] E2E：kill `qian-platform` 一个副本，`/readyz` 摘流、无 5xx 泄漏到网关；滚动升级时迁移 Job 先完成再切镜像
- [ ] 检查：Argo `qian-platform`、`qian-integrations` Application 存在且按 digest 引用
