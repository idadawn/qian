## 背景

S1-CFG-008（idadawn/qian#102）之后，profile 装配的两端 Schema 验证器（CLI 为 Ajv 8.20，.NET 为 JsonSchema.Net 9.4.0）共用正则翻译规则，诊断也归一为出错实例位置。用 77 组 Schema 与配置做差分时，以下情形两端仍不一致，S1-CFG-008 只把它们写进了 `packages/Qian.Profiles/README.md` 的已知分歧：

1. prefixItems 之后的 items。JsonSchema.Net 9.4.0 的 `ItemsKeyword.Evaluate` 跳过前缀后从 0 起算实例位置（上游缺陷，`["a", 1, 2]` 报 `/0`、`/1`，应为 `/1`、`/2`）；Ajv 对 `items: false` 只在数组上报一条。
2. unevaluatedItems。Ajv 对 `false` 只报数组位置；JsonSchema.Net 逐项报告，且按规范把 contains 匹配的项算作已求值，Ajv 不算。
3. minLength 与 maxLength。JsonSchema.Net 用 `StringInfo.LengthInTextElements` 按文本元素计数（`e` 加组合重音算 1），Ajv 按码点计数（算 2）。
4. multipleOf 的小数。Ajv 用浮点取余，`0.3` 不算 `0.1` 的倍数；.NET 按十进制判断为倍数。
5. 超过 2^53 的整数。Ajv 按双精度比较，const、enum、minimum 等的结论与 .NET 不同。
6. `$schema` 声明 draft-07。Ajv2020 无法编译，CLI 报无法解析；JsonSchema.Net 按 draft-07 验证。
7. contains 或 propertyNames 的子 Schema 经 `$ref` 引用、且 Ajv 没有内联引用时，Ajv 的错误不再带外层关联，CLI 多报逐项位置或对象位置。

两端的归一规则在 `ProfileLoader.Locations` 与 `profiles.ts` 的 `locations`。差分做法：把同一组 Schema 与配置写进 `tck/profiles/base` 的临时副本，同时交给 `loadProfile` 与 `ProfileLoader`，逐项比较诊断。
