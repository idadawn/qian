## 背景

三套 TCK 之一：`Inject` / `Apply`、五种分发、可逆副作用、scope 遮蔽与 `restrict` 交集、patch 替换；fixture 与语言无关（以 ADR-020 与 specs/component-model.md 为准，不以某个实现为准），.NET 侧在 `minimal` profile 基准宿主运行，TS 侧随 S1-RT-003 接入同一组 fixture。S1-M1 首版。

## 验收

- [x] TCK：`Inject` 的服务键无人提供 → 启动失败并指出缺失键与请求方；依赖成环 → 结构化错误列出环路；卸载后 `dump-config` 与服务容器中无残留
- [x] TCK：五种分发模式各一组用例；事件声明的模式与调用点不一致时 CI 失败
- [x] TCK：scope 遮蔽与 `restrict` 交集；被过滤项在目录、提示词与执行三处都「不存在」
- [x] 检查：fixture 以语言无关格式存放并被 .NET 与 TS 两侧共同引用
- [x] TCK：T19 两端真实文件监视更新表面，保持代码对象与效果，并核对卸载清理
- [x] TCK：T23 按组件规格 §10.2，用同组真实 Provider 在 minimal 与实际 platform 宿主运行同一场景并核对等价；单一模式或骨架清单不能代替双宿主证据（口径，S1-DEC-019 R68：platform 宿主是 TCK 生成的组合包 `qian.bundle.tck-platform`，启用真实 Registry / Capabilities，不是仓库交付的 `profiles/platform`；Provider 组是 CRM 样例组合；ADR-019 D19.8 第二条点名的 Files / Authz / Identity.Client 平台模式对照由 S1-QA-003 / S1-QA-005 承担）

共同引用证据：[主线双侧 CI](https://github.com/idadawn/qian/actions/runs/38146040203) 在 `efa87397fd8313c93ff28ec4d3a9f3ca997528cf` 上通过。现有 23 个 YAML 场景和 T15–T17 的 3 个装配场景由两侧直接读取；TS 共 34 项、.NET 运行时共 46 项测试通过。该项证明现有 fixture 的格式与共同消费，仅是当时的核心场景证据；T19、T23 与产品链路的后续证据见进度日志及 tck/runtime/README.md。
