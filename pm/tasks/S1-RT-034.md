## 背景

S1-RT-014 的 `dotnet-release` 工作流与 `scripts/dotnet_release.py` 已把 0.1.0 的 35 个包锁步发到 GitHub Packages 并真实还原（复核 claude，2026-10-16）；复核同时发现几处只在出事时才暴露的缺口：`dotnet nuget push` 没有 `--skip-duplicate`，35 次推送中途失败就只能换版本号；`verify-feed` 取版本列表 `per_page=100` 不翻页，版本超过 100 后会误报；`verify-packages` 不核对 `PackageReadmeFile`（39 个包里只有 Generators 带 README，ADR-019 §5 要求每包 README 含独立模式装配）与符号包，包族内依赖只核下限（`[0.1.0, )` 也算钉住）；`plugins/*/.qian-plugin/plugin.json` 的 `runtime.nuget[]` 版本与摘要靠人工同步；`test_dotnet_release.py` 没有覆盖 `check-version` 的包源查重分支与 `feed_records`；`CodeDerivedManifestTests` 按 `{runtime}/../../../packs/Microsoft.NETCore.App.Ref/<版本>/analyzers` 定位 System.Text.Json 源生成器，runtime-only 安装或 `DOTNET_ROOT` 与 packs 不同根时直接找不到；工作流注释与任务日志把私有句引为「ADR-021 D21.1」。包族已从 0.1.0 的 35 个长到 39 个（Qian.Authz.AspNetCore、Qian.Lifecycle 三包），下次发版的 `verify-feed` 按 39 核对。

## 验收

- [ ] 工作流：推送带 `--skip-duplicate`，部分推送失败后同一版本可重跑续推；`verify-feed` 版本列表翻页；运行末尾核对 `plugins/*/.qian-plugin/plugin.json` 的 `runtime.nuget[]` 版本（与摘要）是否指向本次发布，不一致时给出待同步清单；核对已发布制品含清单声称的生成元数据（Qian.Config.Apollo 0.1.0 早于代码派生改动，S1-RT-011 复核）
- [ ] `verify-packages`：核对每个包的 `PackageReadmeFile`（ADR-019 §5）与符号包；包族内依赖按精确区间锁步，或在 ADR-019 D19.7 写明「下限锁步」并保持现状（二选一，写明理由）
- [ ] 门禁自测：`test_dotnet_release.py` 用注入的 fetch 覆盖 `check-version` 的包源查重分支与 `feed_records`；`CodeDerivedManifestTests` 的 System.Text.Json 源生成器定位改为不依赖 `packs/` 布局（按 `DOTNET_ROOT` / SDK 解析或引用包内分析器）
- [ ] 文档：发版步骤（版本号、触发条件、失败续推、清单同步）写进 SDK 页或 `docs/ops/`，SDK 安装页给出 nuget.config 的 `%ENV%` 凭据引用写法；`.github/workflows/dotnet-release.yml` 注释里的「ADR-021 D21.1」改为 §1 / D21.2 与 R93
