## 背景

S1-RT-014 六条验收成立、done 维持；复核（claude，2026-10-16，裁决 R94）发现 PRD 7.2.3 与两处移交里无人承接的部分汇到本任务：生成器只派生 `inject` / `provides` / `runtime.form` / `runtime.entry` 与 `tools/*.json`，遇到具名 `Provide(key, name, …)`、注册表 `Register(name, …)` 或 `CommandPolicies.Register` 直接报 QIANSDK002（S1-DATA-006 的 `Data.Dialects:pg`、S1-RT-011 建议 ③ 都卡在这里）；PRD 列为派生字段的权限点、事件声明与规格 §3 / §12 G1 的 `configSchema` 没有进 `plugin.json`；全仓 19 个 `IQianPlugin` 实现只有 Data / Events / Config.Apollo 三个带 `[QianPlugin]`，`plugins/` 下 32 个清单仍是 `x-skeleton`（S1-RT-006 / S1-RT-019 曾移交给 RT-014「随清单合并生成替换」），CI 的漂移检查也只手写列举这三个；`qian-plugin check|sync` 对无注解程序集、`id` 不一致、第二份清单、手写覆盖、路径逃逸一律输出通用 `INPUT_INVALID` 且不带承诺的 `errors`，CI 失败时看不出原因；参考宿主 `samples/Qian.Sample.Crm` 没有 `.qian-plugin/plugin.json`（仓库里没有任何带 `[Capability]` 的真实组件清单），三条业务端点只用 `WithMetadata(new PluginEndpointBinding(...))`、没有 `RequireQianPlugin`，示例宿主本身不装 `PluginEnabledMiddleware`，`AddQianCapabilities()` 漏调时静默回退。

## 验收

- [ ] 生成器：`[ExtensionPoint]` / `[Contributes]`（或等价的独立声明）让 `Apply` 里的具名 `Provide(key, name, …)`、注册表 `Register(name, …)` 与 `CommandPolicies.Register` 派生为 `provides: ["<Key>:<name>"]`（R38，规格 §5.5），不再报 QIANSDK002；S1-DATA-006 的 `qian.data.dialect.pg` 与 S1-RT-011 建议 ③ 以此落地
- [ ] 生成器：`[Permission]` 权限点与 `[QianEvent]` 事件声明按 R37 派生进组件文件夹的 `metadata/permissions.json` / `metadata/events.json`（带派生指针，不进 `plugin.json`，R101 澄清），`configSchema` 由代码派生（规格 §3 带代码组件、§12 G1）；手写同名字段视为漂移，`check` 失败并指出指针
- [ ] 清单：其余含 `IQianPlugin` 实现的平台包（Audit、Authz、Capabilities、Lifecycle、Registry、Tenancy、Surfaces、Surfaces.Hosting 等）加 `[QianPlugin]` 并 `sync` 清单（Authz 的 `Authz.Permissions`、`Authz.SuperadminBypass` 与兼作服务键的 `qian.authz.resource-type/v1` 先按 R101 改为规格内的单段键；qian.authz 清单的 `scopes` 含 tenant 而 `AuthzPlugin` 只接受 global，一并改，S1-AZ-002 复核），`x-skeleton` 只按 S1-DEC-018 口径留在 `qian add` 尚未通过的组件（qian.events / qian.config 已通过，随本条去标并同步 Profiles 测试计数与 docs/generated，R100）；手写字段与代码一致（qian.config 清单的 `scopes` 含 tenant 而代码只接受 global、`description` 仍写骨架，S1-RT-011 复核）；多实现程序集按 S1-DEC-028 / 规格 §3.7：每个组件一个入口，同程序集可含多个不同 ID 的组件；包装器与动态适配器显式分类，不虚构独立清单；CI 对每个带代码组件跑 `check`（不再逐个列举三步）
- [ ] 工具：`qian-plugin check|sync` 对程序集无 `[QianPlugin]`、`id` 不一致、第二份清单、手写覆盖、路径逃逸各给出自己的错误码与原因文本，不再一律 `INPUT_INVALID`；UT 覆盖 PRD 7.2.3 的「仓库出现第二份清单时门禁失败」
- [ ] 参考宿主：`samples/Qian.Sample.Crm` 补 `.qian-plugin/plugin.json`（`tools/*.json` 由代码派生）并进 CI check；三条业务端点改用 `RequireQianPlugin`，示例宿主在 platform 条件下装 `AddQianPluginEndpoints` / `UseQianPluginEndpoints`（独立模式在 README 写明无可见性门）；platform profile 下 `AddQianCapabilities()` 漏调记 Warning 或拒绝启动
- [ ] 文档：`packages/Qian.Plugin.Sdk/README.md` 与文档站 SDK 页列出已派生 / 手写字段清单与推迟到 S2 的项（R94）
