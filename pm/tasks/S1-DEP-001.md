## 背景

S1-M1 K3s 基线：`qian-staging` / `qian-prod` 命名空间；每环境专属 PostgreSQL 16（`qian` 库、schema-per-service、RLS 开启）与 Redis 7（不复用跨 ns 共享实例）；default-deny NetworkPolicy + 按 `permissions.egress` 白名单放行（平台自有出网点 SSRF 基线，R10）；ResourceQuota / LimitRange / PDB 模板；K3s `--secrets-encryption`；Traefik `forwardedHeaders.trustedIPs`；生产独立节点池（Q16）；Harbor 新增「插件包 OCI artifact」制品类型。

## 验收

- [x] E2E：在 `qian-staging` 内启动一个未声明 egress 的 Pod，访问外网与其他 ns 被 NetworkPolicy 拒绝；明确标识的已授权诊断工作负载能经真实协议/认证访问本环境 PG / Redis（基线阶段，不冒充平台应用）
- [x] 检查：`qian-staging` / `qian-prod` 使用独立命名空间、专属 PG / Redis 与独立数据卷；生产独立节点池实际就绪
- [x] 检查：`qian-staging` 命名空间存在 ResourceQuota 与 LimitRange；无 `:latest` 镜像
- [x] 检查：Traefik `trustedIPs` 已配置，OIDC issuer 为 https；K3s secrets-encryption 开启

真实 `qian-platform` 访问 PG / Redis / RabbitMQ / Apollo 的协议联调按已批准的 DEC-016 留在 S1-DEP-005 发布必过项；本任务完成不代表应用已经完成该联调。
