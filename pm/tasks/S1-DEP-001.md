## 背景

S1-M1 K3s 基线：`qian-staging` / `qian-prod` 命名空间；每环境专属 PostgreSQL 16（`qian` 库、schema-per-service、RLS 开启）与 Redis 7（不复用跨 ns 共享实例）；default-deny NetworkPolicy + 按 `permissions.egress` 白名单放行（平台自有出网点 SSRF 基线，R10）；ResourceQuota / LimitRange / PDB 模板；K3s `--secrets-encryption`；Traefik `forwardedHeaders.trustedIPs`；生产独立节点池（Q16）；Harbor 新增「插件包 OCI artifact」制品类型。

## 验收

- [ ] E2E：在 `qian-staging` 内启动一个未声明 egress 的 Pod，访问外网与其他 ns 被 NetworkPolicy 拒绝；`qian-platform` 能访问 PG / Redis / RabbitMQ / Apollo
- [ ] 检查：`qian-staging` 命名空间存在 ResourceQuota 与 LimitRange；无 `:latest` 镜像
- [ ] 检查：Traefik `trustedIPs` 已配置，OIDC issuer 为 https；K3s secrets-encryption 开启
