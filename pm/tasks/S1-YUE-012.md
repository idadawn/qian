## 背景

S1-YUE-002 验收复核（2026-10-23，done；R129）后仓内有两套外壳入口，各自只走通一半：

- `apps/qian-shell`（S1-YUE-001，MF2 静态宿主）：`index.html` 读 `/app-config.js` 的 `apiBase` / `bootstrapUrl` / `auditUrl`，经 bootstrap 聚合端点取 `context`（tenant、membership、app、locale、theme）、`remotes`（组件 ID、版本、scope、ui 清单）、`mounted / entitled` 与 `permissions`，远程模块经 `loadRemote` 按需加载；验收用的是 fixture bootstrap，没有真实登录。
- `apps/qian-shell-auth`（S1-YUE-002，薄入口）：真实登录——网关 Identity.Client BFF 会话（`GET /auth/session`、`POST /auth/session/refresh`、`/auth/login?returnTo=…[&prompt=select_account]`）、`PlatformClient({ sessionProvider })` 合并并发 401、能力导航 `GET /api/capabilities/navigation` → 路由、有效权限 `GET /api/authz/me/permissions`、运行时配置 `/app-conf.js`（`readAppConf`）、403 / 404 / 500 / 离线兜底与过期对话框；页面内容只是远程模块占位，没有 MF2 宿主。

本任务把两者融合成唯一可部署的外壳入口，并补验 S1-YUE-002 未勾的验收 2。要点：

1. 网关（Identity.Client / Qian.Gateway 生产入口）新增 bootstrap 聚合端点，路径与返回形状以 `apps/qian-shell` 的 bootstrap 契约为准：`context` 取自 `qian.sid` 会话的规范身份快照（tenant、membership、displayName）与偏好缺省；`remotes` 与 `mounted / entitled` 取自租户 scope 的 registry / lifecycle 条目（未挂载的组件不出现，其 `mf-manifest.json` 不被引用）；`permissions` 与 `GET /api/authz/me/permissions` 同源同义；响应不含任何令牌，匿名 401，平台身份（tenant_id 为空）给出代管上下文。权益（`entitled`）的真实来源归 S1-ENT-002，此处先按 mounted 等价并写明。
2. `apps/qian-shell` 的 `ShellApplication` 接入 `@idadawn/yue-shell` 的真实接线模块：无会话顶层跳 `/auth/login`、`sessionProvider` 刷新合并、`prompt=select_account` 切换租户、`SessionExpiredDialog`、兜底页与离线横幅；运行时配置合并为一份（`app-config.js` 与 `app-conf.js` 二选一，字段 `apiBase` / `authBase` / `bootstrapUrl` / `auditUrl` 统一走同源路径校验）。
3. 真实流程 E2E 从 `apps/qian-shell-auth/e2e/auth.spec.ts` 迁入 `apps/qian-shell`（仍对 `tools/Qian.Dev.Shell` 拉起的真实栈运行，入口脚本与 `shell-auth` 工作流改指向新目录），并补 S1-YUE-002 验收 2：参考应用远程模块在租户 A scope 已挂载时按需加载并出现在导航；切到租户 B（未挂载）时 `mf-manifest.json` 不被请求。联调环境要为乙方租户提供「未挂载」形态（种子不再给 beta 挂参考应用，或另建第三租户）。
4. 融合完成后撤销 `apps/qian-shell-auth`（目录、`yue:auth` 根脚本名可沿用但指向新入口）；`packages/qian-identity-ui` 与 `tools/Qian.Dev.Shell` 不动。
5. 融合时一并处理（S1-YUE-002 验收复核的独立审读意见）：两个入口的 `window.__APP_CONF__` 形状冲突（YUE-001 `apiBase: location.origin` 是绝对源，YUE-002 的 `readAppConf` 拒绝绝对源，同一份 ConfigMap 无法同时满足）；运行时配置改为 JSON 经 fetch 读取并给外壳加 CSP `script-src`（普通脚本形态下能写 ConfigMap 即可在外壳源执行任意脚本，形状校验发生在脚本执行之后）；两套 PlatformClient 接法与两套路由（PRD 7.15 写的是 react-router 7）；共用偏好命名空间 `qian-shell`；运行时配置的 `locale` 被持久化成用户偏好、`Promise.all` 让辅助接口 403 整页 403、`/?x=1` 404、`html[lang]` 不随语言切换、`Number()` 还原身份修订抵消 int64 策略；Qian 专有接线（`/api/identity/*`、Identity.Client 会话、能力导航）放在通用库 `@idadawn/yue-shell` 与 ADR-019 D19.1 的张力（评估拆到 `@qian/*` 包）；认证页族与外壳静态产物的生产托管（`/login` 的 `frame-ancestors` / no-store / Referrer-Policy 目前只在 Dev.Shell 里，Identity.Server 缺省 `SelectionPath` 指向未托管的页面）要给 S1-DEP 任务一个明确交付物；平台表面宿主在生产里由谁提供（联调栈是 dev 拼装的 `DevPlatformApi`，CRM 参考命令宿主只认机器身份）。
