## 背景

PRD 7.3 API 行的 `GET/POST /api/tenancy/tenants`、`PUT /api/tenancy/tenants/{id}` 由本任务交付（R85）。S1-TEN-001 只交付了 `ITenantDirectory` 内部 API（`CreateAsync` / `UpdateAsync` 为 `internal`，id 由服务端生成，`CreateTenant` / `UpdateTenant` 请求体拒绝 `tenantId` / `tenant_id` / `id`）与 HTTP 租户边界；运营接口的调用方是没有租户的平台主体，必须走 S1-AZ-003 的超管旁路显式声明并审计，不能由 `TenantRequestBoundary` 回退为租户范围。同一资源上的状态迁移端点归 S1-TEN-002，管理员维护归 S1-TEN-005，设置与配额归 S1-TEN-004。消费方：S1-TEN-005 运营后台页面（列表 / 新建 / 编辑抽屉）与 S1-GW-001 的 E2E 探针路由。

## 验收

- [x] IT：`GET/POST /api/tenancy/tenants`、`PUT /api/tenancy/tenants/{id}` 只对平台主体开放：经 S1-AZ-003 的超管旁路放行并审计 `bypass = superadmin`；未带凭据 401 `UNAUTHENTICATED`；租户主体的有效令牌 403 `AUTHZ_DENIED`，不经 `TenantRequestBoundary` 回退为租户范围
- [x] IT（R85，承接 S1-TEN-001 验收第 4 条后半句）：目标租户只来自资源路径——`PUT` 请求体含 `tenantId` / `tenant_id` / `id` 返回 400 且不写入（码按 `UseQianErrors` 对请求体反序列化失败的既定映射）；`POST` 的 id 由服务端生成并在响应返回；路径 id 不存在返回 404 `NOT_FOUND`
- [x] IT：`PUT` 以 `expectedRevision` 做乐观并发，过期版本返回 409 `CONFLICT`；租户号与隔离策略不可经编辑修改（复用 `UpdateTenant` 契约，不出现第二套 DTO）
- [x] 契约：三个端点进入组件 OpenAPI 契约并经 S1-RT-006 的契约准入；`inputSchema` 不出现 `tenantId`（S1-RT-020 `tenant-field` 规则）；`packages/Qian.Tenancy/README.md`「验证与剩余验收」改写为已发布，S1-GW-001 的 E2E 探针路由以此为准
