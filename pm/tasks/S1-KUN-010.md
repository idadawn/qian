## 背景

组件规格 §6.1 与 ADR-019 D19.2 要求 Definition 包仅依赖 `Kun.*.Abstractions`，但 Kun 的稳定事件标记 `IntegrationEventIdAttribute` 与事件注册端口在 `Kun.EventBus` 包里，没有 `.Abstractions` 拆分，`Qian.Identity.Abstractions` 只能直接引用它，传递带入 StackExchange.Redis 等实现依赖（S1-IDP-001，S1-DEC-013 R64）。`scripts/check_deps.py` 的 `role_of()` 把非 `qian.` 包一律归 external 放行，所以这条规则目前没有门禁；同类现状还有 `Qian.Data.Abstractions` 直接依赖 `Kun.EntityFrameworkCore` / `Kun.MultiTenancy.EntityFrameworkCore`。

## 验收

- [ ] 上游：Kun 拆出 `Kun.EventBus.Abstractions`（`IntegrationEventIdAttribute`、`IIntegrationEvent`、带 `JsonTypeInfo` 的事件注册端口），`Kun.EventBus` 依赖它；随下一次 Kun 发版
- [ ] Qian：`Qian.Identity.Abstractions` 改引 `Kun.EventBus.Abstractions`，`DefinitionReferencesOnlyRuntimeAndFrameworkEventPort` 的期望值同步，包 README 的延期项移除
- [ ] 门禁：`check_deps.py` 对 `definition` 角色的 Kun 直接依赖只放行 `Kun.*.Abstractions` 与显式白名单（`Qian.Data.Abstractions` 的两项要么迁移要么登记理由），`tests/gates` 加正反例
