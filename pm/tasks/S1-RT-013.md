## 背景

代码部分子命令：`pack` 产出 OCI 制品（代码、`plugin.json` 快照、文件摘要、SBOM、Kustomize 片段、YARP 路由片段、OpenAPI、事件 Schema、AsyncAPI），`sign` 调 cosign / Ed25519，`publish` 推 Harbor 并在注册表登记 `Submitted`；声明式表面不进 OCI。`qian dev` 以 Aspire AppHost 拉起 PG / Redis / RabbitMQ / Apollo 容器与 `standalone` profile 宿主。

## 验收

- [ ] 发布前契约门（R114 / S1-DEC-025）：首次发布 qian.tenancy 前确认 TEN-008/TEN-011 已一次收口全部服务端校验约束，发布快照与真实端点一致且边界拒绝测试通过；核对当前平台契约仓库不存在旧基线。若 publish / 发布链已跑过或已有基线，任何 v1 收窄走 v2 与 R33 别名、Deprecation、successor-version Link，不能覆盖旧基线。

- [ ] E2E：`qian dev` 一条命令拉起 PG / Redis / RabbitMQ / Apollo 容器与 `standalone` profile 宿主，开发者 10 分钟内看到参考应用登录页
- [ ] IT：`pack` 产物含 `plugin.json` 快照、SBOM、Kustomize 与路由片段、OpenAPI / 事件 Schema / AsyncAPI；`publish` 只接受 `@sha256:` digest 并在注册表登记
- [ ] 检查：Harbor 中存在参考应用的插件包 OCI artifact，`qian publish` 以 digest 登记进注册表
- [ ] IT：未 `sign` 的制品 `publish` 被拒绝
- [ ] IT（R89，自 S1-RT-005 移交）：`qian.lifecycle` 的 `Install` 对 OCI 制品做 cosign 验签：未签名、签名不匹配、签名者不在信任根均安装失败且不登记制品；Ed25519 的载荷与 KeyId 约定与 `qian sign` 一致
