## 背景

S1-QA-021 第 2 条（PR #284，已合入 389f33b364）把 `Qian.Scheduler.Tests` 从分片 a 换进分片 b（与 Sample.Crm、Registry、Files 同分片、一开始就跑）。换进后第三次运行、main 运行 40216295478 红了：分片 b 落在慢 runner（测试步骤之前 176 秒，快 runner 111–116 秒），`SchedulerTakeoverTests.真杀执行副本_到期后另一副本用同run接管_副作用幂等与执行尝试分别计数("effect-then-hold", 1)` 在 `SchedulerTakeoverTests.cs:28` 等「首次尝试出现」的 10 秒超时。证据文件 `scheduler-effect-then-hold-failure.json`（构件 test-results-b/evidence）的时间线：

- 17:28:15.80 三个 worker 就绪，15.89 调度（到期 16.80）；
- 领取约 17.0（领取语句 `lease_until=now()+6 秒`，由后来的接管时刻反推）；run 行 `started_at` 20.46（`SchedulerWorker.BeginAsync` 准备完成时的应用时钟），attempts 1、generation 1、worker 7684…；
- 约 23.0 第二个 worker 领走（triggers 行 generation 2、lease_owner 47e8…、lease_until 29.02）：原 worker 的 6 秒租约在准备阶段耗尽，心跳（`ExecuteAsync` 里在 `BeginAsync` 之后才启动，间隔 LeaseSeconds / 3 = 2 秒）没来得及续；
- 25.96 失败时 `sch_probe_attempts` 仍为空：两个 worker 都没进入处理器；三个 worker 进程都活着、stderr 为空，PostgreSQL 无未授予锁。
- 同一运行分片 b 的其他模块也慢：Sample.Crm 224.2、Scheduler 175.5、Registry 153.5 秒；前一次 main 40215523908（也是慢 runner）b 的 CRM 220.2、Scheduler 204.9、Registry 145.9 秒，都高于换前区间上限（187 / 169 / 126）。
- 换前（Scheduler 在 14 个模块的分片 a 里，通常晚 27–108 秒开跑）7 次运行该模块全绿：main 40211664083 / 40212216918 / 40213012218、PR 40195434001 / 40196309275 等。S1-QA-022 的拆类并行让四个主题类同时起 7–9 个 worker 进程与四个 PostgreSQL 容器（本次夹具创建用了 19.5 秒），模块开跑瞬间的 CPU 突发比拆类前大。

产品负责人 2026-10-26 裁定（R140）：SHARDS 回退到换前布局，S1-QA-021 第 2 条留 review、配平待本任务与 S1-QA-019 的 runner 分组数据后重做；本任务查清时序余量并给出修法。

产品代码事实（`packages/Qian.Scheduler/SchedulerWorker.cs`）：领取是一条 `UPDATE … lease_until=now()+@lease` 语句；`ExecuteAsync` 先 `BeginAsync`（建 / 更新 run 行、写 `StartedAt`）再启动心跳；测试宿主 `HostConfig.LeaseSeconds = 6`（产品缺省 30、允许 3–3600）；`首次建run准备后初始续租` 三条用例已覆盖「准备阶段租约过期则不进入第一轮处理器」的既定语义。

## 验收

- [ ] 复现与归因：本机或限 CPU 容器（`mcr.microsoft.com/dotnet/sdk:10.0 --cpus=1/2`）复现「领取后处理器超过 5 秒未进入、租约在准备阶段被接管」，给出领取、`BeginAsync` 完成、首次心跳、接管四个时刻与 CPU 争用证据；分清 Scheduler 自身并行（四类同时起 worker 与容器）与分片邻居（同时起宿主的重模块）各自的贡献
- [ ] 测试侧修法：不削弱断言（接管语义、attempts / effects 计数、「尚未接管」快照）且用例数不少的前提下，让 Takeover / Renewal 用例在慢 runner 上稳定——候选：调度前让 worker 真正预热（首个领取循环已跑过）、首次尝试等待与租约按比例而非写死 10 秒、错开四个主题类起进程的时刻；改法写进 `tests/README.md`「调度验收的用例写法」
- [ ] 产品侧评估：初始租约从领取的 `now()` 起算、心跳在 `BeginAsync` 之后才启动，准备阶段耗时超过 LeaseSeconds − 续租间隔即被接管——是否符合设计写明结论；若要改（如 `BeginAsync` 内先续一次、或初始租约单独配置），说明对生产的影响，生产缺省值不变并单独验证
- [ ] 分片放置依据：给出 Scheduler 适合的分片条件（开跑时同分片起宿主的模块数、是否能一开始就跑）与 runner 分组后的数据，交 S1-QA-021 第 2 条 / S1-QA-019 重做配平
- [ ] 门禁：修复合入后 main 连续 5 次（不含取消）`Qian.Scheduler.Tests` 全过且首尾跨度 ≤ 250 秒；`pm.py validate` 通过
