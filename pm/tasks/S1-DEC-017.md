## 背景

DATA-001 / PRD §7.6 要求“数据库超级用户直连”仍被 RLS 拒绝，和 PostgreSQL 16 的角色边界冲突。超级用户及 BYPASSRLS 角色始终绕过行安全；FORCE RLS 约束表所有者，但不能约束超级用户。仓库 `tests/README.md` 与 `packages/Qian.Data/AGENTS.md` 已规定使用受限应用角色验证 RLS。

另有会话名漂移：PRD 旧例写 `app.tenant_id`，组件规格旧例写 `qian.tenant_id`；已发布 Kun 2026.10.9 的双拦截器及既有 Qian 数据测试实际使用 `app.current_tenant_id`，租户标识为字符串。

建议：管理员连接仅建表和造数；RLS 正向验收通过 NOSUPERUSER / NOBYPASSRLS 的应用角色直接执行原生 SQL，验证跨租户读不可见与 WITH CHECK 拒绝写；增加超级用户可以绕过的对照，在线应用拒用超级用户或 BYPASSRLS 角色。SQL 策略与文档统一到现有 Kun 会话契约，不额外引入第二个租户会话变量。

依据：[PostgreSQL 16 行安全文档](https://www.postgresql.org/docs/16/ddl-rowsecurity.html)、`tests/Qian.Testing.Containers/PostgresFixture.cs`、`tests/Qian.Data.Tests/DataSafetyTests.cs` 与 Kun `TenantRlsConnectionInterceptor` / `TenantRlsTransactionInterceptor`。

## 验收

- [ ] 产品负责人确认按受限应用角色验收，并保留超级用户绕过的对照
- [ ] DATA-001、PRD、ADR/规格和实现统一既有租户会话名，禁止混用第二变量
- [ ] PostgreSQL 16 真库验证角色属性、FORCE RLS、WITH CHECK 与缺租户时拒绝访问
