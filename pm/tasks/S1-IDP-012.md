## 背景

S1-DEC-027 Q1 选 C。S1-AZ-009 先让同进程宿主闭环：授权组件提交后直接调身份端口。S1 默认拓扑里 `platform`（授权）与 `identity`（身份服务）是两个独立 Pod，这条路径够不着身份服务，所以 R7 在拆分部署下的闭环由本任务在 S1-EVT-002（消费端）之后承接：

- 身份侧订阅 `authz.grant.changed.v1`，在信封租户的作用域内对 user 主体调 `BumpIdentityRevisionAsync`。判据与 S1-AZ-009 一致：非 user、非 GUID、无成员身份跳过，`authz.role.changed.v1` 不扇出。
- 同进程宿主不登记该订阅，免得与授权组件的直接调用重复递增。
- 拆分部署下授权侧拿不到端口返回值，PEP 修订下限怎么同步（Q5）由本任务定：身份侧递增后发事件、授权订阅后抬高，或维持懒抬高。
- R123（S1-EVT-002 复核移交）：S1-IDP-004 日志交给 S1-EVT-002 的身份会话 handler（`TenantSuspendedSessionHandler` / `TenantExpiredSessionHandler`）订阅投递接线没有交付：`AddQianIdentitySessionHandlers` 挂在 Kun 事件总线构建器上，不经 Qian.Events 订阅器。改由本任务与 `authz.grant.changed.v1` 订阅一并承接；接线前，租户冻结 / 到期靠会话校验读租户目录与后台对账兜底。

## 验收

- [ ] IT：platform 与 identity 分属两个宿主，撤销授予后经 RabbitMQ 投递，≤ 3 秒内递增 identity_revision；旧令牌在 userinfo 被拒，refresh 拿到新修订
- [ ] 拆分部署下 PEP 修订下限的同步方式定稿并实现：旧令牌在 PEP 侧的拒绝时效写明；若维持懒抬高，PRD 7.5 与 ADR-006 D6.7 同步改口径
- [ ] IT：同一事件重投不重复递增（消费端幂等）；同进程宿主不登记订阅，一次授权变更只递增一次
- [ ] IT（R123，自 S1-EVT-002 复核移交）：身份侧经 Qian.Events 订阅 `tenant.suspended.v1` / `tenant.expired.v1`，投递后该租户的会话即时吊销、refresh 被拒；同进程宿主与拆分部署各只登记一次；Identity.Server README 中「订阅投递由消费端接线，在此之前靠后台对账兜底」的说法同步
