## 背景

S1-AGT-002 的输入 Schema 租户字段检查（Qian.Surfaces 语义校验、@qian/surfaces、Qian.Capabilities 的 TenantInputContract）只看 properties 的属性名：只出现在 required、dependentRequired、dependentSchemas 里的租户名，以及能匹配租户名的 patternProperties 都不拦，顶层的 patternProperties 与 required 也绕过 tool Schema 的 propertyNames。三处的遍历也不一致：表面校验把示例、默认值里的数据当 Schema 检查，能力契约跳过名为 default、enum 的属性的子 Schema；.NET 表面校验的 $ 还会把 tenant 后接换行算成租户名。

## 验收

- [x] 规则：名称按 contracts/v0 的 `TenantFieldName` 整体匹配（tenant、tenantId、tenant_id、tenant-id 的 ASCII 大小写变体）；`properties`、`dependentSchemas`、`dependentRequired`（及旧式 `dependencies`）的名称与 `required`、`dependentRequired` 的数组项点名租户字段即拒绝；`patternProperties` 的模式按 ECMA-262 可移植子集（`SchemaPattern`）能匹配任一租户名、或超出子集无法判定，同样拒绝；顶层也适用
- [x] 三处同一规则、同一遍历：示例、默认值、常量等实例数据不当 Schema 检查，名称表（`properties`、`$defs` 等）里叫 `default`、`enum` 的条目照常检查。Qian.Surfaces 与 @qian/surfaces 为 `SURFACE_POLICY_DENIED`，pointer 指向名称、数组项或模式本身；Qian.Capabilities 的 `TenantInputContract` 返回同一位置段（能力编译为 `tenant-field`）；.NET 两处共用 `packages/Common` 的同一份源文件
- [x] TCK：新用例只经 `scripts/generate_surface_fixtures.py` 生成，两端校验器各跑一遍后 `compare-fixtures` 全部一致，README 计数同步；`TenantFieldInstallTests` 名单逐个更新，反例经 `InstallAsync` 一律 INPUT_INVALID 并带 fixture 的 pointer
- [x] UT：`TenantInputContract` 与能力编译覆盖新写法、名为 `default` / `enum` 的属性、实例数据不误报
- [x] 需要人拍板的部分（嵌套 object 是否必须关闭、`propertyNames` 的角色）记为建议裁决，本任务不实现
