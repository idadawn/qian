## 背景

三个独立组件 `qian.notify.channel.inbox / .smtp / .sms`（`Qian.Notify.Channel.Inbox` / `.Email` / `.Sms`，只依赖 `Qian.Notify.Abstractions`）：站内信（`inbox_messages`、已读 / 回执 / 深链、`GET /api/notify/inbox`、`POST /inbox/{id}:read`，有实时通道时推角标、否则 30s 轮询）、邮件（唯一默认账号）、短信（阿里云 / 腾讯云 Provider 先接一家，签名与模板码配置，`+86` 默认国家码可配，模板同步 P1）；平台级启停走 profile patch、租户级 = scope 挂载；系统预置模板不可删；「系统公告」消息类型 S1 可发。短信为 7.4 OTP 与找回密码的前提。

## 验收

- [ ] E2E：7.4 的短信 OTP 经 `sms` Provider 发出并在 staging 收到短信（供应商测试账号）；国家码可配为非 `+86`
- [ ] E2E：站内信产生后外壳 ≤ 3s 收到未读角标更新（经 7.13.2；降级为 30s 轮询）
- [ ] IT：租户 A scope 未挂载 `sms` 渠道组件时，A 的发送配置里不出现短信渠道，强行指定返回与「渠道不存在」相同的错误；经 scope patch 挂载后无需重启即可用
- [ ] UT：系统预置模板删除被拒；渠道凭据只以 secretRef 出现
