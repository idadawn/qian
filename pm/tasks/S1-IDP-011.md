## 背景

S1-DEC-020 选定方案 A：身份事件 v1 尚无生产方、消费方与已发布包，就地删除五类载荷里重复信封的 `event_id`、`occurred_at`、`tenant_id`，`IdentityIntegrationEvent` 不再实现 Kun 的 `IIntegrationEvent`；三项只由 Qian.Events 写入端生成在信封上，消费端从信封取。「破坏性变化升 v2」自首个发布版本起生效。

## 验收

- [ ] UT：五类身份事件载荷与 Schema 都不含 `event_id`、`occurred_at`、`tenant_id`，Schema 成员与源生成 JSON 属性一致，`IdentityIntegrationEvent` 不实现 `IIntegrationEvent`，通过 PublicAPI 分析器
- [ ] UT：经 Qian.Events 写入端发布的身份事件，三项只出现在信封上：event_id、occurred_at 由写入端生成，tenant_id 取当前租户，平台级事件为 null
- [ ] 文档：ADR-008、contracts/identity/v1/README.md 与包 README / AGENTS.md 记载 S1-DEC-020 结论
