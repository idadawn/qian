## 背景

组件 `qian.notify`（`Qian.Notify.Abstractions` / `ctx.Notify` + `Qian.Notify`）：消息类型由清单 `contributes: qian.notify.message-type/v1` 注册（编码、参数 Schema、模板变量、落地深链）；`message_types` / `notify_templates`（每模板一渠道、`{@字段}`）/ `send_configs` / `send_config_templates` / `receive_configs`（admin 默认 / 锁定）/ `channel_accounts`（配置 + `secretRef`）；`INotifier.SendAsync(configCode, recipients, params, idempotencyKey)`；`INotificationChannel` typed port；判定链（场景未开启不生成 → 接收配置过滤 → 模板必须启用 → 被引用模板不可删）；`GET /api/notify/send-configs`、`POST /send-configs/{code}:validate`、`POST /api/notify/send`；收件人寻址经 7.4.3 目录。

## 验收

- [ ] IT：同一 `idempotencyKey` 的两次 `send` 只产生一次投递
- [ ] IT：删除被发送配置引用的模板返回结构化错误；渠道账号详情接口不含明文密钥
- [ ] UT：`GET /api/notify/send-configs` 返回每个配置的参数 JSON Schema；`:validate` 对缺参返回带 JSON Pointer 的错误
- [ ] UT：收件人在接收配置里关闭某渠道时该渠道记录被跳过；全部过滤则不生成监控
