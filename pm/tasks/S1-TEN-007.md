## 背景

S1-DEC-023 的最小权限方案已随 PR #147 落地并经复核（claude，2026-10-16，R104）成立；复核发现的缺口汇到本任务。`initializationCapabilities` 目前在部署层无法生效：`TenancyPlugin.ApplyAsync` 对 `initializationCapabilities` 之外的任何配置键一律 `INPUT_INVALID`，而 `plugins/qian.bundle.base/config/qian.patch.yml` 的 tenancy 全局条目带 `resolver`，参考宿主挂载 `TenancyPlugin` 的 config 是 `{}`，仓库里只有测试通过卸载再重挂载配置过清单，`docs/generated/config-catalog.md` 展示的「生效配置」按现实现会 Apply 失败。DEC-023 专项负例只有 2 个用例（任务日志的「27/27」是 Qian.Authz.Abstractions.Tests 的项目总数），缺配置校验（通配符 / 缺 `/` / 重复 / 非数组）、destructive / external 能力进清单后在消费时被拒、清单已配置但由非编排方派发 `tenant/provisioned` 命中同一 hook、Grant 打开期间的并发复用与嵌套 Begin、`POST /api/tenancy/tenants` 端到端触发初始化 hook 并审计已认证超管等负例。`plugins/qian.tenancy/.qian-plugin/plugin.json` 声明 `scopes: [global, tenant]`，而 Apply 只接受 global。文档措辞：Tenancy README 的「短期凭据」（实现无超时，寿命等于派发作用域）、Plugin.Sdk README 的「保留 Kun 权限行为与三项策略」（判定由凭据给出、不查 RBAC）、Authz.Abstractions README 的可见名单漏测试程序集；`InternalsVisibleTo` 含 `Qian.Authz.Abstractions.Tests` 且无强名签名；`AuthorizedHandlerRegistration` 依赖 Kun `AddPermissionBehavior` 最后一个描述符是工厂注册，只断言工厂非空；同一能力被两组 hooks 引用时第二次 Enter 以同一个 `AUTHZ_DENIED` 拒绝、重试永远失败；AuthzPlugin 建内置角色与组件 hook 同为 serial 监听器、顺序只靠挂载拓扑。

- [ ] IT：`qian.bundle.base` 的 tenancy 全局条目同时带 `resolver` 与 `initializationCapabilities` 时 `TenancyPlugin.ApplyAsync` 通过并生效；参考宿主的挂载配置与 `docs/generated/config-catalog.md` 的生效配置都能被 Apply 接受；`plugins/qian.tenancy/.qian-plugin/plugin.json` 的 `scopes` 与 Apply 只接受 global 一致
