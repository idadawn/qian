## 背景

本机多个会话并发跑 Testcontainers 时，偶发整个测试类以 0ms 失败。报错是 `Class fixture type 'Qian.Testing.Containers.PostgresFixture' threw in InitializeAsync`，内层为 `ResourceReaperException: Initialization has been cancelled.`。

已记录三次，原样重跑都通过：

- Qian.Data.Tests 的 MigrationCoordinationTests；
- Qian.Events.Tests 的 OutboxRelayTests；
- Qian.Authz.Tests 的 PermissionCatalogPersistenceTests。

根因：

- Testcontainers 4.15.0 在每个测试进程第一次启动容器时初始化 Ryuk（资源回收容器）；等待连接确认的超时写死为 60 秒，宿主繁忙时会耗尽，这次启动随即失败。
- 失败的 Ryuk 实例不缓存，下一次启动会重新初始化。
- ContainerFixture 只在容器就绪前自行退出（ContainerNotRunningException）时重建，缺省还只试 1 次。所以哪个夹具碰巧触发了 Ryuk 初始化，哪个测试类就整类失败。

2026-10-16 建档后，本机三个会话同时跑全量，又出现第二种同类失败：Docker 守护进程在 Docker 客户端的请求超时内没有响应。CreateContainer 超时 161 次、StartContainer 超时 34 次，195 个用例在夹具启动时以 `TaskCanceledException` 失败，内层为 `HttpRequestException`。这同样是宿主繁忙造成的环境类瞬时失败，一并纳入本任务。

## 验收

- [ ] ContainerFixture 把 Ryuk 初始化失败与 Docker API 请求超时视为瞬时失败，所有夹具都重试，最多 3 次：
  - 每次重试前，先释放本次启动拿到的全部资源，含 OnStartingAsync 准备的依赖容器与网络；
  - 按次数线性退避，然后从头启动；
  - 每次重试发一条诊断消息；
  - 用尽次数后，抛出最后一次的原始异常。
- [ ] 其他失败的处理不变：
  - 容器在就绪前自行退出，仍按各夹具的 StartAttempts 处理（K3s 3 次，其余 1 次）；
  - 其他错误不重试，如镜像、配置错误；Docker 不可用仍按 DockerRequirement 处理；不是 Docker API 请求被取消的其他取消也不重试；
  - 测试已取消时不再重试。
- [ ] UT（用假容器，不需要 Docker）：
  - 前两次 Ryuk 初始化失败、第三次成功时，夹具可用，失败的两次都已释放；
  - Docker API 请求超时同样从头重来；
  - OnStartingAsync 里出现的同类失败，同样从头重来；
  - 一直失败时共尝试 3 次，抛出原始异常；
  - 非瞬时错误只尝试 1 次；
  - 测试取消后不再重试；
  - 未声明 StartAttempts 的夹具，容器提前退出时不重试。
