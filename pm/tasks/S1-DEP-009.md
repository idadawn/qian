## 背景

S1-YUE-012 的裁决 ②（产品负责人 2026-10-24 选推荐项 A）：面向用户主体的平台表面在生产里由 platform profile 的平台宿主提供（qian-platform 镜像），本任务交付这个宿主。

这类表面是能力目录、导航、外壳目录（`MapQianCapabilities`，含 `GET /api/capabilities/shell` 与能力执行入口）与有效权限（`MapQianAuthz`）。网关路由表把 `/api/capabilities/**`、`/api/authz/**` 分簇给它（受众 `qian-platform`），外壳 bootstrap 聚合端点（Qian.Gateway 的 `MapQianShellBootstrap`）的三条下游随之。没有这个宿主时，生产外壳的 bootstrap 只能拿到空目录与空权限。

现状：

- `hosts/` 只有 `Qian.Gateway.Host`，没有平台宿主。
- 联调环境与集成测试用的是参考宿主 `samples/Qian.Sample.Crm/PlatformSurfaceHost.cs`。它只认网关 S2S（完整 issuer / 受众 / 有效期 / 签名校验，只接受 RS256），接受 user / service / agent 主体，主体快照取自令牌，按令牌 `tenant_id` 进租户 scope；平台身份没有租户表面；授权 PEP 按生产模式装配，处理器内判定的端点也比对身份修订下限。
- 平台运营端点（`TenantOperationsHost` 的 `MapQianTenancy`）同样走受众 `qian-platform`。两类表面合进同一个平台宿主还是分开，开工时先定。

用户主体执行应用能力（S1-YUE-015 裁决 ④）：参考栈里平台表面宿主把验证过的主体交给参考应用的身份适配器，经通用执行入口调用的 `module` 应用能力以调用者本人执行。生产里 `module` 应用随 platform 镜像发布、与本宿主同进程，解析同一个身份适配器，本任务补同一条验收。装配时注意：先登记数据组件（如身份库）再登记安全组件时，Kun 数据约定的匿名兜底会以 `TryAdd` 抢先占住框架当前主体端口（Kun `ICurrentUser`），命令管道随之对一切能力执行判拒（403 `AUTHZ_DENIED`），参考宿主的处理见 `samples/Qian.Sample.Crm/CrmCommandApplication.cs`。

## 验收

- [ ] 生产宿主入口经 platform profile 装配平台插件树（Data / Tenancy / Authz / Audit / Config / Registry / Capabilities / Lifecycle），运行期连接只用受限角色
- [ ] 只接受网关 S2S：错误 issuer、受众、过期、非 RS256 一律 401，不接受浏览器 Cookie 或外部访问令牌；平台身份访问租户表面 401
- [ ] IT：生产网关配置加本宿主跑外壳 bootstrap，与参考宿主同一契约（匿名 401、成员结果与导航 / 有效权限一致、平台身份代管、未挂载组件不出现、旧修订 401 换令牌后恢复、响应不含令牌）
- [ ] IT（S1-YUE-015 裁决 ④）：user 经网关与本宿主的通用执行入口执行 `module` 应用能力，以本人执行：命令 PEP 按其角色判定并记放行决策，写类能力的审计记 `actor_type = user`、主体为 person_id、通道 `api`；只读成员执行写类能力 404 且无写入，另一租户看不到，带 `act` 的令牌被拒
- [ ] qian-platform 镜像带本宿主，随 S1-DEP-008 的供应链检查（digest、签名、SBOM、非 root、只读根文件系统）
- [ ] 联调环境与集成测试改用本宿主，或在 README 写明参考宿主与它的差异
