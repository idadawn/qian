## 背景

S1-YUE-015 验收复核（R132 ②）发现的测试强度缺口：参考应用身份适配器的纵深防御各层只被 ShellInvokeTests 整体测到——删掉 IsAuthenticated 里 `_current.UserId == snapshot.Subject` 或 `_current.PrincipalKind == KindName(snapshot.Kind)`、删掉 `entry.PlatformSurface` 来源标志、AcceptPlatformSurface 去掉 Service，全部用例照过；AcceptPlatformSurface 对 user / service / agent 都交快照，service 主体（外部机器客户端带 Bearer 经网关 `/api/capabilities/**`）经平台表面执行成为只靠 RBAC + scope 门禁的新入口却没有用例；真实流程 E2E 第 4 步「多了这一条」以列表一页 100 条（按 Id 升序）为界，`notified` 的监听没有 await 就点击。现有行为维持、与 README 一致，是否收窄到只收 user 由本任务的 IT 结果再议。

## 验收

- [ ] CrmCurrentUser 单测（`samples/Qian.Sample.Crm` 已开 InternalsVisibleTo）：用 DefaultHttpContext 建已认证主体，分别经 AcceptPlatformSurface 交进 Subject 不同、Kind 不同、带 Actor 的快照，各自 `IsAuthenticated == false`；对已验证的 user 令牌调 Capture 结果失败；能杀掉删 Subject 比对、删 Kind 比对、删 act 检查三类回退
- [ ] IT：service 主体（在甲方有角色授权）经平台表面通用执行入口执行 customer.list 200，决策与审计 actor_type = service；agent 404；或经产品负责人裁决收窄 AcceptPlatformSurface 只收 user 并同步 README 与参考宿主注释
- [ ] ShellInvokeTests 加强：act 的对照改用 create 或断言手工令牌下 customer.create 可见；补 user 令牌直调 `POST /api/customers` 401；用只属于乙方的用户做隔离断言；任务日志补记镜像等价突变（删 `&& entry.PlatformSurface`）与 M5 还依赖 IsAuthenticated 的 act 检查
- [ ] `apps/qian-shell/e2e-auth/auth.spec.ts`：`notified` 先 await 挂好监听再点击；「同一联调栈可反复跑」的注释注明以 take=100 为界，或改按名字查询
