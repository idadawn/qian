## 背景

R130 ②（产品负责人 2026-10-24）认可外壳 CSP 的 'unsafe-eval' 为已登记例外：@idadawn/yue-form 的 SchemaForm 在运行期用 Ajv 编译表单 Schema（低代码表单的 Schema 来自运行期，无法预编译），经共享依赖在外壳源执行；由跟进会话把 yue-form 改成解释型校验后去掉。本任务分两段：第一段从 main 开，把 Ajv 换成不生成代码的解释型子集校验并加静态检查；第二段等 S1-YUE-012（#259）合入后撤销外壳 CSP 的 'unsafe-eval'。

## 验收

- [ ] 列出 SchemaForm 实际用到的 Schema 关键字（表单数据 Schema 与 form / list / widget 元数据 Schema），解释型校验覆盖这一子集：判定、错误顺序与错误对象（instancePath、schemaPath、keyword、params、message）与此前的 Ajv 2020（allErrors、strict: false、ajv-formats full）逐条一致，差分测试覆盖仓库内全部表单数据 Schema 与三份元数据 Schema
- [ ] 子集外的关键字、格式与引用在 `assertFormSchema` 时拒绝（`form.error.unsupportedKeyword`），参数不合法拒绝（`form.error.schema`），不静默放过；`validateValues` / `validateMetadata` 的公开签名与错误呈现（字段定位、必填 / 不合法文案、首错聚焦）不变
- [ ] 静态检查钉住 yue-form 的运行时路径：源码不含 Ajv 导入、`require(`、`new Function` / `Function(`、`eval(` 与字符串定时器，`package.json` 的 dependencies 不含 ajv / ajv-formats（照 `packages/qian-plugin-sdk/test/parameters.test.ts` 的写法）
- [ ] 外壳 meta CSP 撤销 `'unsafe-eval'`：`apps/qian-shell/vite.config.ts` 的 `CSP_DIRECTIVES` 与注释、`scripts/verify-dist.mjs` 的已登记例外、门禁自测 `tests/gates/yue/shell-dist.test.ts`、`apps/qian-shell/README.md`（安全策略与已知限制）、`packages/qian-plugin-sdk/README.md`「校验不在运行期生成代码」一节同步（等 S1-YUE-012 / #259 合入 main）
- [ ] `pnpm yue:gates`（其中 `yue:mf` 的租户运营远程页面用到 SchemaForm，全程零 CSP 违规）与 `pnpm yue:auth` 全过
- [ ] yue-form 加 changeset；突变逐条记入日志（改了什么 → 哪个用例哪一行失败）
