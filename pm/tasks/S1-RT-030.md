## 背景

S1-RT-011 合并后复核发现：qian add 的包管理器子进程超时写死 120 秒，预检还原又带 --disable-parallel 逐个下载；冷 NuGet 缓存加私有源下载偏慢时，预检还原超时，add 报 UNAVAILABLE。2026-10-15 在 main 5665b31e4 上本机跑 private-feed.e2e.mjs，连续两次约 121 秒失败，预热缓存后 22.9 秒通过，CI 约 1 分钟通过。

## 验收

- [x] UT：包管理器操作的超时由环境变量 `QIAN_PACKAGE_TIMEOUT`（整数秒）配置，缺省 600 秒；非整数、小于 1 或大于 86400 时，`qian add` / `qian remove` 在任何改动前以结构化错误（`--json`）失败
- [x] UT：用真实子进程验证超时：在配置的秒数内停止整个进程组，诊断写明超时秒数与配置方式；未确认停止时仍保留安装锁与备份（既有语义不变）
- [x] IT：预检还原不再逐个下载（去掉 `--disable-parallel`，与安装阶段的还原一致）；私有源 E2E 在全新的 NuGet HTTP 缓存下通过并记录耗时
- [x] 文档：qian-cli 的 README 与 AGENTS 写明超时配置、默认值与预检并行
