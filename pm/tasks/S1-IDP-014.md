## 背景

S1-IDP-005 交付了依赖方包 `Qian.Identity.Client`，组件文件夹 `plugins/qian.identity.client` 却只能保留 `x-skeleton`、不声明 `runtime`：gateway profile 是 `build.aot: true`，装载器（`packages/Qian.Profiles/ProfileLoader.cs`）要求其中声明了 `runtime` 的代码组件带 `x-aot: true`，而 Kun.Identity / Kun.Identity.AspNetCore / Kun.Security 发布包没有 AOT 兼容元数据（成因是 Kun 的构建缺陷，见 S1-KUN-015），所以 `qian add identity` 还用不了。2026-10-22 冒烟实测：只引用 `Qian.Identity.Client` 的 PublishAot 宿主经 ILC 发布为 0 条 IL 警告，原生二进制能挂载组件并响应端点。产品负责人认可的方案：身份组件以 Qian 侧 CI 的 NativeAOT 冒烟为依据声明 `x-aot`；判断兼容性看 ILC 结果，不看包元数据。网关整体能否保持 AOT（配置组件的 Kun `AddKunOptions` 标了 RequiresDynamicCode、审计组件依赖 EF Core）归 S1-GW-001；组合验收 `qian add identity authz files` 仍归 S1-QA-005（R84）。

## 验收

- [ ] CI：冒烟宿主 `tools/Qian.Identity.Client.AotSmoke` 以 `IlcTreatWarningsAsErrors=true`、`TrimmerSingleWarn=false` 发布 linux-x64 NativeAOT，ILC 0 条 IL 警告；原生二进制启动后挂载 `IdentityClientPlugin`，端点冒烟通过（`/auth/login` 回 502 ErrorDetail、`/auth/csrf` 回 401、无会话登出回 204）
- [ ] 包：`Qian.Identity.Client` 声明 `IsAotCompatible`，裁剪与 AOT 分析器 0 警告
- [ ] 清单：`IdentityClientPlugin` 带 `[QianPlugin("qian.identity.client")]`，经 `Qian.Plugin.Tool sync` 写入 `runtime.form` / `runtime.entry` 与 `provides`，清单加 `x-aot: true`；CI 漂移检查与 Data / Events / Config 一致；gateway profile 校验通过，其中 identity 条目声明了 `runtime` 与 `x-aot`
- [ ] 发布：从 main 锁步发布新版本到私有源，`runtime.nuget` 钉版本与归档摘要（同 S1-RT-011），去掉 `x-skeleton`，`qian add identity` 从私有源真实安装；`plugins/qian.identity.client/README.md` 第四问与包 README「已知限制」同步
