## 背景

S1-RT-011 四条验收成立、done 维持；复核（claude，2026-10-16，裁决 R98–R100）发现的实质缺口汇到本任务。`qian remove` 到最后一个组件后，CLI 用 `dotnet restore --use-lock-file` 生成的空 `packages.lock.json` 留在宿主里，让宿主此后进入锁文件模式（R99 判为 add 对宿主的持久改动）；`source.url` / `repo` 的查询串不受检查，签名市场里 `?token=…` 一类地址会被接受并原样写进必须提交的 `.qian/lock.json`（登记市场时 `marketplaces.ts` 已拒绝带凭据的地址，两处不对称）；CLI 侧验签失败、条目 digest 不符、残留锁、手工改写、profile 不允许几乎都报同一个 `SURFACE_POLICY_DENIED`，`@qian/surfaces` 已定义的 `SURFACE_HASH_MISMATCH` 闲置，`SURFACE_*` 码也没有登记进 `contracts/v0/error-codes.json`（ErrorDetail 的 `Code` 要求登记）；`installFailure` 把本机绝对路径写进诊断的 `file`；进程被杀后 `.qian/.install.lock` 与 prepared 状态的 journal 留下，下次 add / remove 直接拒绝，没有恢复或清理命令；规格 §9.3 第 5 步（安装结束跑 doctor 组件子集、打印 `defaultPrompt` 与下一步）与第 2 步的「engines 与当前 profile 运行时版本比对」未实现；`qian list --outdated / --surfaces` 未实现（后者把参数值当未知参数报错）；`url` / `git-subdir` 来源只有 resolve 级测试、`installation: restricted` 与带代码组件的验签失败回滚没有 CLI 级用例；`dump-config` / `docs generate` 的 `--json` 错误输出是多行缩进，与 add / remove 的一行不一致；NuGet 签名 / npm provenance（规格 §11.5）未做。

## 验收

- [ ] IT：`qian remove` 移除最后一个 CLI 管理的包时删除 CLI 生成的 `packages.lock.json`（或 add 改为不生成锁文件、以 assets 核对），宿主 csproj / patch / 文件集合回到安装前；`.qian/` 工作区与 `.gitignore` 两行按 R99 保留并写进 README；`private-feed.e2e.mjs` 的保留项断言随之更新
- [ ] IT：`source.url` / `repo` 的查询串与市场登记校验同一规则（含 token 类键或凭据即拒绝），`.qian/lock.json` 与 `list` 输出都不含凭据；`installFailure` 的 `file` 只写相对路径；`surfaces.yml` 的 private-feed 作业把构建与测试拆成两步，令牌只给测试步骤
- [ ] UT：验签失败、条目 digest 不符（`SURFACE_HASH_MISMATCH`）、残留锁、手工改写、profile 不允许各用可区分的错误码；`SURFACE_*` 码登记进 `contracts/v0/error-codes.json`；`dump-config` / `docs generate` 的 `--json` 错误输出与 add / remove 同为一行，`add --json` 不再把 profile 级 warning 重复塞进每个组件的 diagnostics
- [ ] IT：进程被杀后 `qian doctor --fix`（或等价子命令）按 journal 回滚残留事务并清除安装锁，之后 add / remove 可继续；用例用真实子进程中断复现
- [ ] IT：安装结束对受影响组件跑 doctor 子集并打印 `defaultPrompt` 与「下一步」（待填 `secretRef`、推荐 profile）；`engines` 与当前 profile 的运行时版本比对；`qian list --outdated / --surfaces` 实现，或从规格 §9.1 删除并说明
- [ ] IT：`url` 与 `git-subdir` 来源走完整 `qian add`（含 lock 内容）、`installation: restricted` 被拒、带代码组件验签失败整批回滚；NuGet 签名 / npm provenance（规格 §11.5）的去向写进 README 并登记任务
