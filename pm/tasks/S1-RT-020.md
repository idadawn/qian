## 验收

- [x] 输入 Schema 装载期拒绝：`CapabilityInputValidator` 在能力登记（`ctx.ProvideCapability` 进入目录）时预编译并缓存校验器，不再在首次调用时编译；`patternProperties` / `dependentSchemas` 键含 `/` 或 `~`、`$id` 内嵌引用无法定位、Schema 无法编译的能力在登记阶段以带插件 ID、能力名与 JSON Pointer 的异常拒绝（风格同 `RegistryScopeApplyException`），通用执行入口不再因此返回 500 `INTERNAL`；单测覆盖上述三类输入，IT 一条「登记被拒且目录不出现该能力」
- [x] 幂等回执上限与分级：组件规格 §9.5 与 `packages/Qian.Capabilities/README.md` 定义回执体上限（建议 64 KiB，经 `plugins/qian.capabilities/schemas/config.schema.json` 可配）与超限行为（建议：超限不存响应体，同键重放返回 409 `CONFLICT` 并在 ErrorDetail 说明不可重放）；新增迁移把 `invoke_receipts.response` 改为有上限，或在写入前执行上限并写明理由；按条目 `dataClassification` 决定是否保存响应体，口径由本任务定并写进规格；IT 覆盖超限与不保存响应体两种重放
- [x] 迁移装配与 RLS 说明：S1-RT-014 验收加一条「platform profile 组合包以 `AddQianData<CapabilitiesDbContext>` 把能力上下文纳入迁移目录，TCK 平台组合包（R68）在真实 PostgreSQL 断言迁移历史与 `pg_policies`」，本任务只登记不实现；`packages/Qian.Data/README.md` 第 18–20 段补上：RLS 与策略由 `QianPostgresMigrationsSqlGenerator` 在迁移执行期生成，迁移必须经 `AddQianData<T>` 登记的 `IDataMigrator` 执行，直接 `dotnet ef database update` 不生成策略、启动检查会拒绝非 Qian 生成器，并给出查 `pg_policies` 的验证 SQL；`docs/ops/configuration-runbook.md` 的部署步骤引用这一段；补 `IDesignTimeDbContextFactory<CapabilitiesDbContext>`（或等价设计时入口），使 `dotnet ef migrations has-pending-model-changes` 可在仓库内复跑
- [x] 测试补强：`CapabilityService` 直接以 Actor 主体调用（绕过端点）被拒绝且处理器不执行的单测；`CapabilityEndpoints.SuccessorLink` 孤立 UTF-16 代理项按 `%EF%BF%BD` 编码的单测，IT 宿主加 `UsePathBase` 用例断言 `Link` 含 PathBase；`catalogTtlMs` 配置非默认值（如 2500）的 IT 断言 `ttlMs`；`schemaSha256` 的独立验证改为用 RFC 8785 正文示例与附录的数字序列化样本直接断言 `Qian.Surfaces.ToolContractHash`，删除 `tests/Qian.Sample.Crm.Tests/CapabilityInvokeTests.cs` 与 `tests/Qian.Runtime.Errors.Tests/Contracts.cs` 里的两份 JCS 复刻，仓库只保留生产实现一份
- [x] 口径与文档：S1-RT-019 验收 2 文字加注「实现为 PG 回执表 `invoke_receipts`，Kun 未改，见 R75 实现说明」；`website/docs/sdk/dotnet/capabilities.md` 通用执行入口一段补 `Idempotency-Key` 请求头、`Idempotent-Replayed` 响应头与 409 语义，与 README 第 45 行一致；buf 输出解析把 stderr 与 stdout 分开记录，stderr 不并入规则行日志；`check_docs.py` 与文档站构建通过
