## 背景

DEP-001 第一项要求真实 qian-platform 可访问 PG / Redis / RabbitMQ / Apollo；DEP-002 的专属 L1 服务和 DEP-003 的平台镜像却都依赖 DEP-001。当前 qian-platform 仍是组合骨架，不能以贴同名标签的探针或已有共享服务冒充验收。

2026-10-11 只读实查另发现 qd 的 API 返回 ServiceUnavailable，K3s activating/start、NRestarts=550；未修改现网。这是独立的环境阻塞，不因下面的验收裁决而消失。

## 待裁决

- 推荐：分阶段验收。DEP-001 在真实集群完成独立命名空间、专属 PG/Redis、默认拒绝、配额、节点池与入口/加密检查后完成基线阶段；把真实 qian-platform 的四依赖协议联调明确保留为后续部署的必过验收，回链 DEP-002/003，不能在上线时跳过。
- 维持原口径：DEP-001 保持 blocked，直到专属 L1 与真实应用镜像均可运行并完成全项验证；后续任务的启动安排由产品负责人决定。

已准备两环境隔离清单、数据服务、只建缺失项的 Secret 引导工具、静态门禁及上线/回退步骤，尚未接入 Argo 或执行集群变更。具体部署仍须现网恢复、容量/节点池确认和变更批准。
