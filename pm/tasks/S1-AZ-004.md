## 背景

ASP.NET Core `[RequirePermission]`、Mediator `AuthorizationBehavior`（读 `[Capability(RequiredPermission=...)]`，作为 base 组合包的 `waterfall` 监听器）、gRPC 拦截器同一入口；端点 → 权限点写进 OpenAPI 扩展 `x-qian-permission`；`decision_logs`（可配采样，拒绝必记）入哈希链；授权变更 → `authz.grant.changed.v1` / `authz.role.changed.v1` → 7.4 递增受影响主体的 `identity_revision` → 7.13 推送刷新。

## 验收

- [x] IT：未声明权限点的端点在 `Production` 模式返回 403（默认拒绝）；声明后无权限主体 403、有权限主体 200，且每次拒绝有 `decision_logs` 记录
- [x] IT：移除角色后 `identity_revision` 递增、缓存失效，旧令牌请求被服务端拒绝
- [x] UT：卸载 `qian.authz` 组件时 `waterfall` 监听器被逆序撤销；OpenAPI 中每个受保护端点带 `x-qian-permission`
- [x] IT：gRPC 调用与 HTTP 调用对同一权限点判定一致
- [x] IT：租户专属权限点不可绑定到子作用域（应用 / Agent 会话 / 别的租户），跨作用域绑定返回结构化 ErrorDetail（`AUTHZ_SCOPE_MISMATCH`，pointer `#/scope`）且不落库
- [x] IT：最后一个持有成员管理权限（`tenant.owner` / `tenant.admin`）的主体不可被移除或降级（`AUTHZ_LAST_ADMIN_LOCKOUT`，防自锁）
