## 背景

S1-RT-038 验收复核（2026-10-23，done）里复核方与独立审读又找出一批「代码正确、口径没有用例钉住」的点（复核方在突变工作区逐条实测，存活的才列入）：

- 缺审计时卸载 / 清除的拒绝时机：`LifecycleController.Tenants.cs:170`、:210 的 `RequireAudit` 挪到最终迁移处（钩子已跑、执行记录已认领、卸载还撤下了 scope 条目之后才 503）全过——撤下审计后卸载的用例（`LifecycleAuditTests.cs:113–128`）没断言执行记录与 scope 条目，清除没有缺审计用例。
- profile 软边的「上传 false」：`ProfileLoader.cs:623` / `profiles.ts:298` 复位 state 但把 false 改成 true，仓内 127 例（含 S1-RT-038 加的两节点反向例）全过——两节点环里「上传 false」本身不可观察。复核方临时加的三节点链 optional-inject-cycle-three（settings `optionalInject [Consumer]`、consumer `inject [Middle]`、middle `inject [Settings]`，bundle one 顺序 settings、consumer、middle，期望顺序 settings、middle、consumer）能让两侧失败。
- 平台链追加抛非 AUTHZ_DENIED 的 Qian 错误（链头被改 → CONFLICT）时应原样传出：`LifecycleController.Audit.cs:104` 的 catch 放宽为任意 QianErrorException（CONFLICT 也转 503 + 误导的事件 8）全过。
- 事件 8 原因串对「平台链未配置 chain.platformRole」这一来源只靠模板里的同名字样覆盖（`LifecycleLog.cs:32` 模板本身含 chain.platformRole），删去这一来源全过。
- 重做次数：`attempt < 5` 改为 `< 1`（租户链、平台链各一处）全过——并发用例只要求发生过一次重做，README「5 次重做、共 6 次尝试」无处钉住。

另有几处同源的小项：批准缺失的升级被拒后租户链长度不变没有断言（`PermissionApprovalTests.cs:221` 之后加一行即可）；`LifecycleAuditTests.Chain`（`ReadAsync(0, 100)`）与 `TenantProvisioningTests` 的 `ReadAsync(0, 50)` 没有到达上限即失败的守卫；`LifecycleAuditHttpTests.cs:51` 硬编码 qian.audit 为第 03 步第一个 system 组件，日后加入排序靠前的 system 组件会误报；事件 7 / 8 的告警断言只对关键词 `Contains`，建议 `WarningLogs` 捕获结构化的 `{Reason}` 再断言。
