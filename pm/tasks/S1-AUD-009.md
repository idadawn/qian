## 背景

R126 ①（S1-RT-037，2026-10-23）：平台级生命周期操作（安装、激活、回切、弃用、退役）记平台链，但审计端口的平台链入口 `AppendPlatformAsync` 是独立事务——专用平台登录，RLS 要求 current_user 与 session_user 都是平台角色——Lifecycle 的应用角色在自己的事务里写不进平台链，所以只能在状态变更提交之前追加：追加成功之后、本事务提交完成之前的任何失败都会在平台链多留一条孤儿条目（ADR-009 §3 的崩溃窗口取「宁多不漏」）。ADR-009 把同事务写入定为「业务成功即有审计、业务失败即无审计」的唯一正确语义，平台链现在缺这个入口。`packages/Qian.Lifecycle/README.md` 已知限制写明「补同事务端口要改 Audit 的 RLS 策略与 SECURITY DEFINER 函数，归 Audit 所有者另立任务」，本任务即此。

## 验收

- [x] Audit 提供平台链的同事务入口（形如 `AppendPlatformEnlistedAsync(producer, record, DbTransaction, ct)`，与租户链的 `AppendEnlistedAsync` 同一约束：调用方的可串行化事务、不提交、冲突由调用方换会话重做）：追加由 SECURITY DEFINER 函数以平台链角色完成，调用方的应用角色只获执行权；RLS 仍拒绝应用角色直接读写平台记录，`AuditPlatformAccess` 的现有保证（平台角色不能更新 / 删除历史、不能读写租户数据、普通角色不能借 SET ROLE 冒充）不变；Audit README「受控平台链」与 ADR-009 写明口径
- [x] qian.lifecycle 的 `PlatformAudited` 改走同事务入口；`LifecycleAuditTests` 里「状态提交失败时平台链多留一条」改为两者都不留，README 已知限制删去孤儿条目一条，R126 ① 补记
- [x] 突变：改回提交前追加（孤儿条目重现）、函数不校验调用方角色、应用角色直接 INSERT 平台记录各有失败用例；日志逐条记「改了什么 → 哪个用例哪一行失败」
