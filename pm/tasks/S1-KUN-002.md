## 背景

7.1 第 2 项：领域事件派发改为提交前同 scope、分析器规则「集成事件只能在命令 handler 同 scope 发出」、消费端处理成功后才 ack 并指数退避进 DLX、`IOutboxMessageStore` EF 默认实现、Outbox 锁默认开、publisher confirm。S1 第一周先用最小集成测试实证「领域事件→集成事件路径丢消息」再定上游修复或 Qian 侧规定。

## 验收

- [x] IT（第一周实证）：Catalog 建商品后断言 `outbox_messages` 行数，确认当前路径是否丢消息并记录结论
- [x] IT：命令 handler 内经通知 handler 发出的集成事件，提交后 `outbox_messages` 行数 +1
- [x] IT：消费端 handler 第一次抛异常、第二次成功，事件最终恰被处理一次且 `processed_messages` 只有一行；RabbitMQ 容器重启后未 ack 消息重投不丢
- [x] IT：两个发布器副本同时轮询同一 Outbox 表，每条消息只发布一次（publisher confirm 计数）
- [x] UT：被 Skip 的 at-least-once 集成测试恢复为必跑并通过
