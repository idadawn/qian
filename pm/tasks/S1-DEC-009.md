## 背景

产品族仓库目前分在两个 GitHub 所有者下：Kun 与 iClaw 源码在 CavaiLAB 组织，Qian、部署仓库、MaaS 在个人账号。GitHub Packages 的 NuGet feed 按所有者划分，`Qian.*` 又传递依赖 `Kun.*`，两个所有者意味着消费者要配两段源加 `packageSourceMapping`，与「装一个包就能用」（ADR-019）相悖；`qian-plugins` 规定为「与 Qian 同组织」但组织名仍是占位。

**推荐：Qian 迁入 CavaiLAB**。理由：Kun 的 CI 与 feed 零改动，产品负责人是该组织管理员，Kun 的其它下游不受影响；迁移成本只在 Qian 侧的四处地址。**备选：新建专用组织**（公开形象更干净，但要同时迁 Kun 的 feed 与 CI；留到 S3 公开前再评估，届时包已在 nuget.org / npm）。**备选：维持现状**（两个 feed，S1 内部可忍，S2 末公开前必须解决）。

若迁移，GitHub 会自动重定向 git 地址，但要改：① `deploy/pm-board/deployment.yaml` 的 `GITSYNC_REPO`；② `deploy/pm-board/bootstrap.sh` 的 `REPO`；③ 部署仓库 `env-ds/argocd/qian-pm-board-application.yaml` 的 `repoURL` 与 ArgoCD 仓库凭据 `argocd/qian-repo-ssh` 的 `url`；④ 在新仓库重新登记只读 deploy key；⑤ CI secrets / variables 随仓库迁移；开放的 PR 与 issue 随仓库保留。
