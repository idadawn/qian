## 背景

数据本体的五项验收已有真实证据；组件代码字段必须由 SDK 源生成，但 RT-014 依赖 RT-004，而 RT-004 又依赖 DATA-001，形成验收循环。完整代码包安装由 RT-011 负责，其开发中的 CLI 尚未通过真实命名组件、私有发布与平台权限等全部门禁。产品负责人已批准本体与集成分阶段验收，保留后续必过门，不以配置骨架代替完整安装。

## 已准备的可审阅结果

- [Qian PR #44](https://github.com/idadawn/qian/pull/44)：安全装配、自动新表 RLS、受限角色检查、数据服务、同上下文 Outbox、软删审计、连接引用选择与独立库使用均已有实现和真实测试。
- samples/Qian.Sample.Crm 是实际 Kestrel 宿主，使用真实签名令牌和 Kun 认证/权限端口。PostgreSQL 中 A/B 各 1000 行；A 的全部分页只返回 A，B 读取 A 记录为 404，伪造令牌/租户头/错误调用方被拒绝。
- 测试抓取 HTTP 列表的实际 SQL 与参数执行 EXPLAIN ANALYZE，确认命中 ix_customers_tenant_id_id；没有关闭顺序扫描或扩大数据集。实际计划随 CI 测试结果上传。
- 同步 CFG-002 / Kun 2026.10.12 后，本地全仓构建零警告、16 包依赖检查、38 项门禁及 358 项测试通过，零跳过；[远程 CI](https://github.com/idadawn/qian/actions/runs/38176785648) 的 358 项结果和真实索引计划已复核。

## 已批准的分期

1. 第一阶段：在本 PR 远程 CI 全绿后合并已完成的数据本体，DATA-001 标为本体验收完成，解除 Registry 的实现前置。
2. 第二阶段：由 RT-014 补代码字段源生成、SDK 默认装配和包族私有 NuGet 锁步发布；由 RT-011 补 qian add 代码包真实安装。两者仍是完整组件交付的必过门，后续任务必须回验本组件。
3. 第二阶段未通过前，保留 plugins/qian.data 的骨架标记，不宣称正式组件安装或私有 NuGet 发布已经完成。QA-002 总目标继续保持未完成，按必要依赖推进。

产品负责人于 2026-10-12 明确选择「分阶段验收，保留后续安装门」，第一阶段在本 PR 最终 CI 全绿后交付；第二阶段的未完成项已经回写 RT-014 / RT-011，不因 DATA-001 关闭而豁免。
