## 背景

S1-AUD-009 验收复核（2026-10-23，done）里独立审读推演、复核方在突变工作区实测出一批没有用例钉住的边界，以及两处零成本的加固：

- 函数属主没有断言：`AuditPlatformAccess.cs:142–143` 去掉两行 `ALTER FUNCTION … OWNER TO writerRole`，平台函数留给迁移超管、SECURITY DEFINER 以超管身份运行、RLS 整体旁路，`AuditStoreTests` 与 `LifecycleAuditTests` 全过（租户链的 transaction_tip / transaction_append 同一盲区）。
- 执行权检查按计数：`AuditTransactionWriter.cs:104` 的 `count(*) = 2` 改成 `>= 1`（只授一个函数也放行）全过——用例都用常量两函数同授同撤；同一 grantee 由不同 grantor 各授一次时 `aclexplode` 出 4 行会误拒。
- 链头核对只改过 tip_seq：`AuditPlatformAccess.cs:109` 去掉 `content_hash = h` 全过——tip_hash 被改而 tip_seq 正确时追加成功、前序挂到伪哈希，只有事后验链报 previous_mismatch。
- 属主成员关系只查一个方向：RLS 属主分支（:44）与 CallerGuard（:86）的 `ON (m.roleid = r.oid OR m.member = r.oid)` 去掉 `member` 方向全过——用例只做 `GRANT writer TO qian_app`。
- 属主被改成 LOGIN（需 CREATEROLE / 超管）后直接登录：current_user = session_user = 属主、无成员关系、GUC 为空，属主分支开放且属主持有表的 INSERT 权，可绕过哈希校验直接写平台行；前置检查只在迁移时查 NOLOGIN。属主分支与 CallerGuard 各加一句 `session_user <> writerRole` 即可封堵。
- 事件 8 的原因串没列「本组件的连接就是平台登录」这一来源（`LifecycleController.Audit.cs:99` 注释列了；LifecycleDbContext 绑错登录时挂载校验查的是 AuditDbContext，拦不住，PlatformGuard 会拒但告警不点名）。
- 文档：Audit README「受控平台链与生命周期」先讲一参 `CreateMigrationSql(role)`，装 qian.lifecycle 的宿主要读到后文才知道必须三参（验收 PR 已加半句指引）；「三参之后再误跑一参」的失败形态（platform_append 的 INSERT 裸抛 42501、无事件 8）与「与其它平台生产方重叠即耗一次重做」没写；参考宿主里 producerRole 就是共享的 qian_app，同一登录下的所有平台组件在数据库层都获得写平台链的能力（进程内仍受 `Platform(producer)` 约束），生产宜给 Lifecycle 独立登录（S1-DEP-005 移交写的是「Lifecycle 的登录」，README 应点明）。
- 兼容性：`IAuditWriter.AppendPlatformEnlistedAsync` 是接口新抽象成员，Abstractions 已随 0.2.0 发包，外部实现者升级即编译断；改为默认接口实现（抛 NotSupportedException）可零成本保兼容。`SET search_path = pg_catalog` 未带 `pg_temp`（租户链函数同），现状只会自伤报错不会放行。

## 验收

- [ ] 迁移后断言 platform_tip / platform_append 与 transaction_tip / transaction_append 的属主都是 writerRole——去掉 `ALTER FUNCTION … OWNER TO` 有失败用例
- [ ] 写入器守卫与函数逐个检查两个函数的直接执行权（不用 `count = 2`）：只撤销 platform_append 的执行权时激活 503 + 事件 8；同一 grantee 多个 grantor 的重复 ACL 项不误拒
- [ ] tip_hash 被改而 tip_seq 正确时同事务追加 CONFLICT——去掉 `content_hash = h` 有失败用例
- [ ] 属主分支与 CallerGuard 加 `session_user <> writerRole`：属主被 ALTER ROLE LOGIN 后直接登录仍读不到、写不进平台行；成员关系两个方向各有用例（`GRANT 任一角色 TO writer` 也关闭分支、函数拒绝、迁移拒绝重跑）
- [ ] 事件 8 原因串补「本组件的连接就是平台登录」；Audit README 写明「三参之后再跑一参」的失败形态与「与其它平台生产方重叠会重做」，README 与 S1-DEP-005 建议生产给 Lifecycle 独立登录
- [ ] 评估并决定 `AppendPlatformEnlistedAsync` 改为默认接口实现、`search_path` 补 `pg_temp`（两条链一起）；不改也要在日志写明理由
- [ ] 日志逐条记「改了什么 → 哪个用例哪一行失败」
