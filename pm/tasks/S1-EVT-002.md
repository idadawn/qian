## 背景

`Subscribe<TEvent, THandler>()`；处理成功后 ack；重试 5 次后进 `qian.dlx` 并告警；幂等装饰器先查 Redis `processed:{consumer}:{event_id}`（TTL 7 天）再执行、成功后写入，PG `processed_messages` 兜底；信封 `tenant_id` → `BeginScope` 与 baggage 注入在订阅器统一完成；竞争消费与广播两种订阅。

## 验收

- [x] IT：消费端前两次抛异常、第三次成功，`processed_messages` 恰一行；第 6 次仍失败进 DLX 并发告警（幂等记录为 Redis 键 `idemp:{consumer}:{event_id}`，恰一条；告警为 dead_lettered 计数加 Error 日志，见 2026-10-22 日志）
- [x] IT：同一事件重投两次，幂等装饰器拦截第二次，handler 只执行一次
- [x] IT：消费端 handler 内租户上下文为该事件的租户，EF 查询自动带 `tenant_id` 过滤（CRM 参考宿主，两个租户并发）
- [x] IT：广播订阅下每个实例各收到一次，竞争订阅下只有一个实例收到
- [x] IT（R81，自 S1-TEN-001 移交）：消费端 `BeginScope` 后可读到 `ITenantContextPropagator` 写入的 `tenant_id`，缺失时 fail-closed（消费端口径见 2026-10-22 日志的建议裁决，R122 采纳）
