## 背景

PRD 7.4.1 把 RFC 8707 `resource` 列为 S1 范围，7.9 的 Agent 契约要求 S1 保证令牌受众绑定。S1-IDP-005 实测发现，qian-identity 对显式 `resource` 一律拒绝：OpenIddict 7.7.2 对 resource 做两层检查，服务端要用 `RegisterResources` 登记（缺失时报 ID2190），客户端还要有 `rsrc:` 权限（缺失时报 ID2192），而 `Qian.Identity.Server` 两层都没做。授权端点不带 resource 时，会取客户端登记的全部资源作为受众。Identity.Client 因此不发 resource，`Resource` 只当作预期受众使用。由此有两个问题：

- 多受众令牌可以在不同资源服务器之间重放：登记了多个资源的客户端拿到的访问令牌 `aud` 含全部资源，任何一个资源服务器收到后都能拿去调用其他资源服务器。
- MCP 授权规范要求客户端在授权请求和换码请求里都带 RFC 8707 的 `resource`。按现状，标准 MCP 客户端会被 qian-identity 拒绝。

本任务让 qian-identity 接受 `resource` 并按它收窄访问令牌受众，多资源客户端必须指定 resource；Identity.Client 配置了 `Resource` 时随之发送。

## 验收

- [x] Server：两层检查。第一层由 Qian 接管：OpenIddict 自带的登记检查按 AbsoluteUri 比较，只有主机的标识永远通不过，所以用 `DisableResourceValidation` 关掉，在同一位置按客户端白名单逐字比较，越界报 `invalid_target`，令牌端点上排在客户端认证之后。第二层是客户端的 `rsrc:` 权限，由 `Resources` 推导，随描述符镜像写入，不用 `IgnoreResourcePermissions`。`ResourcesFor` 保留兜底。多资源客户端不带 resource 时报 `invalid_target`，单资源客户端行为不变
- [x] IT（`tests/Qian.Identity.Server.Tests`）：带登记内的 resource 时访问令牌 `aud` 只有该资源；登记外的 resource 报 `invalid_target`；用其他客户端的资源被拒；多资源客户端不带 resource 被拒；refresh 能收窄受众、不能扩大
- [x] Client：配置了 `Resource` 时授权请求带 `resource`，任意发行方模式（未配 `Resource`）不带；换码请求视 Kun `OidcCodeExchange` 能否追加参数决定带或不带，并写明理由；包 README 的选项表与「已知限制」同步
- [x] IT（`tests/Qian.Identity.Client.Tests`，真实 qian-identity）：授权请求带了 `resource`，访问令牌 `aud` 只有 `Resource`
