## 背景

[idadawn/qian#79](https://github.com/idadawn/qian/pull/79) 的 CI 运行 38448590040（「构建、门禁与测试」，2026-10-13T18:45Z）唯一失败的用例是 CRM 样例 `hooks文件更新后实际桥接行为五秒内改变_代码与业务服务不重启`：轮询 `Inject<SurfaceDocument>(SurfaceKeys.Hooks, "qian.sample.crm/hooks")` 时一次抛出 NOT_FOUND；前一个提交与本机均通过，与负载和时序有关。

根因：`SurfaceRegistrationSession.Replace` 先撤销旧注册、再登记新文档，会话锁不覆盖运行时的读取方，新旧快照都有的文档在两步之间对读取方短暂消失；hook 桥接若在这个窗口收到事件，会把 hook 当作不存在而跳过。注册按 key/name 独占（R38），不能先登记再撤销。TS 侧会话同样先 await 撤销再登记，窗口相同。

做法：两侧运行时 `Provide` 返回的注册句柄支持原子替换实例（读取方只看到旧值或新值）；表面会话改为先新增、再原位替换、最后撤销，保留失败回滚；补并发回归测试与共用 TCK 场景。

## 验收

- [ ] UT：.NET 与 TS 运行时 `Provide` 返回的注册句柄可原子替换实例；多个读取方在反复替换期间只看到旧值或新值、从不缺失，`List` 顺序不变；句柄撤销或上下文卸载后拒绝替换
- [ ] TCK：共用场景 T25 覆盖原位替换（新值可见、注册顺序不变、以 inject 依赖该键的条目重新 Apply、卸载无残留），.NET 与 TS harness 读同一 YAML 通过
- [ ] UT：双侧 `SurfaceRegistrationSession` 改为先新增、再原位替换、最后撤销；读取方在反复替换期间对新旧快照都有的文档从不 NOT_FOUND；新增冲突时回滚，旧注册与旧内容不变
- [ ] E2E：CRM hooks 热更新验收与双侧 T19 恢复严格断言，不再容忍过渡期缺失；超时报出最后观察到的内容与监视状态
- [ ] 门禁：.NET 全量构建与测试、`check_deps`、门禁自测、`check_docs`、`pm.py validate` 通过；规格 §5 / §10.2 与相关 README 同步
