## 背景

R106（2026-10-16）把本任务拆为两段：本任务交付镜像构建与供应链流水线；三个业务镜像接入流水线并复验，归 S1-DEP-008。

镜像形态沿用 R31：

- `platform` → `qian-platform`：JIT，含 `shell` 与 `model-gateway` 组合包。
- `identity` → `qian-identity`：JIT。
- `gateway` → `qian-gateway`：AOT distroless。
- 可选 `model-gateway` → `qian-model-gateway-adapter`（P1）。
- `standalone` / `minimal` 不出镜像。

本任务交付构建入口与门禁本身：

- 多阶段构建，提供 JIT 与 NativeAOT distroless 两种运行镜像模板。
- 以非 root 运行，根文件系统只读，只为声明的写目录提供临时卷。
- 按不可变 digest 生成 Syft SBOM，用 Grype / Trivy 做漏洞扫描，用 Cosign 签名并附 SBOM 证明；验签约束 CI 发布者的身份与 issuer。
- profile 文件与 `qian.patch.yml` 随镜像发布，环境级 `--patch` overlay 由 ConfigMap 挂载。
- 在源码树与镜像内分别执行 dump-config 合成并比对，作为配置漂移门禁。

流水线用 CI 内构建、不发布的自检镜像做端到端验证。自检镜像不是任何 profile 的产品镜像，也不替代三个业务镜像。业务宿主就绪之前，同样不拿基线探针、minimal 或 Storybook 页面冒充（见 deploy/images/README.md）。

## 验收

- [ ] 检查：仓库内有 profile 镜像的统一构建入口（多阶段，JIT 与 NativeAOT distroless 两种运行镜像模板）；JIT、AOT 各一个自检镜像在 CI 内端到端构建通过，只在 CI 内使用，不推送为产品镜像
- [ ] 检查：流水线按 digest 生成 Syft SBOM、执行漏洞扫描并按阈值失败、生成 Cosign 签名与 SBOM 证明；验签约束发布者身份与 issuer，缺签名、签名身份不符、缺 SBOM 证明三种反例都使门禁失败
- [ ] 检查：dump-config 漂移门禁在源码树与镜像内对同一 profile + 组合包 + patch 执行合成，逐项比较解析后的结构与来源层；改动镜像内 patch 的反例使门禁失败
- [ ] 检查：在 CI 内实际启动自检镜像，取得以非 root UID 运行、根文件系统只读的证据；构建证据记录源码 SHA、KunVersion、profile 修订与镜像 digest
