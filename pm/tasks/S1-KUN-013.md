## 背景

真实审计/CRM 前置核验发现正式 Kun 2026.10.12-hotfix.2 的 HTTP、gRPC、Mediator 三个 PEP 均省略 AuthorizationSubject.Kind，默认成 user。修复只读取已认证主身份的主体信息，透传 user/service/agent 类型，拒绝歧义值；验证服务与同名用户授权分离，再发布并由 Qian 精确消费正式包。

## 验收

- [x] UT/IT：HTTP、gRPC 四形态与 Mediator 保留主体种类，同名 service 不获得 user 授权，拒绝发生在 handler/读取业务流之前
- [x] UT：旧 ICurrentUser 与无类型的浏览器身份保持 user；歧义/未知种类和冲突标识拒绝，不从次身份拼接主体
- [x] 交付：上游完整 CI（含格式、分层和 AOT）全绿后合并，正式包发布并校验发布物
- [x] IT：Qian 精确消费正式 Kun 包，真实 PostgreSQL RBAC 验证同名服务/用户不共享授权，相关主线和草稿消费得到同步
