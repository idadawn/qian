## 背景

2026-10-20 产品负责人要求设计「从租户注册到管理员审批」的流程并先完成登录；主会话给出开通流程原型画板（端到端流程、申请状态机、登录、注册并申请、申请进度、选择工作空间、开通申请列表、审核抽屉、租户管理改版、企业首次进入，共 10 块）。2026-11-03 产品负责人指示「根据原型，完成租户相关的开发工作」，并要求「修改的同时优化前端组件的样式」。

PRD 7.3 把「自助申请 / 审核 / 加入 / 退出 UI」列为 S3；S1-YUE-002 的已通过裁决规定平台身份「不拉菜单 / 权限 / 能力目录、只显示代管横幅与会话卡片」。原型与这两处口径不同，本任务登记范围变更与实现时采用的技术口径。规格见 `docs/prd/specs/tenant-signup.md`。

D1 由产品负责人的指示直接决定；D2–D8 是主会话按原型与现有代码给出的推荐口径，实现按推荐进行，产品负责人逐条确认或改裁后登记进 `docs/decisions/key-decisions-v0.md`。

- D1 范围（产品负责人 2026-11-03 指示）：自助申请与平台审核提前到 S1。加入、退出、邀请与多管理员仍在 S3。PRD 7.3「范围与边界」随之改写。
- D2 组件：新增可选组件 `qian.tenancy.signup`（Abstractions + Provider），装进 identity profile（`qian.bundle.identity-server`）。不装即不提供自助开通，不设数据库开关。理由有三：申请人接口必须在身份服务那个公开入口上；建账号要进程内调 `IIdentityAccounts`；开通要进程内调 `ITenantProvisioning`。这三者在 identity profile 里同宿主。备选：并进 `qian.tenancy`。这样少一个组件，但公开匿名表面会进入租户主档组件，「不装即关」也做不到，所以不取。
- D3 账号先行：新号码在提交时经 `CreatePersonAsync` 建立不属任何租户的自然人，手机号经验证码核验后标为已验证，申请人自设密码，不强制改密。已有号码就以该自然人申请；账号停用、锁定或具备平台访问资格时拒绝（Q12）。通过时经开通编排第 05–07 步成为新租户管理员（R96 / R141 同口径）。
- D4 申请人访问：获批前不新增登录会话。统一登录流水线对没有成员身份的账号返回 `NO_AVAILABLE_TENANT`，而令牌里 `tenant_id` 为空专指平台身份。若增设「个人会话」，就要改令牌语义和下游的平台身份判定。所以进度页凭「手机号 + 验证码」建立本组件自己的申请人会话：HttpOnly、SameSite=Strict、Path 限 `/api/signup`、30 分钟、服务端只存哈希，只能读写本人的申请；提交成功时直接建立。凭密码查看进度需要身份组件新增「只核验第一因子」的端口，留作后续。
- D5 验证码与发件：本组件自带最小验证码挑战，规则见规格 §4 与 §6。发件端口 `ISignupMessenger` 定义在 Definition 包。通知组件（S1-NTF-003）就绪前，生产宿主没有实现：发验证码返回 503 `SIGNUP_UNAVAILABLE`，审核结果发不出不阻断审核。开发宿主登记开发期发件箱，只在 Development 环境、只监听回环地址，供手测与 E2E 读取。
- D6 租户号与缺省值：自助申请的租户号为 3–32 位小写字母或数字，有保留字。运营开户仍是 1–64 位。申请期间在进行中的申请之间、以及与已有租户之间都唯一；通过前运营可以修正，驳回或撤回后释放。缺省试用 30 天、用户配额 20（含租户管理员，不含平台超管），两者都在组件配置里改。
- D7 审核：通过、驳回、重试只对平台主体开放，处理顺序与租户运营相同（R113：主体检查 → 输入校验 → 上下文核对 → 超管旁路与平台链审计）。权限点为 `qian.tenancy.signup:application:read|approve|reject`。通过的顺序：申请转 provisioning → `ProvisionAsync`（成员 ID 在申请上只生成一次）→ `ActivateAsync`（试用或正式）→ approved。编排失败时申请转 failed，运营可以重试，申请人仍看到「正在开通」。驳回原因对申请人可见，审核备注只给运营看。
- D8 平台控制台（改 S1-YUE-002 裁决中平台身份的那半句）：持 `platform.superadmin` 的平台身份进入外壳后，加载全局 scope 组件的页面与菜单（租户管理、开通申请），按超管角色的只读判定过滤。显示菜单不等于放行：每次操作仍逐次经超管旁路并写平台审计链。没有平台角色的平台身份保持原样，只显示代管横幅与会话卡片。
