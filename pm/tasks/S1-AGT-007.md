- 2026-10-23 claude：建议裁决 ⑤（改变 R121 的接受范围，待用户在本会话确认）：两侧都拒绝「引用指向实例数据或名称表」，不采用「表面路径也跟随引用」。规则：`$ref` / `$dynamicRef` 的片段是 JSON Pointer 时，先还原 ASCII 范围的百分号编码（编码的斜杠 `%2F` 在各实现里含义不同，按无法判定），再按 `~1` / `~0` 还原，按遍历的口径逐段判定位置：途经 example、examples、default、const、enum，或停在名称表（properties、patternProperties、dependentSchemas、dependentRequired、dependencies、$defs、definitions）本身上，即违规（失败关闭），位置指向 `$ref` 本身，表面为 SURFACE_POLICY_DENIED、能力为 tenant-field。理由：纯语法判断，与引用的是哪个资源无关，`$id` 遮蔽、百分号编码与数组下标都拦得住，C# 与 TS 同一遍历；能力路径照旧跟随其余文档内引用（HTTP 契约要从请求体跟到 components），表面路径照旧不解析，其余可引用的位置遍历时已在定义处检查。代价：这类引用即使目标里没有租户名也拒绝，正常写法不会这样引用。另一方案只把表面路径对齐到能力路径现有的解析器：`$id` 遮蔽两侧仍绕得过去；解析失败时表面路径只能拒绝（锚点等合法引用一并被拒）或跳过（`%64efault` 照样绕过）；`$ref` 到 `$defs` 的租户字段还会在引用处与定义处各报一次。实例数据里声明的 `$anchor` / `$dynamicAnchor` / `$id` 建议不查，记为已知行为
