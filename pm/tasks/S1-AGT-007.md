## 背景

S1-AGT-004 验收复核（2026-10-23，done）留下的非阻断项。规则在 C#（`packages/Common/TenantFieldRule.cs`）与 TS（`@qian/surfaces`）两侧一致，口径见 R121；但 TCK 缺几种写法，TS 侧对应分支删掉后没有用例失败，compare-fixtures 也看不到；表面路径不解析 `$ref`，与能力路径口径不一。

- 2026-10-23 claude：实测执行侧（main 187c880189，探针不提交）：JsonSchema.Net 9.4（能力登记期预编译与执行）与 Ajv 2020 都按原始 JSON 解析片段为 JSON Pointer 的引用，`#/$defs/x/default`、`/examples/0`、`/const`、`/enum/0`、`/example` 指向的数据被当 Schema 执行（输入 `{"f":{}}` 报 REQUIRED `#/f/a`）；引用停在名称表本身（`#/$defs/t/properties`）时，表里的名称被当关键字执行（`tenantId` 成了属性）。能力路径的 FindFields 从文档根跟随 `#/` 引用，查得出指向对象成员的实例数据与名称表；数组下标、百分号编码（`%64efault`）与锚点让解析抛异常，整个契约按 contract-invalid 拒绝；`$id` 内嵌资源里的同名路径（执行侧按内嵌资源解析，FindFields 按根解析）检查不到，执行时却要求 tenantId，是能力路径现有的漏洞。表面路径不解析引用，以上写法都放过。锚点或 `$id` 声明在 example 里：Ajv 能引用到，Qian 登记期按 unresolved-reference 拒绝
- 2026-10-23 claude：建议裁决 ⑤（改变 R121 的接受范围，待用户在本会话确认）：两侧都拒绝「引用指向实例数据或名称表」，不采用「表面路径也跟随引用」。规则：`$ref` / `$dynamicRef` 的片段是 JSON Pointer 时，先还原 ASCII 范围的百分号编码（编码的斜杠 `%2F` 在各实现里含义不同，按无法判定），再按 `~1` / `~0` 还原，按遍历的口径逐段判定位置：途经 example、examples、default、const、enum，或停在名称表（properties、patternProperties、dependentSchemas、dependentRequired、dependencies、$defs、definitions）本身上，即违规（失败关闭），位置指向 `$ref` 本身，表面为 SURFACE_POLICY_DENIED、能力为 tenant-field。理由：纯语法判断，与引用的是哪个资源无关，`$id` 遮蔽、百分号编码与数组下标都拦得住，C# 与 TS 同一遍历；能力路径照旧跟随其余文档内引用（HTTP 契约要从请求体跟到 components），表面路径照旧不解析，其余可引用的位置遍历时已在定义处检查。代价：这类引用即使目标里没有租户名也拒绝，正常写法不会这样引用。另一方案只把表面路径对齐到能力路径现有的解析器：`$id` 遮蔽两侧仍绕得过去；解析失败时表面路径只能拒绝（锚点等合法引用一并被拒）或跳过（`%64efault` 照样绕过）；`$ref` 到 `$defs` 的租户字段还会在引用处与定义处各报一次。实例数据里声明的 `$anchor` / `$dynamicAnchor` / `$id` 建议不查，记为已知行为
