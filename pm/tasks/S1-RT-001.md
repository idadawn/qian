## 背景

ADR-020 D20.1–D20.5 的 .NET 落地：`IQianPlugin { Inject; Apply }`、`IPluginContext`（`Get / Provide / On / Emit / Waterfall / Parallel / Serial / Bail / Effect / Scope / Restrict`）、按 `inject[]` / `provides[]` 拓扑排序的装载器、可逆副作用逆序撤销、scope 两层扁平（`tenant:` / `app:` / `agent-session:`）与遮蔽 / `restrict` 交集。组件库唯一必需依赖，一切组件任务的前置，第 1 波首项。

## 验收

- [ ] TCK：`Inject` 的服务键无人提供 → 启动失败并指出缺失键与请求方；依赖成环 → 结构化错误列出环路
- [ ] TCK：`Apply` 中注册的全部 effect 在卸载时按逆序撤销，卸载后服务容器中无残留
- [ ] TCK：五种分发模式各一组用例——`waterfall` 监听器不调用 `next()` 时下游不执行；`bail` 停在首个返回值；`parallel` 任一失败不影响其余
- [ ] TCK：租户 A scope 注册同名服务后，A 内解析到遮蔽项，B 与全局不受影响；两条 restriction 的交集生效；被过滤项在目录与执行两处都「不存在」
- [ ] UT：`Qian.Runtime` 只依赖 `Kun.Core`、`Kun.Mediator` 与 .NET DI，无业务语义
- [ ] `Kun.*` 的 PackageVersion 一律引用 `$(KunVersion)`（属性若尚不存在则在本任务加入），`NuGet.config` 加 Kun 的 GitHub Packages 源与 packageSourceMapping（ADR-021 D21.3）
- [ ] Kun `Error` → `QianError`、`ValidationException.Errors` → `errors[]` 的桥接随 `Kun.*` 包引入一起落地（contracts/v0/README.md §3.7）
