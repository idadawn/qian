## 背景

ADR-020 D20.1–D20.5 的 .NET 落地：按规格 §5.2 实现 `IQianPlugin { Inject; ApplyAsync }`、`IPluginContext`（`Inject / TryInject / WhenReadyAsync / Provide / On / DispatchAsync / Effect / Scoped / Restrict / List`）、按 `inject[]` / `provides[]` 拓扑排序的装载器、可逆副作用逆序撤销、scope 两层扁平（`tenant:` / `app:` / `agent-session:`）与遮蔽 / `restrict` 交集。组件库唯一必需依赖，一切组件任务的前置，第 1 波首项。仅实现 .NET 侧；语言无关场景位于 `tck/runtime/`，TS harness 与完整套件由 S1-RT-003 / S1-QA-002 接续。

## 验收

- [x] TCK：`Inject` 的服务键无人提供 → 启动失败并指出缺失键与请求方；依赖成环 → 结构化错误列出环路
- [x] TCK：`Apply` 中注册的全部 effect 在卸载时按逆序撤销，卸载后服务容器中无残留
- [x] TCK：五种分发模式各一组用例——`waterfall` 监听器不调用 `next()` 时下游不执行；`bail` 停在首个返回值；`parallel` 任一失败不影响其余
- [x] TCK：租户 A scope 注册同名服务后，A 内解析到遮蔽项，B 与全局不受影响；两条 restriction 的交集生效；被过滤项在目录与执行两处都「不存在」
- [x] UT：`Qian.Runtime` 只依赖 `Kun.Core`、`Kun.Mediator`、.NET DI 与已有的 `Qian.Runtime.Errors`，无业务语义；不引用 `Kun.Validation`
- [x] `Kun.*` 的 PackageVersion 一律引用 `$(KunVersion)`（属性若尚不存在则在本任务加入），`NuGet.config` 用 packageSourceMapping 把 `Kun.*` 映射到 nuget.org；Kun 正式版从 nuget.org 还原，只有需要 Kun 预发布版时才加 GitHub Packages 源（ADR-021 D21.3）
- [x] Kun `Error` → `QianError` 放在 `Qian.Runtime`，`ValidationException.Errors` → `errors[]` 放在 `Qian.Runtime.Errors.AspNetCore`（只有它引用 `Kun.Validation`）；保持 ErrorDetail 封闭，按平台内置码映射（contracts/v0/README.md §3.7 / R48），上游 KunExceptionHandler 修正由 S1-KUN-006 负责
