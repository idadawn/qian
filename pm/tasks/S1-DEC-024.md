## 页面可用（本批收口）

S1-TEN-005 转 review 前，在本机对真实宿主跑通下面七步，并把证据（命令、Playwright 结果或截图、请求与响应摘要）写进 S1-TEN-005 的进度日志。不含登录页与外壳。

前置：

- 宿主：S1-TEN-006 的运营端点在本机以真实宿主运行，即 Kestrel + JwtBearer（RS256，完整校验 issuer、audience、有效期与签名）+ 受限 PG 应用角色 + 专用平台授权登录写入的超管行，装配同 `TenantOperationsHost` 与 `TenantManagementTests`。仓库里若已有本地手测环境的启动入口就直接用；没有就由 TEN-005 补一个只用于本机开发的入口，私钥不进仓库。
- 令牌：测试签发的平台超管 RS256 令牌，经开发服务器代理注入，或由 `PlatformClient` 的内存令牌提供器带上；不写 localStorage，不进 URL 与 iframe。
- 页面：一条命令启动开发服务器，浏览器打开即用。

七步：

1. 列表：打开页面，`GET /api/tenancy/tenants` 驱动 DataTable 服务端分页并显示总数；按状态与关键字筛选由服务端执行；加载、空、错误三态都能看到，停掉宿主后显示错误态而不是白屏。
2. 新建：抽屉里 SchemaForm 的字段与校验来自 `qian.tenancy` 的 OpenAPI 契约（含 TEN-005 补进契约的租户号与名称约束）。缺必填、租户号不合法时，提交前就定位到字段；绕过前端直接提交时，服务端 400 的 ErrorDetail 按 `pointer` 落到字段。建出租户 A、B：201，列表出现两行，状态 pending；重复租户号显示 409。管理员按契约直填 `membershipId` / `subjectId`（R110）。
3. 状态迁移：行内动作只列出 `GET /api/tenancy/meta/state-machine` 给出的合法迁移。激活 A（可选试用与有效期）后为 active 或 trial；冻结后为 suspended，恢复后回到冻结前的状态；非法迁移不出现，服务端拒绝时显示结构化错误。
4. 编辑：修改 A 的名称与用户配额，`PUT` 带 `expectedRevision` 成功；在另一处先改一次再提交，页面收到 409 并提示刷新，不覆盖别人的修改。
5. 详情：只读详情显示 `GET /api/tenancy/tenants/{id}/quota` 的限额；`usageAvailable` 为 false 时显示「用量不可用」，不显示 0。
6. 权限：换成租户主体令牌，页面显示 403 `AUTHZ_DENIED` 的无权限状态；去掉令牌显示 401 状态。两种情况都不是白屏或无限加载。
7. 代码审查：页面只用 `@yue/form` SchemaForm、`@yue/data` DataTable 与 `@yue/sdk` PlatformClient，没有第二套表单、表格或请求实现；localStorage、URL、iframe 中没有令牌。
