## 背景

S1-DEC-032 新增可选组件 `qian.tenancy.signup`，承接自助开通的后端。范围：
- 申请人一侧：验证码与申请人会话、租户号可用性、提交、查看、撤回；
- 平台运营一侧：列表与计数、详情与自动检查、通过 / 驳回 / 重试；
- 通过时对接 `qian.tenancy` 的开通编排与激活；
- 发件端口与开发期发件箱。

状态机、接口、数据与安全约束以 `docs/prd/specs/tenant-signup.md` §3–§7 为准。

## 验收

- [ ] 组件四问落地：
  - `plugins/qian.tenancy.signup` 的清单、配置 Schema（由代码派生）、HTTP 契约、权限目录与 UI 清单通过 `check_plugin_manifests.py`；
  - `Qian.Tenancy.Signup.Abstractions` + `Qian.Tenancy.Signup` 过 PublicAPI 门禁与 `check_deps.py`；
  - 装进 identity profile 组合包，`docs/generated` 重新生成
- [ ] IT 申请人：
  - 验证码只存哈希、单次有效、错误 5 次作废、按手机号与来源地址限流（429 带 Retry-After）；已注册与未注册号码的发码响应相同；
  - 核验后建立会话，Cookie 属性符合规格；
  - 新号码提交时建自然人（手机号已验证、密码按身份策略、无成员身份）并建申请；已有号码以该自然人申请、不改密码；停用 / 锁定 / 平台身份被拒；
  - 同一账号同时只能有一条进行中的申请；租户号与进行中的申请、已有租户冲突时被拒；
  - 撤回只对 submitted 生效；
  - 申请人只能看到本人的申请，跨申请人访问返回 404；
  - 写请求非 JSON 或跨源被拒
- [ ] IT 运营：
  - 列表、计数、详情与自动检查正确；
  - 通过后租户为 trial（或 active）、到期日与配额按审核结果，申请人自然人成为管理员成员并持 `tenant.owner`，用自己的密码经统一登录流水线直接登录新租户；
  - 编排中途失败时申请为 failed，重试后收敛到 approved 且不重复建租户或成员；
  - 驳回后租户号释放、原因对申请人可见、备注不可见；
  - 租户主体、Agent、无凭据分别 403 / 403 / 401，请求体带租户字段 400；
  - 每次通过、驳回、重试在平台审计链各有一条旁路记录
- [ ] 开发期发件箱只在 Development 环境登记、只监听回环地址；没有发件端口时发验证码返回 503 `SIGNUP_UNAVAILABLE`，审核不受影响
