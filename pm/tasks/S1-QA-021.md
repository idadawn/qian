## 背景

S1-QA-018（PR #262）验收复核（R134 ②）记下的四项遗留，均不阻断、不改门禁语义：

- **自检覆盖面**：`scripts/dotnet_ci.py paths-check` 只认 .NET 源码里以 `docs/` 或 `pm/` 开头的单一字符串字面量（`REPOSITORY_LITERAL`）。分段写法 `Path.Combine(root, "docs", "prd", "x.md")`、相对路径 `"../docs/…"`、插值 `$"docs/{name}.md"`、根目录 Markdown（`AGENTS.md`、`README.md`）、csproj 的 `Content` / `None Include` 指向 docs/ pm/、以及门禁作业里 python 脚本读到的文档都扫不到。复核时用 intent-to-add 探针验证：四种写法全部放行，同文件改成 `"docs/prd/14-quality.md"` 字面量即被拦。现有源码没有这些写法（全仓 grep），所以暂无现实漏洞；在自检放宽前，写法约定是「读取仓库文档写成以 `docs/` 或 `pm/` 开头的单一字面量」，这条约定还没写进 `tests/README.md`。
- **分片 a 重新配平**：S1-QA-017 合入后分片 b、c 明显变短，a 成了每次运行的唯一长杆。合入后 main 运行（40049850952 起 9 次）测试步骤：a 333–373 秒，b 112–246 秒，c 174–292 秒；关键路径 517–551 秒。a 的长杆是 `Qian.Scheduler.Tests`（310 秒，由 S1-QA-022 处理）；此外 a 有 14 个模块、同时只跑 4 个，最新 main 运行里 Scheduler 比分片开跑晚 39 秒。PR #262 说明里已预告「S1-QA-017 合入后把 c 里的轻模块挪一部分到 b，再按实测重新配平」。
- **说明更正**：`dotnet.yml` 的 `pull_request.paths` 注释、`tests/README.md` §5 与 PR 说明都写「docs/generated 由 Qian.Docs.Tests 比对」。实际 `Qian.Docs.Tests` 只用样例项目测生成器；读取 `docs/generated/config-catalog.md` 的是 `tests/Qian.Tenancy.Tests/TenancyConfigurationTests.cs:22`，派生文档新鲜度门禁在 `.github/workflows/documentation.yml`（自带 `docs/generated/**` 路径过滤）。重新纳入仍然必要，理由要写对。
- **slnx 外的测试项目**：`verify` 以 `Qian.slnx` 里引用 xunit.v3 的项目为全集，没加进 slnx 的测试项目在哪个分片都不会跑、也不会被核对（沿袭旧单作业行为）。`tests/` 下不在 slnx 的测试项目目前只有三个 `*.AotTests`（由专属作业运行）与 `tests/gates/**` 样例。
- 另记：第三次 PR 运行（40043749259）汇总作业在三个分片结束后等 runner 约 2 分钟；PR 说明给出的替代方案是把核对挪进各分片、省掉末尾作业，代价是没有合并的 `test-results` 构件。
