## 背景

S1-AUD-001 验收复核（2026-10-16）五条验收成立、已置 done。复核同时发现几处缺口：它们不在 AUD-001 的五条验收里，但影响生产路径的正确性和审计链的防篡改。逐条依据见 S1-AUD-001 进度日志「非阻断缺陷」一行。

- **只追加没落到租户直写路径**：REVOKE 只作用于平台角色和事务函数属主。按 Qian.Data README 推荐的默认授权，`qian_app` 对 `plugin_qian_audit` 两张表有 UPDATE / DELETE（受 RLS 限于本租户），能删掉链尾并回拨链头，`VerifyAsync` 发现不了。这与 ADR-009 D9.10「不做审计记录的物理删除」不符。
- **命令路径没有统一的冲突重试**：同事务追加要在业务快照之后才取链锁，同租户并发写会得到序列化失败（40001）。SDK 命令管道和 `/api/capabilities/{id}/invoke` 都不重试，只有参考应用自己的端点重试。
- **生产路径的审计字段没写全**：`resource` 恒为空，`result` 恒为 success，失败或被拒的调用不入审计。
- **AUD-001 第 5 条的测试证伪力不足**：已关闭的上下文会被可见性过滤，即使监听器撤销没挂上效果栈，断言也照样通过。
- **缺一条命令级用例**：没有覆盖「审计已写入、外层随后回滚」。
- **写命令能静默关闭审计**：命令可以用 `Audit = false` 关掉审计，生成器不拦。
- **热路径重复建校验器**：`AuditCommandPolicy` 每次调用都重新解析 Schema、重建校验器。
- **文档与 PRD / ADR 不同步**：`hook` 通道（R83）、R23 能力 ID 写法、监听器形态都没跟上。

审计上下文不随包带迁移，这一项归 S1-DEP-005 的迁移装配验收，不在本任务。

## 验收

- [ ] IT：租户应用角色对 `plugin_qian_audit.audit_entries` 只有 SELECT / INSERT，对 `audit_chain_state` 没有 DELETE / TRUNCATE，链头只能经受限函数推进；授权随包的迁移 SQL 落地，Qian.Data README 的默认授权说明同步。以应用角色删除链尾、改写记录或回拨链头都被拒绝（ADR-009 D9.10）
- [ ] IT：同事务追加遇到序列化失败时，SDK 命令管道与通用执行入口按有界次数重试整笔业务，或在业务快照之前取链锁；两个宿主经真实 HTTP 并发对同一租户各发多条写命令，全部成功、`seq` 连续、业务记录与审计一一对应
- [ ] IT：生产路径写入 `resource` 与真实 `result`；失败与被拒调用是否入审计按 ADR-009 定口径并实现；`on_behalf_of` 在 S4 处理 `act` 之前保持为空，README 写明
- [ ] UT / IT：S1-AUD-001 第 5 条补可证伪断言（卸载后派发确认审计监听器不再被调用，或同名不同 Definition 重新登记成功）；补「审计已写入、外层随后回滚」的命令级用例
- [ ] UT：源生成器对命令的 `Audit = false` 给出诊断（ADR-009 §5「每个写命令必有审计条目」），确需豁免的显式声明并在清单可见；`AuditCommandPolicy` 的 Schema 解析与校验器按契约缓存，不再每次调用重建
- [ ] 文档：`plugins/qian.audit/README.md`、`packages/Qian.Audit.Abstractions/README.md` 的过期句改正；PRD 7.11.1 与 ADR-009 同步 `hook` 通道（R83）、R23 的能力 ID 写法（`qian.sample.crm/customer.create`）与 waterfall 监听器形态，删去不存在的 `AddAuditBehavior`
