## 背景

组件规格 §7.6 / §9.5 规定租户 scope patch 的写入路径是管理面 `PUT /api/registry/tenants/{tenant}/patches/{scope}/{entry}`（幂等、带 `revision`）与 CLI `qian add --scope tenant:<id>`。S1-RT-004 只交付了 GET 的 scope 视图（`Qian.Registry.AspNetCore`），S1-RT-005 交付了进程内的 `MountAsync` / `UnmountAsync` 与同事务入 Outbox 的 `registry.scope.*.v1`，S1-RT-011 交付了本地 `qian add`；写入端点在 S1-RT-004 复核时发现无任务承接，S1-RT-011 的验收第 5 条（`--scope tenant:<id>`）也因此不能勾。按裁决 R86 由本任务统一交付：HTTP 写入端点（含 v1 别名）复用 RT-005 的服务端口，运营 CLI 经该端点写入。调用方是平台运营主体，走 S1-AZ-003 的超管旁路并审计；租户主体写入需新权限点并受权益检查。

## 验收

- [ ] IT：`PUT /api/registry/tenants/{tenant}/patches/{scope}/{entry}` 幂等、带 `revision`，经 S1-RT-005 的 `MountAsync` / `UnmountAsync` 写入并同事务发 `registry.scope.*.v1`；修订过期返回 409 `CONFLICT`；`policy.required: true` 的条目写 `disabled: true` 被拒；写入后 ≤ 5 s 在目标租户生效（复用 S1-RT-004 的通知与补偿读取），其他租户与全局不变
- [ ] IT：调用者授权——平台主体经 S1-AZ-003 的超管旁路放行并审计 `bypass = superadmin`；租户主体需新权限点 `qian.registry:scope:write`（`plugins/qian.registry/metadata` 声明，默认只授予 tenant.owner）并先过权益检查，S1-ENT-001 交付前 Entitlement 端口缺席时拒绝写入（fail-closed）；无权限者 404（R32 不可区分）、未带凭据 401；目标租户只来自路径 `{tenant}`，请求体不含租户字段（与 R85 同口径）
- [ ] IT：v1 别名 `PUT /api/kernel/tenants/{tenant}/patches/{scope}/{entry}` 同结果并带 `Deprecation` 与 `Link: <后继路径>; rel="successor-version"`（R33，复用 SDK `DeprecatedAlias`）
- [ ] IT（R86，自 S1-RT-011 验收第 5 条移交）：`qian add --scope tenant:<id>` 经该端点写租户 scope patch，需平台连接与运营权限，S1 仅运营 CLI；`qian remove --scope tenant:<id>` 逆序撤销；失败输出结构化错误（`--json`）
- [ ] 契约与文档：端点进入组件 OpenAPI 契约并经 S1-RT-006 契约准入；`packages/Qian.Registry/README.md`「剩余工作」、组件规格 §9.5 表与 PRD 7.2.1 的写入路径按交付改写
