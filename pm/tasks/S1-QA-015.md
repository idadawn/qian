## 背景

两次 CI 都在同一条用例上失败：

- 一次是 PR #199（S1-EVT-002）的 CI，run 39670252705，job「构建、门禁与测试」；
- 另一次是 main 的最新提交 90fcad73b4，即 #198 合并后的 run 39667300417。

失败的用例是 `Qian.Identity.Server.Tests.AuthentikConnectorTests.经Authentik首次登录确认绑定_再次登录直接进入_同租户重复绑定被拒`。

异常为 `KeyNotFoundException: The given key 'openid' was not present in the dictionary`，栈在 `AuthentikFixture.CreateClientAsync`：它按 `scope_name` 取 openid、email、profile 三个 scope 映射，此时映射还不存在。

这条用例在 #197 自己的 PR CI 和本机都能通过。

根因：夹具的就绪等待只等三个内置 flow，没有等 scope 映射，而两者来自不同的蓝图。

- 三个内置 flow 是 `default-provider-authorization-implicit-consent`、`default-provider-invalidation-flow`、`default-authentication-flow`，来自镜像里 `/blueprints/default/` 下的蓝图。
- scope 映射来自另一份系统蓝图 `/blueprints/system/providers-oauth2.yaml`（「System - OAuth2 Provider - Scopes」）。

两份蓝图互不依赖，worker 分别应用，先后顺序不定。CI 的 x64 机器较慢时，可能出现 flow 已就绪、映射还没建好的窗口，用例一取映射就失败。

## 验收

- [ ] 夹具启动时的就绪等待同时要求：
  - 三个内置 flow 都已存在；
  - scope 映射中有 openid、email、profile 三项。

  两者都就绪后才交给用例。超时报错要写明还缺哪些 flow 或映射。
- [ ] `CreateClientAsync` 与就绪等待共用同一份 flow 与 scope 映射查询，不另写一套
- [ ] 只改测试夹具，不改 Identity 产品代码
- [ ] 本机用真实 Authentik 容器跑 `AuthentikConnectorTests` 通过，`Qian.Identity.Server.Tests` 全部通过
