## 背景

S1-RT-025 差分时发现，两端读取表面文件的解码方式不同，与解析器本身无关：

- 表面文件：.NET 用 `File.ReadAllText(path, new UTF8Encoding(false, true))`，StreamReader 遇到 BOM 会改用 UTF-16 或 UTF-32 解码；CLI 用 `TextDecoder('utf-8', { fatal: true })`，只认 UTF-8。以 UTF-16LE（带 BOM）保存的 `metadata/roles.json`，.NET 判为有效，CLI 报 SURFACE_PATH_INVALID「文件无法读取或超过大小限制。」。
- `runtime.configSchema` 指向的 Schema 文件：.NET 用 `File.ReadAllText(path)`，CLI 用 `readFileSync(path, 'utf8')`，两端都把非法的 UTF-8 字节换成 U+FFFD 而不拒绝，BOM 的处理同上。

应统一为按 UTF-8 严格解码（只认 UTF-8 的 BOM），两端对非 UTF-8 文件给出同一诊断，并补表面 TCK 场景（样例要按字节写文件）。

## 验收

- [ ] 表面文件与配置 Schema 文件两端都按 UTF-8 严格解码；UTF-16、UTF-32（含 BOM）与非法 UTF-8 字节两端给出同一诊断
- [ ] 表面 TCK 补充按字节写入的样例，两端报告比较通过
- [ ] 相关测试、门禁、`check_docs.py`、`pm.py validate` 通过
