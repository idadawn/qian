## 背景

7.1 第 4、5 项：回退认证策略默认「要求已认证」、路由级限流真正绑定、可信代理网段、JWKS 双钥热轮换、网关宿主 `AddKunObservability`、`/healthz` `/readyz`、`client_credentials` 签发端点；Tracing / Auth / Result 三个 gRPC 拦截器补齐 server / client / duplex streaming。7.9 网关装配的前提。

## 验收

- [x] E2E：未带令牌请求任一业务路由返回 401（除显式匿名白名单）
- [x] IT：对限流路由超阈值返回 429 且响应头含 `Retry-After`
- [x] IT：轮换签名私钥后，旧 `kid` 令牌在重叠窗口内仍可验证，窗口外被拒绝；过程不重启进程
- [x] E2E：伪造 `X-Forwarded-For` 的请求（非可信网段发出）不改变限流分区
- [x] IT：无 `tenant_id` 的流式调用在首帧前被拒绝（`Unauthenticated`）；流式调用出现在 trace 中

## 验收证据与边界

- Kun 上游实现与真实集成测试：网关 9 项、gRPC 四形态 8 项；实际 Kestrel/HTTP2 与 RSA JWT，缺租户时 handler 和应用帧读取计数均为零。
- 签名私钥在同进程原子替换后使用新 kid；重叠 JWKS 同时验旧、新签名，到期刷新 JWKS 后拒绝旧签名。消费者缓存不会被主动撤销，仍须验证寿命与时钟偏移并刷新公钥；多副本和重启需协调轮换。
- 信任名单为空、非匹配代理、显式可信 IP、可信 CIDR 四种情形均经实际请求验证；仅后两者可根据转发地址切换分区。
- 本地全仓 Release 测试 811 项通过、2 项既有外部对象存储测试跳过；本机不跑依赖已部署示例环境的测试及 Linux 专用原生示例测试，后者由上游 CI 单独执行。
- 原生网关开启观测后的健康检查/就绪/JWKS 200、匿名业务路由 401 已验证；EF 观测通过运行时特性守卫从原生路径裁掉，保留原生编译门禁。
- 机器 `client_credentials` 端点按 ADR-010 D10.5 与 PRD 7.9 属于 `qian.identity`（S1-IDP-002）；此项完成 Kun 的认证换签边界，不将身份产品端点标为已实现。
