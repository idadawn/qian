## 背景

`callback` 类型：`POST {service}/qian-jobs/{code}` 按 K8s Service 名寻址，头 `X-Qian-Run-Id`、`X-Qian-Signature`（HMAC，密钥 secretRef），S2S `aud = service`（服务身份 `client_credentials`），幂等键 = run id，超时、重试、结果回写 `POST /api/scheduler/runs/{id}/result`；结构化执行日志（状态、耗时、错误分类、业务结果）；API 与最小管理面；事件 `scheduler.run.completed / failed.v1`；`qian.scheduler.job-type/v1` 扩展点。

## 验收

- [ ] IT：回调签名错误被对端拒绝；回调超时后按策略重试并最终写 `error_class = timeout`；对端回写业务失败后 `job_runs.business_result = failed`
- [ ] IT：回调携带的 S2S 令牌 `aud` 为目标服务且 `principal_kind = service`
- [ ] UT：`jobs.create` 标 `write` + `confirm`，`run-now` 标 `write`
- [ ] IT（R81，自 S1-TEN-001 移交）：作业执行器 `BeginScope` 后可读到 `ITenantContextPropagator` 写入的 `tenant_id`，缺失时 fail-closed
- [ ] E2E（R95，自 S1-TEN-002 移交）：调度器以 callback 类型按计划调用 `qian.tenancy` 的到期扫描能力，在 staging 准点触发并发出 `tenant.expired.v1`
