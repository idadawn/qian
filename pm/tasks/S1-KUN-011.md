## 背景

RT-004 的真实 PostgreSQL 多宿主测试复现：正式 Kun 2026.10.12 的全局查询过滤器捕获首个 ITenantContext 实例；相同上下文类型和租户复用 EF 模型后，新宿主会引用旧宿主已退出的租户作用域，SQL 变成 WHERE FALSE，已写入 patch 无法查询或更新。需在 Kun 修复并真实发版，再由 Qian 升级唯一 KunVersion 回验，不能靠共享测试上下文或绕过查询过滤器掩盖。

## 验收

- [x] Kun：共享模型在不同租户访问器/宿主之间复用时读取当前 DbContext；真实 PostgreSQL 覆盖旧访问器退出及改为其它租户，默认与按租户模型缓存均通过
- [x] Kun：旧访问器入口无法安全绑定当前 DbContext 时明确拒绝，提供 DbContext 重载、迁移说明与回归；全部上游 CI 通过后合并
- [x] 发布：按修正后的同日修复规则发布到 nuget.org，Qian 真实还原并核验来源；不以本地项目引用或临时包代替
- [x] Qian：只通过中央 KunVersion 钉定修复版，真实 Data 跨宿主回归从旧版失败转为通过，全仓构建/门禁/测试通过，解除 RT-004 的框架前置

## 已准备的上游修复

[Kun PR #54](https://github.com/idadawn/kun/pull/54) 在正式版源码上复现 4/4 失败后修复；最终 8 项真库模型复用回归、13 项相关单元测试及 27 项相关基础设施测试通过。旧 `ApplyKunMultiTenantFilters(ITenantContext)` 标记 KUNTENANT001 并明确拒绝，非 KunDbContext 消费者迁移到接收 DbContext 的重载。Qian 继承 KunDbContext 的路径自动获得修复。

原 `2026.10.12-2` 发布被 nuget.org 以包清单版本无效拒绝，失败标签保留。S1-KUN-012 将同日补丁格式改为 `2026.10.12-hotfix.2`，并在推送前检查实际包及内部依赖；[正式发布](https://github.com/idadawn/kun/actions/runs/38206412089) 已成功。Qian 使用 `[KunVersion]` 精确范围，实际还原出的 13 个 Kun 依赖均为该版本且来自 nuget.org，防止按最低版本范围选回同日基础版。
