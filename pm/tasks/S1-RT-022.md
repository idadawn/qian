## 背景

S1-CFG-009 差分时发现：配置补丁里的字符串或键名含残缺代理项的转义（反斜杠 u 后接未成对的 D800 至 DFFF 码元）时，.NET 的 SurfaceReader 与 CLI 的 parseSurface 处理不同。YAML：YamlDotNet 报「YAML 语法无效或存在重复键。」，TS 的 yaml 包照常解析。JSON：.NET 读键名时 Utf8JsonReader.GetString 抛 InvalidOperationException，SurfaceReader.Parse 不捕获，profile 装配按无法解析处理；字符串值要到之后取用时才失败；TS 一律接受。S1-CFG-009 只让 profile 装配在配置验证前两端都按无法解析处理，报告的位置与时机仍不同（见 packages/Qian.Profiles/README.md 的已知分歧）。应在表面解析层统一：两端解析时都拒绝含残缺代理项的字符串与键名，给出同一诊断，补表面 TCK 场景。

## 验收

- [ ] 两端表面解析器对含残缺代理项的字符串与键名给出同一诊断（JSON、YAML 与 Markdown front matter），`SurfaceReader.Parse` 不再把 InvalidOperationException 抛给调用方
- [ ] 表面 TCK 与 profile TCK 补充用例，两端报告比较通过
- [ ] 删去 `packages/Qian.Profiles/README.md` 中对应的已知分歧
- [ ] 相关测试、门禁、`check_docs.py`、`pm.py validate` 通过
