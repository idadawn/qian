## 背景

S1-DEC-024 / R110 从 S1-TEN-005 移出的运营后台功能。原有第三块「权益授予」（租户详情里的「授权（调 7.14）」）已于 2026-11-02 经用户确认拆为 S1-TEN-015，本任务不再依赖 S1-ENT-001：

- 管理员维护：PRD 7.3 API 行的 `GET/PUT /api/tenancy/tenants/{id}/admins`，此前没有任务承接。单管理员，计入用户配额（补充裁决 Q12）；`tenant_admins` 只存 Membership 指针，Membership 与凭据归 `qian.identity`，`qian.tenancy` 不直写身份表（S1-TEN-003 / R96 同口径）。建立或绑定 Membership 用 S1-TEN-003 已登记、由 S1-IDP-003 提供的 `ITenantMembershipProvisioner`；替换管理员时原管理员授权怎么处理，按 PRD 13 与 Q12 在实现前写进任务日志，偏离写「建议裁决」。新建租户表单的管理员改为经 `qian.identity` 选择或创建，取代 S1-TEN-005 期间按契约直填 `membershipId` / `subjectId` 的做法。
- 重置密码：PRD 13 权限矩阵里平台运营的「管理员重置密码」（S1 最小）。重置经 `qian.identity` 的端口执行；S1-IDP-003 交付时若没有该端口，由本任务在 `Qian.Identity.Abstractions` 加端口、identity Provider 实现并向 IDP-003 登记（R96 同例）。

页面沿用 S1-TEN-005 的页面包，只用 SchemaForm、DataTable 与 PlatformClient。

## 验收

- [x] IT：`GET/PUT /api/tenancy/tenants/{id}/admins` 只对平台主体开放（S1-AZ-003 超管旁路 + 审计，与 S1-TEN-006 同一路径），租户主体 403 `AUTHZ_DENIED`、无凭据 401，请求体含 `tenantId` / `tenant_id` / `id` 返回 400；PUT 经 `qian.identity` 端口建立或绑定该租户的管理员 Membership（满额返回 `CARDINALITY_USER_LIMIT`），更新 `tenant_admins` 指针并经 `ITenantRoleGrant` 授予 tenant.owner；端点进组件 OpenAPI 契约并过 S1-RT-006 准入
- [x] IT：平台运营重置租户管理员密码经 `qian.identity` 端口执行，旧密码立即失效、下次登录被强制改密（S1-IDP-003 的初始密码语义），写审计；该操作标 `humanOnly` + `confirm`（PRD 7.4 Agent 契约），页面有二次确认
- [x] E2E（R81 / R110，自 S1-TEN-005 转来）：运营后台新建租户 A、B 时经 `qian.identity` 选择或创建管理员，两位管理员经统一登录流水线登录后各自只看到本租户数据
- [x] 代码审查：页面只用 `@yue/form` SchemaForm、`@yue/data` DataTable 与 `@yue/sdk` PlatformClient，无第二套实现；令牌不在 localStorage、URL 与 iframe 中

    - 验收 1：读代码确认，五个端点复用 TEN-006 的 Execute（R113 顺序），权限点为 `qian.tenancy:admin:<action>`。替换的顺序是：新管理员成员 → 新 owner → 撤销原 owner 与管理员标志 → 改指针 → 补审计。替换与开通续跑共用 `tenant:<id>` 会话锁，开通第 05–07 步未全部成功时返回 409。成员经身份侧 `CreateMembershipCoreAsync` 建立（`members:<租户>` 计数锁加配额判定），满额 422 时没有任何改动。IT 覆盖：401；403（租户主体、非超管平台用户、Agent）；请求体带 tenantId / tenant_id / id 时 400；items 条数不对时 400；这些拒绝都在旁路之前，平台链没有记录。契约 12 条路径与发布契约 DeepEquals 一致，RT-006 准入沿用 TenantOperationsTests。
    - 验收 2：重置经 `IIdentityAccounts.ResetPasswordAsync`。旧密码报 INVALID_CREDENTIALS，会话清空，临时密码登录得到 PasswordChangeRequired。租户链的 admin.reset-password 只有成员指针；平台链有 5 条 reset-credential 旁路记录；两条链都没有密码。元数据中 assign-admin、reset-admin-password 均为 expose=false、requiresConfirmation=true。页面的两处二次确认由 E2E 与突变确认。
    - 验收 3：E2E 里，A 的管理员在开户抽屉里新建，B 的管理员按登录标识查找后选定。两人经 `/api/identity/login` 登录（含首次修改初始密码），me 与目录成员都只有本租户；带 tenant_id 参数的越权尝试也一样。重置与更换都走页面。
    - 验收 4：src 只引 yue-core、yue-data、yue-form、yue-sdk，没有 fetch、浏览器存储、iframe、原生表单或表格。E2E 断言 localStorage 与 sessionStorage 为空、没有 iframe、URL 不含令牌、`/api/tenancy` 请求不带 Authorization。
  - 偏离 ①–④：四项都维持，裁决与理由见 docs/decisions/key-decisions-v0.md 的 R141。
  - 非阻断（记录）：
    - 开户接口的管理员资格与替换接口口径不同（见上面的探针）：平台身份可以成为租户成员并持 tenant.owner，与 Q12「平台超管对租户不可见」相左。页面的查找账号已滤掉平台身份，但会列出停用和锁定账号，开户抽屉可以选它们。建档 S1-TEN-016 跟进，含上面存活突变的用例。
    - 交付日志 ⑤ 写「分别向 IDP-003、AZ-003 登记」，但两份任务文件里都没有登记行。复核补在 S1-IDP-003（`SetTenantAdministratorAsync`，替换用 `CreateMembershipAsync`）和 S1-AZ-005（`ITenantRoleGrant.RevokeAsync`）。授权 API 由 AZ-005 建在这个端口上，TEN-003 的 `AssignAsync` 也登记在那里。
    - 重置不持租户锁，与并发的替换之间有很窄的先查后改窗口。两边都是平台超管，影响小。
    - 重置作用于自然人全局，但只有路径所在租户的链上有 admin.reset-password；他所属的其它租户链上没有。平台链的旁路记录带租户与成员路径，README 已写明。
    - 偏离 ④ 所说的「同一份开户请求重复提交仍幂等」在页面层没有用例；后端开户幂等有 IT。
    - 查找账号接口在请求体带租户字段时返回 400，这一点没有单独断言。它与其余四个接口是同一机制，契约用例已覆盖 Schema。
