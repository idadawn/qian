## 背景

S1-DEC-024 / R110 从 S1-TEN-005 移出的三块运营后台功能：

- 管理员维护：PRD 7.3 API 行的 `GET/PUT /api/tenancy/tenants/{id}/admins`，此前没有任务承接。单管理员，计入用户配额（补充裁决 Q12）；`tenant_admins` 只存 Membership 指针，Membership 与凭据归 `qian.identity`，`qian.tenancy` 不直写身份表（S1-TEN-003 / R96 同口径）。建立或绑定 Membership 用 S1-TEN-003 已登记、由 S1-IDP-003 提供的 `ITenantMembershipProvisioner`；替换管理员时原管理员授权怎么处理，按 PRD 13 与 Q12 在实现前写进任务日志，偏离写「建议裁决」。新建租户表单的管理员改为经 `qian.identity` 选择或创建，取代 S1-TEN-005 期间按契约直填 `membershipId` / `subjectId` 的做法。
- 重置密码：PRD 13 权限矩阵里平台运营的「管理员重置密码」（S1 最小）。重置经 `qian.identity` 的端口执行；S1-IDP-003 交付时若没有该端口，由本任务在 `Qian.Identity.Abstractions` 加端口、identity Provider 实现并向 IDP-003 登记（R96 同例）。
- 权益授予：租户详情里的「授权（调 7.14）」，消费 S1-ENT-001 的 `PUT/DELETE /api/tenants/{id}/entitlements/{plugin}` 与 `GET /api/tenants/{id}/entitlements`。

页面沿用 S1-TEN-005 的页面包，只用 SchemaForm、DataTable 与 PlatformClient。

## 验收

- [ ] IT：`GET/PUT /api/tenancy/tenants/{id}/admins` 只对平台主体开放（S1-AZ-003 超管旁路 + 审计，与 S1-TEN-006 同一路径），租户主体 403 `AUTHZ_DENIED`、无凭据 401，请求体含 `tenantId` / `tenant_id` / `id` 返回 400；PUT 经 `qian.identity` 端口建立或绑定该租户的管理员 Membership（满额返回 `CARDINALITY_USER_LIMIT`），更新 `tenant_admins` 指针并经 `ITenantRoleGrant` 授予 tenant.owner；端点进组件 OpenAPI 契约并过 S1-RT-006 准入
- [ ] IT：平台运营重置租户管理员密码经 `qian.identity` 端口执行，旧密码立即失效、下次登录被强制改密（S1-IDP-003 的初始密码语义），写审计；该操作标 `humanOnly` + `confirm`（PRD 7.4 Agent 契约），页面有二次确认
- [ ] E2E（R81 / R110，自 S1-TEN-005 转来）：运营后台新建租户 A、B 时经 `qian.identity` 选择或创建管理员，两位管理员经统一登录流水线登录后各自只看到本租户数据
- [ ] E2E：租户详情里授予、撤销一个组件的权益（S1-ENT-001 的运营 API，二次确认），页面结果与 `GET /api/tenants/{id}/entitlements` 一致
- [ ] 代码审查：页面只用 `@yue/form` SchemaForm、`@yue/data` DataTable 与 `@yue/sdk` PlatformClient，无第二套实现；令牌不在 localStorage、URL 与 iframe 中
