## 背景

配置契约里的 `patternProperties` 决定哪些动态键带敏感标记。两处 .NET 消费方都按 .NET 默认方言、区分大小写匹配：

- `SecretSafety`：Apollo 快照与 CI 门禁共用；
- `ProfileLoader.Sensitive`：profile 条目配置，同一份配置先经 JsonSchema.Net 按 ECMAScript 方言验证。

由此有两类漏报，旧构建与 S1-CFG-005 之后行为相同：

- 方言：JSON Schema 2020-12 规定模式按 ECMA-262 解释，.NET 默认方言的 `\w`、`\d`、`\s` 认 Unicode，否定简写匹配得更少。已验证：模式 `^\W+$` 遇键 `é`、`^\D+$` 遇阿拉伯-印度数字键、`^\S+$` 遇含 U+0085 的键时，按 ECMA-262 应判为敏感，扫描却没有诊断。
- 大小写：`IConfiguration` 的键不区分大小写，`IQianPlugin<TConfig>` 也按 `JsonSerializerOptions.Web` 不区分大小写绑定 profile 配置。`SecretSafety` 的固定属性名已不区分大小写，动态键却区分：`Endpoints:Legacy_billing` 不被 `^legacy_` 标记，应用按 `legacy_billing` 读取仍拿到明文。`ProfileLoader` 连固定属性名也区分大小写。

S1-AUD-006 已为审计脱敏写了严格的方言翻译（Qian.Audit 内部的 `AuditPattern`），按依赖图门禁配置包不能引用它。2026-10-14 经用户确认：

- 翻译器改为共享的内部源文件，编译进需要它的包，不新增公开 API、依赖或包；
- 本任务修 `SecretSafety` 与 `ProfileLoader`，CLI 的 `profiles.ts` 只在 PR 中记录差异；
- 配置的动态键改为不区分大小写并失败关闭：与之相等（OrdinalIgnoreCase）的任一键名能匹配，即算匹配。

- [x] 匹配仍为 NonBacktracking、超时有界并复用编译实例，引擎、超时与缓存只在共享文件定义一处
