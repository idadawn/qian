## 背景

S1-TEN-007 五条验收成立（复核 claude，2026-10-17）、S1-TEN-008 四条成立且一条退回（A1，见该任务），两轮复核的非阻断建议汇到本任务。TEN-007：`TenancyConfigurationTests` 的 13 项 Apply 负例缺「清单项超过 384 字符」「resolver 未知子键」「mode 非字符串」三类，`TenancyPlugin.ReadConfiguration` 对应分支无用例；`AuthorizedHandlerRegistration` 新增的 Kun `PermissionBehavior` ServiceType 守卫只被正向用例间接覆盖；`HookCapabilityRegistration` 的 sideEffect 门在 `Enter` 之后，被拒的 destructive / external 能力也会占掉本次派发的一次性槽位；Tenancy README 的排查说明没写从步骤表读 `04:provisioned` 的 Reason，也没说明二次 Enter / 不在清单 / destructive 三种拒绝同为 `AUTHZ_DENIED`；样例 README 未记录宿主读取的 `Tenancy:Resolver:*` 与 `Tenancy:InitializationCapabilities` 配置节；`租户九个服务键符合单段语法且不重名` 是纯 UT 却挂在依赖 PostgresFixture 的 partial class 里。TEN-008：契约变异只注入请求 schema 顶层 `properties`，`parameters[]`（query / path）不在扫描范围，`?tenantId=` 不会被门禁拦下；`TenantContractSchemaTests` 的词表与遍历是 RT-020 `CapabilityContractCompiler` 规则的复制（且跳过 example / examples / default 键的口径不同）；`[DisallowNull]` 在 HTTP 请求体路径没有运行时效果，显式 `null` 直达处理器，非空全靠端点 validate；`Respond` 的 400 先于旁路 403（R113 接受，README 未写取舍）；租户主体 403 与上下文不匹配 404 不记结构化日志；`[Range(0, int.MaxValue)]` 让快照 `skip.maximum = 2147483647`，属性与手写分页校验重复维护；默认 `take = 50` 只在契约 default 里断言、无端到端成功调用；`AspNetCoreHttpContractSource` 的 DisallowNull / IsSetNullable 去 null 变换对响应 DTO 同样生效；契约快照门禁只有 qian.tenancy 一份，CRM 的 rest-v1 现场生成无快照，其它组件原生 HTTP 契约的导出规则变化不会被任何门禁发现（既有问题）；`TenantOperationsHost` 放在业务样例 `samples/Qian.Sample.Crm` 而 `tools/Qian.Dev.TenantOps` 反过来依赖样例取宿主工厂，业务样例与平台装配边界变模糊。

## 验收

- [ ] UT：`TenancyConfigurationTests` 补清单项超长、resolver 未知子键、mode 非字符串三类 Apply 负例；`AuthorizedHandlerRegistration` 的 ServiceType 守卫补负例（最后一个描述符不是 Kun `PermissionBehavior` 时抛 InvalidOperationException）；服务键语法 UT 挪出依赖 PostgresFixture 的类
- [ ] 代码：`HookCapabilityRegistration` 的 sideEffect 门移到 `Enter` 之前，被拒的 destructive / external 不占一次性槽位（补用例：被拒后同一能力仍可被合法 hook 消费一次）；`Respond` 对租户主体 403 与上下文不匹配 404 也写结构化日志（reason 如 tenant_principal / context_mismatch，不进响应）；分页校验在 `[Range]` 与手写校验之间二选一，`skip` 不再把 int.MaxValue 写进契约
- [ ] UT：租户字段门禁覆盖嵌套层级（如 `administrator` 内部）与 `parameters[]` 的名称与 schema；词表与遍历抽到共享位置与 RT-020 的 `CapabilityContractCompiler` 复用同一常量与跳过口径；`AspNetCoreHttpContractSource` 的去 null 变换限定到请求体 schema；补一次无参 `GET /api/tenancy/tenants` 成功断言（默认 take = 50）
- [ ] 文档：Tenancy README 补排查说明（从 `GetStepsAsync` / 步骤表读 `04:provisioned` 的 Reason；三种拒绝同为 `AUTHZ_DENIED` 时的区分方法）、R113 的校验顺序取舍与「DTO 标注只服务契约、非空由端点校验」的分工；样例 README 记录 `Tenancy:Resolver:*` 与 `Tenancy:InitializationCapabilities` 配置节；把「其它组件原生 HTTP 契约无快照门禁」与「TenantOperationsHost 放在业务样例」两个边界问题写成一条给产品负责人的决策请求（本任务不自行推广或迁移）
