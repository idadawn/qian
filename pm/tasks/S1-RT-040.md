## 背景

R144 ③（产品负责人 2026-11-11 在 S1-DEP-009 执行会话选推荐项）：platform profile 预装的六个平台组件以平台宿主的 profile 装配与集成测试为启动证据去掉 x-skeleton，安装路径是平台镜像预装，不经 qian add。这是对 S1-DEC-018 / R100 去标口径的限定例外；qian add 独立安装这道门没有过，由本任务补上。qian.tenancy、qian.authz、qian.audit 走这道门（清单至今没有 runtime.nuget）；qian.registry、qian.capabilities、qian.lifecycle 是 policy.required 的平台组件，只在平台宿主里运行，不提供独立安装，不在本任务范围。做法照 S1-IDP-015 与 S1-FILE-004：从 main 触发 dotnet-release 锁步发布包源里还没有的新版本，清单钉版本与归档 sha256 摘要，私有源 E2E 加入这三个组件。

## 验收

- [ ] 发布：S1-DEP-009 合入后从 main 触发 `dotnet-release`，锁步发布一个包源里还没有的新版本；`Qian.Tenancy`、`Qian.Authz`、`Qian.Audit` 及其 Abstractions 能从私有源还原
- [ ] 清单：三个组件的 `runtime.nuget` 钉版本与归档 sha256 摘要；同一项目里依赖的 qian.data / qian.events 等一并钉到同一版本，不出现新旧版本混用
- [ ] E2E：私有源 E2E（`packages/qian-cli/test/private-feed.e2e.mjs`）加入这三个组件。`qian add` 后表面进 `.qian`，NuGet 按清单钉版且只从私有源还原，lock 记录摘要；宿主按清单入口挂载组件，组件就绪；`qian remove` 逆序撤销
- [ ] 文档：三个组件的 README 安装说明改为可经 `qian add` 安装，并写明平台镜像预装与 `qian add` 两条路径的区别
