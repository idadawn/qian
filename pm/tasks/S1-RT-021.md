## 验收

- [ ] 聚合 OpenAPI 与文档站：`packages/Qian.Capabilities/CapabilityOpenApi.cs`（第 43、53 行附近）为写类能力的 invoke 路径在 `default` 响应描述与 `Idempotency-Key` 参数描述补 409 `CAPABILITY_REPLAY_UNAVAILABLE`（两种 reason：`response_too_large`、`data_classification`），IT 断言 `/api/capabilities/openapi.json` 文本含该码；`website/docs/sdk/dotnet/capabilities.md` 第 37 行补「未知分级也不保存」
- [ ] 两处说法更正：`packages/Qian.Capabilities/README.md` 回执策略段、迁移 `Migrations/20261014170738_InvokeReceiptLimits.cs` 注释、组件规格 §9.5 与 PRD 7.2.1 中「24 小时后被清理」改为「过期后不再回放，物理删除靠本租户后续带键写调用登记时的惰性清理（每次最多 100 行）」；NOT VALID 的理由改为「存量超限行会让带校验的约束失败，而迁移属主在 FORCE RLS 下删不掉这些行；DDL 校验本身不经 RLS」；`docs/ops/configuration-runbook.md` 补一条：长期没有带键写调用的租户，过期回执靠运维清理（给出 SQL）
- [ ] 登记期检查的装配：`packages/Qian.Capabilities/README.md`「登记期契约检查」段与 `docs/ops/configuration-runbook.md` 部署步骤写明 platform profile 宿主必须调用 `AddQianCapabilities()`，否则退化为首次调用时编译；TCK 平台组合包宿主（R68）加一条断言：容器里解析到的 `ICapabilityContractCheck` 为宿主单例，且不合格契约在该宿主下于登记期被拒（S1-RT-014 验收已登记装配本身，本任务只加断言与说明）
- [ ] 数据分级标注：组件规格 §9.5 与 README 提醒作者按 `dataClassification` 标注能力，写明 SDK 默认 `internal` 即默认保存响应体；`samples/Qian.Sample.Crm/CrmCommands.cs` 中含个人信息的能力（`customer.create` 等含 Name 的）标为 `pii`，IT 同步：含 Name 的响应不再入回执、同键重放 409 `data_classification`；PRD 7.2.1 一句同步
- [ ] 测试补强：恰好等于 `receiptMaxBytes` 的响应保存；`receiptMaxBytes = 0` 端到端从不保存；`public` 分级的保存路径；`pg_constraint.convalidated = false` 钉住 NOT VALID；`entry-invalid` / `contract-invalid` 两条规则的单测；Registry → SDK 端到端（经 Registry 装载不合格组件，断言 `RegistryScopeApplyException` 的原因码为 `INPUT_INVALID`、`InnerException` 为 `CapabilityContractException`）
- [ ] 工程细节：`CapabilityInputValidator` 校验器缓存满 1024 后不再整表清空，改按条目淘汰（LRU 或按 `schemaSha256` 单条替换），保持登记期预编译口径；`RegistryScopeReconciler` 原因码守卫正则改为 contracts/v0 的码格式 `^[A-Z][A-Z0-9]*(_[A-Z0-9]+)*$`；`CapabilityInputValidator.Validate` 中三类之外的求值异常记录带插件 ID 与能力名的日志后再交给 ErrorDetail 中间件
