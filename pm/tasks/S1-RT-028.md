## 背景

S1-RT-024 的 PR（idadawn/qian#111）CI 里，`GrpcReflectionTests.真实认证HTTP2反射与实际RPC一致_声明类型漂移拒绝_匿名不能探测` 偶发失败：匿名探测期望 `Unauthenticated`，实际得到 `Cancelled`（dotnet.yml run 38703725538 第 1 次尝试，头提交 36ceae8f7）。本机同一提交连跑 8 次都通过，最近 12 次失败的 dotnet.yml 运行里也没出现过。读 Grpc.Net.Client 2.67.0 源码：服务端认证拒绝后 Kestrel 回 401 并以 RST_STREAM 结束请求流；客户端此时若正在写请求流，写入因请求体被取消抛 `OperationCanceledException`，`HttpContentClientStreamWriter.WriteAsyncCore` 用 `CreateCanceledStatusException` 换成 RpcException。若这时 401 响应还没处理完、调用状态尚未写入 `CallTask`，状态就退成 `Cancelled`；读响应流（`MoveNext`）则会等到调用的最终状态，抛出 `Unauthenticated`。探测器把写请求时的取消直接当成结果，凭据错误于是被报成取消，挂载失败的诊断会把运维引向超时或网络问题。

## 验收

- [x] 复现：单测用自定义 `CallInvoker` 确定性地构造「写请求失败先于调用状态就绪」：双向流写入抛 `Cancelled`，读取抛服务端的最终状态（`Unauthenticated`）。修复前该用例失败，与 CI 现象一致；另在真实 HTTP/2 认证宿主下循环匿名探测，记录修复前后 `Cancelled` 的出现情况
- [x] 修复：`GrpcReflectionContractProbe` 写请求流失败（`Cancelled`，或传输层 `IOException` 及其子类 `HttpProtocolException`），而调用方的取消令牌没有触发时，读响应流取得调用的最终状态并以它报错；调用方自己取消仍报 `Cancelled`，截止时间到期仍报 `DeadlineExceeded`，读不到失败状态时保留原异常。单测逐一覆盖这些分支（Grpc.Net.Client 2.67.0 的 `CompleteAsync` 只在写入未完成时报错，不涉及这一时序）
- [x] 回归：原用例 `真实认证HTTP2反射与实际RPC一致_声明类型漂移拒绝_匿名不能探测` 循环运行稳定通过；`Qian.Capabilities.Tests` 与全量 `dotnet test` 通过
- [x] 文档：`packages/Qian.Capabilities/README.md` 的探测段写明服务端提前结束调用时按最终状态报错
