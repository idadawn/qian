## 背景

组件 `qian.observability`（`Qian.Observability.Abstractions` + `Qian.Observability`，随 SDK）：`AddQianObservability()` 一行装配 + 网关宿主接入；baggage `tenant.id / user.id / membership.id / plugin.id / principal.kind` 在租户中间件、消息订阅器、作业执行器三处写入，`agent.id / run.id` 预留；`traceparent` 贯通 HTTP、gRPC、RabbitMQ 头与作业参数；日志结构化（`tenant_id`、`trace_id`）；指标前缀 `qian_`；`PgHealthCheck / RedisHealthCheck / RabbitMqHealthCheck / ApolloHealthCheck` 聚合到 `/readyz`；OTel 语义约定文档。

## 验收

- [ ] E2E：外壳一次请求 → 网关 → platform → RabbitMQ 消费 → 作业回调，在 Tempo 中为一条 trace，每个 span 带 `tenant.id`
- [ ] E2E：拔掉 RabbitMQ 后 `/readyz` 503、`/healthz` 200；恢复后 `/readyz` 200
- [ ] UT：三处写入点（中间件、订阅器、作业执行器）均设置 baggage；日志行含 `tenant_id` 与 `trace_id` 字段
- [ ] 文档：OTel 语义约定（baggage 键、指标前缀、span 命名）入开发手册
