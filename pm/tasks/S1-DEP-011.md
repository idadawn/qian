## 背景

S1-DEC-033 D2 的落地任务。产品负责人 2026-11-11 选 A「平台身份同进程」（R143，ADR-017 §10），本任务不再等该决策任务的其余项，前置只剩 S1-DEP-009。

目标是让里程碑的第一步「多租户可用」在集群上成立：平台运营登录平台控制台，开户一个租户，租户管理员登录并进入工作台。形状照联调环境（`scripts/dev-shell.sh`）与集成测试已验收的装配：身份服务与平台运行时同一个进程，身份请求走自己的分支；网关是独立进程。区别是用生产入口，不带开发路由、种子与开发期发件箱。

范围：

- 宿主：在 S1-DEP-009 的平台宿主上并入身份分支，装配方式与 profile 落位开工时定并记进 S1-DEC-033。网关用 `hosts/Qian.Gateway.Host`，托管外壳与远程制品，路由按前缀分簇。
- 镜像：两个镜像经 `scripts/images.py build` 构建，按 digest 引用，非 root、只读根文件系统。完整的三镜像供应链复验仍归 S1-DEP-008。
- 清单：手写 Kustomize，进部署仓库经 PR 合入。命名空间、专属 PG / Redis、默认拒绝的网络策略与配额用 S1-DEP-001 已就绪的基线；节点落位、更新策略与资源上限按集群当前容量定。
- 数据：迁移先于应用启动执行；平台审计登录与平台授权登录按 S1-DEP-005 验收里列的装配要求创建。
- 入口：外壳与身份发行方各有 https 主机名。首个平台运营账号的引导方式写进运维手册，不用开发种子。

不在范围：Argo 发布链、`qian pack` 生成清单、RabbitMQ 与 Apollo 联调、三宿主拆分。本任务不替代 S1-DEP-005 的发布门（S1-DEC-016）。

## 验收

- [ ] `qian-staging` 里「平台 + 身份」Pod 与网关 Pod 就绪；镜像按 digest 引用、非 root、只读根文件系统；清单在部署仓库经 PR 合入，无 `:latest`
- [ ] E2E（在 staging 上）：平台运营经外壳登录进入平台控制台，开户一个租户并激活；该租户管理员登录、选择租户后进入工作台；另一个租户的管理员看不到它的数据
- [ ] E2E：自助申请按 S1-DEC-033 D4 的裁决验证。发件不可用时发码返回 503 且运营开户不受影响；有发件实现时走完申请到审核通过
- [ ] 检查：不存在 `/__dev/` 路由、开发种子与开发期发件箱；运行期连接只用受限角色；密钥只经 Secret 注入
- [ ] 检查：迁移在应用启动前完成；平台审计链与平台授权登录已配置，平台超管旁路可用且写平台审计链
- [ ] 运维手册：部署、回退、首个平台运营账号引导，以及相对 PRD 7.17 三镜像形状与发布链的已知差异，写入 `docs/ops/`
