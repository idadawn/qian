结论：12 项真完成（S1-KUN-003 / 007 / 011 / 013、S1-RT-003 / 010 / 016、S1-AZ-001、S1-CFG-001、S1-DEC-014 / 015 / 016）；8 项基本完成但有口径偏差（S1-KUN-004 / 012、S1-QA-002、S1-CFG-002、S1-DATA-001、S1-DEC-017 / 018、S1-YUE-004）；1 项证据不足（S1-DEP-001）。代码与测试普遍扎实，问题集中在口径、文档与留痕。

## 裁决（Claude 在产品负责人授权下裁决，未经逐条确认）

- **R65 Kun 同日修复版与精确钉定**：`-hotfix.N` 是推送 nuget.org 的正式修复，但 NuGet 按预发布排序、低于同日无后缀版本；Qian 的 `Kun.*` 一律以 `[$(KunVersion)]` 精确钉定，不依赖最新稳定版排序；钉在修复版上时，Kun 下一个无后缀正式版发布后升级回来——本次 Kun 补发 2026.10.13（S1-KUN-014），Qian 随之升级。写入 ADR-021 D21.3 补注、ADR-001 D1.3、docs-site.md（R62 旁）、`NuGet.config`、产品族页与 README、版本矩阵说明、with-qian。「发布同日修复版之后，下一个工作日补发无后缀正式版」已于 2026-10-13 由产品负责人拍板写进 Kun 发版规则（[idadawn/kun#58](https://github.com/idadawn/kun/pull/58)，仅文档，已合并）。
- **R66 受保护请求的运行期兜底**：S1-AZ-001 的 QIAN0005 只管编译期，反射注册可绕过；Kun 2026.10.13 起 `KunMediatorBuilder` 构建时拒绝漏装 `AddPermissionBehavior` 的受保护请求，首次解析 `ISender` / `IPublisher` 即失败、处理器不执行（S1-KUN-014，kun#57）。Qian 升级后补反射绕过的回归。
- **R67 CFG-002 门禁口径**：「CI 门禁」是 `dotnet` 工作流对仓库全部 profile 的生效配置执行 `Qian.Secrets.Tool --profiles`（门禁自测含注入明文的反例）；线上 Apollo 值由 Kun 运行期逐 namespace 拒绝明文，发布前用 `--apollo` 扫描候选。公开引用以组件规格 §11.3 为准（`secretRef://<scope>/<path>`），`secretRef://k8s/<ns>/<name>#<key>` 只作可信引导的底层定位；PRD 7.8 同步。分工表在 `docs/ops/configuration-runbook.md`。
- **R68 QA-002 的 T23 口径**：platform 宿主是 TCK 生成的组合包 `qian.bundle.tck-platform`（真实 Registry / Capabilities），不是交付的 `profiles/platform`；Provider 组是 CRM 样例组合。ADR-019 D19.8 第二条点名的 Files / Authz / Identity.Client 平台模式对照由 S1-QA-003 / S1-QA-005 承担。写入 QA-002 验收第 6 条、组件规格 §10.2、ADR-019 D19.8 注与 QA-003 日志。
- **R69 DEC-018 与 QA-002 / RT-011**：DEC-018 §3「QA-002 总目标继续保持未完成」指 cody 会话里以 QA-002 编号跟踪的八项任务目标，不是 S1-QA-002 的验收；S1-QA-002 的 6 条验收不含代码包安装，关闭不受约束。DATA 安装门由 RT-011 / RT-014 承担，S1-RT-011 的 depends 加 S1-RT-014。
- **R70 DEC-014–018 的批准留痕**：五份裁决记载的「产品负责人确认 / 批准」只有 cody 自述，仓库内没有产品负责人本人的留痕。在产品负责人补确认之前按仓库惯例视为默认裁决：继续生效，不回退据此调整的验收（S1-KUN-004、S1-DEP-001、S1-DATA-001 等），有异议时新建决策任务。各 DEC 文件加复核备注，`docs/decisions/key-decisions-v0.md` 补登记 DEC-012–019。
- **R71 日志署名与建档顺序**：`pm.py set` / `pm.py add` 缺 `--by` 且无 `PM_ACTOR` 时报错，`pm.py validate` 拒绝署名为 someone 的日志；历史 36 行按引入提交改回实际代理名（cody 30 行、claude 6 行）。任务先以 todo / doing 建档再交付，不在创建提交里直接 done 并勾满验收（S1-KUN-011 / 012 是反例）；写入 AGENTS.md 与 pm/README。
- **R72 YUE-004 收尾**：文档站换用令牌包由既有任务 S1-DOCS-004 完成（删除占位 `website/theme/yue-tokens.css`、`theme/index.css` 导入 `@idadawn/yue-tokens`、删除 data-theme 桥接脚本；令牌包把颜色存成 oklch 分量，文档站的颜色映射改写成 `oklch(var(--yue-<role>))`，照搬旧写法时背景等颜色计算为无效值）；yue 规格 §14「令牌与主题」三项按 PR #32 证据勾选，§3.5 暗色选择器写成实现的 `html.dark, html[data-theme="dark"]`，并写明颜色令牌的消费写法；ADR-013 D13.13 补实现落点。
- **R73 DEP-001 的证据边界**：2026-10-13 经 `ssh qd` 只读核验能确认的事实与不能确认的事项分别记入 S1-DEP-001 日志；核验期间 apiserver 间歇返回 ServiceUnavailable。背景里的 Harbor OCI 制品与按 `permissions.egress` 动态放行分别由 S1-RT-013、S1-DEP-004 承担。
- **R74 状态与措辞对齐**：with-qian 修复状态表补齐 S1-KUN-003 / 004 / 007 与 7.1 之外的 S1-KUN-011–014；PRD 7.1 第 4 项注明 `client_credentials` 签发端点已按 ADR-010 D10.5 移交 `qian.identity`；RT-003 验收第 2 条注明由共用 TCK T12 覆盖；RT-016 背景改为实际的市场登记位置；fixture 自测残留的 `app.tenant_id` 改为 `app.current_tenant_id`；CFG-001 无缓存失败用例补原因断言；本机全量测试前置写进 `tests/README.md`。
