# 与 Qian 的关系

本页是「Kun 框架」小节里唯一由 Qian 手写的一页，其余页面都按锁定版本从 kun 仓库镜像（[ADR-021 D21.4](/pr-preview/pr-50/design/adr/adr-021-product-family-structure.md)）。它回答：写 Qian 组件时，Kun 的哪些模块会用到、用哪一套 API、哪些写法被禁止。

## 定位

- **三层**：Kun 是框架层（底座 SDK），Qian 是平台层，yue 是前端层。Qian 平台基于 Kun 框架构建；Kun 不是 Qian 的子项目，Qian 也不是 Kun 的扩展（[ADR-021 D21.1](/pr-preview/pr-50/design/adr/adr-021-product-family-structure.md)）。
- **Kun 是实现依赖，不是平台内核**：Qian 的运行时 `Qian.Runtime` 与平台插件自成一层，Kun 模块是它们的实现依赖；Kun 的 `AddKunXxx()` 模块在 Qian 里被包装为插件，`Kun.*` 本身不改（[ADR-001 D1.1](/pr-preview/pr-50/design/adr/adr-001-kun-relationship.md)、[ADR-020 D20.10](/pr-preview/pr-50/design/adr/adr-020-component-model-v2.md)）。
- **锁版本消费**：Qian 以 NuGet 包 + CalVer 锁版本消费 Kun，不复制 Kun 源码、不用 `ProjectReference`（ADR-001 D1.2）。版本只写在仓库根 `Directory.Packages.props` 的 `KunVersion` 一处，全部 `Kun.*` 包引用它；本小节其余页面与 [Kun API 参考](/pr-preview/pr-50/sdk/api/kun/index.md) 按同一版本镜像，各页顶部写明版本（[ADR-021 D21.3](/pr-preview/pr-50/design/adr/adr-021-product-family-structure.md)）。
- **以代码为准**：Kun 文档与代码不一致时以代码为准，文档声称但代码不存在的能力不当作已有（ADR-001 D1.8）。

## canonical API

Kun 里有几组功能重叠的「双胞胎」API，Qian 各选定一套，插件只能用这一套（ADR-001 D1.5、§07 7.1「插件化定位」）：

| 能力       | Qian 选用                                                                                              | 不用                                                   |
| -------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| 租户上下文    | `ITenantContext` 的 AsyncLocal 实现（唯一实现；JWT 版退化为它的解析源），claim 名 `tenant_id`                             | 第二套 `ITenantContext` 实现                              |
| 文件存储     | 新线 `Kun.Storage.Abstractions` 的 `IFileStorage` 与 Local / S3 / Oss 后端                                 | 旧线 `Kun.Storage`                                     |
| 审计       | 同事务写 `AuditLog` + Outbox 事件，PostgreSQL 哈希链（[ADR-009](/pr-preview/pr-50/design/adr/adr-009-audit.md)） | `AuditSaveChangesInterceptor`                        |
| S2S 令牌签发 | 网关的 `S2sTokenIssuer` 一套（[ADR-010](/pr-preview/pr-50/design/adr/adr-010-gateway-layers.md)）           | `Kun.Identity.KunJwtIssuer`、`Kun.Security.S2SJwt`    |
| 限流       | 服务侧 `Kun.RateLimit`；网关侧三策略 + Redis 共享计数                                                              | —                                                    |
| 仓储       | `DbContext` + `Kun.EntityFrameworkCore` 的 `IUnitOfWork`                                              | `Kun.Infrastructure` 的 `IRepository` / `IUnitOfWork` |

这些选择会写进 `Qian.Plugin.Sdk` 的分析器：插件作者用错即编译失败（§07 7.1）。

## 强制装配与禁用项

Kun 的安全默认值大多是 opt-in；在 Qian 里改为**强制装配 + 构建期检查**（ADR-001 D1.5）。以下是 S1 的目标形态，随对应任务落地：

- **强制装配**：RLS 连接版与事务版拦截器、租户模型缓存键（`KunMultiTenantModelCacheKeyFactory`）一起挂上，忘记替换模型缓存键的 `DbContext` 拒绝启动（§07 7.1 第 1 项、7.6）；生产模式的租户解析禁用 `X-Tenant-Id` 请求头兜底与默认租户回退，失败即拒绝；网关回退认证策略默认「要求已认证」，路由级限流真正绑定到路由（7.1 第 4 项）。
- **禁用**（Banned API，引用即编译错误）：`Kun.Infrastructure.IRepository`、旧线 `Kun.Storage.IFileStorage`（7.1 第 13 项）；废弃的两套 S2S 签发器（7.1 第 7 项）；`Kun.Audit.EntityFrameworkCore.AuditSaveChangesInterceptor`（7.1 第 8 项）。
- **AOT**：`platform` profile 不承诺 AOT，业务服务一律 JIT；`gateway` 等边缘 profile 可 AOT（ADR-001 D1.5、ADR-020 D20.10）。

1. 上游 PR 优先：改动提到 kun 仓库，Kun 发版后改 `KunVersion` 升级，本小节随之更新。

## 版本与升级

- 当前锁定的版本写在本小节每页顶部的横幅里，与 `Directory.Packages.props` 的 `KunVersion` 一致；CI 比对二者，不一致即构建失败。
- 升级 Kun：改 `KunVersion` 一处 → TCK 两种模式通过 → 本小节与 API 参考在下一次构建时自动镜像新版本（ADR-021 D21.3）。
- 要改 Kun 的代码或文档，去 kun 仓库提 PR，Qian 的任务里只回链。
