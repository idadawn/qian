    #§13 权限与安全

    本页由构建脚本镜像自仓库 docs/prd/13-security.md，请修改源文件，不要改本页。

    状态：草案 v0（2026-10-06）。依据：ADR-004（数据库与隔离）、ADR-005（身份）、ADR-006（鉴权）、ADR-007（Apollo）、ADR-009（审计）、ADR-010（网关）、ADR-002（插件模型）、ADR-020（组件模型 v2）、ADR-016（iClaw 边界）、ADR-017（部署）、ADR-018（阶段）及补充裁决。本章是平台的可信计算基规范：描述目标态；Kun 当前缺口写成「过渡态（2026-10）」并集中在 §13.14。

    四条总原则：

    1. 身份 ≠ 授权：身份记录结构上不携带授权载荷；授权来自判定端口 + 委托链 + 运行时授权快照。
    2. 租户只来自令牌：任何入口（HTTP、gRPC、消息、作业、Agent）都不信任请求头或默认值。
    3. 缺省拒绝、确定性控制优先：没有权限点声明的端点不可达；安全控制不依赖检测器或模型判断。
    4. 一个权限引擎服务三个入口：UI、API、MCP 使用同一判定服务；低代码数据引擎在唯一入口做三段式校验。

    #13.1 角色与主体模型

    #13.1.1 主体类型

    主体类型载体凭据阶段
    userPerson（全局自然人）+ Membership（租户成员）密码 / 短信 / TOTP / 上游连接器断言S1
    service平台服务、平台插件（原称系统插件）、ISV runtime.form: service 组件、外部系统的 OAuth clientclient_credentials；网关换签的 S2S 令牌；K8s ServiceAccount（工作负载身份）S1
    agent有归属人、可吊销的 Agent 客户端RFC 8693 令牌交换，令牌带 act 链S1 字段预留 / S4 启用
    system平台自身的定时任务、状态机迁移、迁移 Job内部服务身份，审计 actor_type=systemS1

    一个请求的审计主体链写法：actor（实际执行者）+ on_behalf_of（代表谁）+ channel（来源通道 UI / API / MCP / A2A / job / event）。人直接操作时 actor = on_behalf_of。

    #13.1.2 角色权限表

    角色以租户为域（平台角色的租户为空）。「能做」是该角色内置权限点的上限，具体授权仍要经 §13.2 的 L1–L6 判定。

    角色域能做不能做对租户的可见性阶段
    平台超管平台创建 / 冻结 / 注销租户；平台级配置与密钥引用；平台插件修订与回切；查看全平台审计；旁路租户权限（策略显式声明、每次审计）以租户成员身份出现在业务数据中；绕过审计；读取密钥明文对租户不可见，审计可见；不计入租户配额（Q12）S1
    平台运营平台租户主档 CRUD、开通白名单、套餐下发、管理员重置密码、运营看板、审核自助申请、市场审核台读取租户业务数据；修改平台插件；旁路租户权限不可见S1 最小 / S3 完整
    平台开发者平台用 SDK 开发官方插件、出修订、跑 TCK、在开发者租户调试直接向生产租户安装未签名制品；访问他人租户数据仅开发者租户S1
    ISV平台（外部）入驻、上传声明式表面、package / function / 受限 ui 与 seam Provider 组件（原 connector）、查看自己制品的审核与安装统计、席位与分成上传任意代码容器（Q9）；访问安装方租户数据；修改已批准能力的描述或 Schema 而不触发复审不可见S3
    租户管理员租户组织 / 岗位 / 用户 / 角色 / 授权；挂载（租户 scope patch）已授权插件 / 应用并批准反向权限；租户级登录与密码策略、IdP 连接器（S3）；查看本租户审计；强制下线；工作交接创建租户；跨租户操作；修改隔离策略；读取密钥明文；删除审计本租户S1
    业务搭建者（租户开发者）租户建应用、设计表单 / 列表 / 流程、发布、生成菜单与权限资源、配置数据接口（SQL 文本模式需额外高级权限）、打包导出 template授予自己没有的权限；绕过发布流程直接改线上元数据；配置出网域名（需管理员批准）本租户内其拥有 / 被授权的应用S2
    终端用户租户使用被授权的应用、菜单、按钮、字段、数据范围；发起 / 处理审批；管理个人中心与偏好一切未授权项（缺省拒绝）本租户内授权范围S1
    Agent 主体租户（有归属人）委托人权限 ∩ 授予 scope 内的读与可逆写；发起申请类动作；查询 Check / ListAllowedActions / Explain标 humanOnly 的动作（签名、签章、转审、协办、撤销等 S4 前一律禁止）；破坏性动作（只能发起申请）；获取委托人以外的权限继承委托人可见性S4（字段 S1）
    服务主体平台 / 租户清单声明的 permissions.platform / data / egress / secrets 范围；以自身工作负载身份调用其他能力直连其他插件的数据表；透传用户令牌；超出事件主题 ACL 发布 / 订阅按租户上下文传播S1

    补充规则：

    • 平台超管与租户管理员在策略中显式表达，不做代码 IsAdministrator 特判。
    • 「使用应用」与「管理应用」是两类权限（S3 市场买家与管理员不同角色）。
    • 创建者自动成为应用 Owner（L3 简版，S2）。
    • 用户「删除」= 禁用 + 标记；SSO 同步删除只置禁用；基数超限直接拒绝并返回结构化错误，不静默截断。

    #13.2 权限七层模型 L0–L6

    层对象判定点（PEP）决策依据与存储阶段
    L0 租户隔离所有业务数据① qian.gateway 验签后注入 tenant_id；② 每服务入口的租户解析中间件 / 消息订阅器 / Saga 执行器建作用域；③ EF 全局过滤 + 插入自动填充；④ PostgreSQL RLS（FORCE ROW LEVEL SECURITY + WITH CHECK）令牌 claim tenant_id；tenancy.tenant；每张业务表的 tenant_id 列与 RLS 策略S1
    L1 角色平台超管；租户 Owner / Admin / 开发者 / 使用者；自定义角色qian.authz 求值：有效角色 = 直接授予 ∪ 经组织 / 岗位 / 用户组获得authz.role、authz.role_assignment（主体类型 × 主体 id）S1（职责分离约束 S3）
    L2 功能权限应用、菜单、页面、按钮、API 端点、流程、打印等（资源类型由插件注册）端点声明权限点 → ASP.NET Core 策略 / Mediator 行为 / gRPC 拦截器调用 IPermissionChecker.Check；缺省拒绝authz.permission_definition（清单派生）、authz.grant、authz.resource_typeS1
    L3 资源实例应用 / 表单 / 流程 / 报表 / 文件夹的所有者、编辑者、查看者、共享人；市场授权qian.authz 内置 ACL 表查询（S2）；OpenFGA 适配插件（S3，仅层级继承与共享，不做行过滤）authz.resource_acl；OpenFGA 元组经 Outbox 同步S2 可选 / S3
    L4 数据权限（行级）列表、查询、导出、报表、API 的记录集IDataPermissionFilter 把条件树 + 系统变量编译为 EF / SQL 谓词，在数据引擎唯一入口注入；与 L0 RLS 叠加；覆盖读、改、删、导出全部路径authz.data_scope_rule（条件树 JSON、全部数据标志）；系统变量目录S2（契约 S1）
    L5 字段字段可见 / 可编辑 / 脱敏读：投影或按脱敏规则替换；写：白名单之外的字段拒绝；yue 按元数据渲染，以服务端为准authz.field_policy；字段敏感度标签S2
    L6 上下文条件（ABAC）IP、时间窗、端类型、套餐、数据密级、step-up、Agent 委派作为条件挂在 L1–L4 规则上；Agent 有效权限 = 委托人权限 ∩ scope规则 JSON 中的 conditions[]；令牌 acr / amr / act / profileS1 部分（IP、端、step-up）/ S4

    #13.2.1 求值规则

    1. 功能权限：Check(principal, action, resource) 缺省拒绝；权限点 = 有效角色授权的并集。
    2. 数据权限合并（补充裁决 Q19，不做可配置）：同一角色内多个方案 AND；不同角色之间 OR；任一方案为「全部数据」则整体放开；资源开启了数据权限但主体无任何方案 → 查不到数据；未开启 → 不过滤（仍受 L0）。
    3. 多表：数据权限条件按表拆分条件组；主表直接字段名，副表 / 子表「表名.字段」。
    4. 端维度：菜单与权限点带 terminals，PC 只读取含 PC 入口的授权，移动端同理。
    5. 身份（权限分区，S3 可选）：有效对象 = 身份所挂对象 ∩ 自身拥有对象；当前身份进令牌 profile，不按终端持久化。
    6. 逐级递减（S3 可选）：下级可授范围 ⊆ 上级授权 ∪ 上级角色授权；授权人只能授出自己拥有的，其余置灰不隐藏。
    7. 「双重门」：按钮 / 列 / 字段既要在设计器勾选显示、又要被授权；但鉴权不依赖设计器勾选与客户端传参（menuId / flowIds 之类一律视为提示），资源化 ACL 在数据引擎唯一入口执行。
    8. 判定结果缓存按主体，以 identity_revision 失效；跨服务一致。
    9. 每次判定产出可解释结构 { allowed, matchedRules[], missingPermissions[], evaluatedAt, identityRevision }，拒绝时随结构化错误返回给调用方（不泄露他人授权），并进审计。

    #13.2.2 判定端口语义

    Kun.Authorization 只定义端口，qian.authz 提供内置实现，OpenFGA / OPA 为 S3 可选适配插件。端口语义如下，所有入口（ASP.NET Core 策略、Mediator 行为、gRPC 拦截器、数据引擎、MCP 门面）只能经它们判定，不得自行读取授权表：

    方法输入输出用途
    Check主体、动作、资源引用、上下文（端、IP、时间、acr）{ allowed, matchedRules[], missingPermissions[], identityRevision }单次判定；拒绝时结构体随错误返回
    BatchCheck同上的数组逐项结果列表页按钮矩阵、菜单裁剪，避免 N 次往返
    ListAllowedActions主体、资源引用允许的动作集合前端按状态渲染合法按钮；Agent 先查后调
    ListPermissions主体、可选 profile有效权限点集合与来源权限透视；S1 可选
    Explain主体、动作、资源引用命中链（角色 → 授权 → 规则 → 条件）与缺失项排障；S3 UI、S4 作为工具
    IDataPermissionFilter.Compile主体、资源引用、目标表集合谓词 AST 或 EF 表达式数据引擎唯一入口注入
    IFieldPolicy.Resolve主体、资源引用、字段集合每字段 读 / 写 / 脱敏规则读投影与写白名单

    缓存由实现负责：按主体缓存有效角色与权限点，以 identity_revision 作版本号；Compile 结果按（主体、资源、规则版本）缓存。端口调用必须带 tenant_id 作用域，跨租户判定（平台运营）走显式的平台作用域并审计。

    #13.3 令牌与会话

    #13.3.1 令牌内容

    用户访问令牌（qian.identity 签发，非对称签名，短时）：

    iss   规范 issuer（每环境一个）
sub   person_id
aud[] 资源标识（RFC 8707 resource）
tenant_id, membership_id
scope           OAuth scope 串
identity_revision  整数，权限 / 身份变更即递增
profile?        当前身份（S3 可选，S1 预留）
acr / amr       认证强度与方式（step-up 判定）
act?            委托链（S4，RFC 8693）
sid, iat, nbf, exp, jti

    不进令牌的东西：权限点、角色列表（除 S2S 中的粗粒度 roles[]）、组织归属、任何业务字段。理由：权限变更即时失效、令牌体积、以及「令牌被当作权限载体」会让所有服务各自解释权限。

    选择令牌：命中多个 Membership 时签发 5 分钟、只能换正式令牌的受限令牌。

    S2S 令牌（qian.gateway 换签下行，与 iClaw 契约同形、各签各的，Q15）：

    iss / aud[]（每服务一个）/ sub / tenant_id / project_id? / roles[]（粗粒度角色代码）/ scope / session_id / iat, nbf, exp, jti
exp − iat ≤ 300s（网关换签默认 60s）
plugin_id（服务主体为插件时）

    新能力授权 = 增加 scope 串，不新增 claim。下游每一跳重新验签；禁止把上游令牌透传给下游（混淆代理防线）。roles[] 是与 iClaw 同形的例外：只放粗粒度角色代码，不是权限点集合；Qian 服务不得仅凭它放行，必须调用 Kun.Authorization 决策端口，时效性由 identity_revision 管；project_id 为可选 claim，Qian 只透传不解释（R24）。

    #13.3.2 会话

    规则内容
    两类会话SSO 会话（qian.identity 持有，sid cookie 不透明）与应用会话（各前端 / 插件）分离
    refresh设备级 refresh 令牌、轮换、重用检测即吊销整族
    索引服务端会话表 + 用户 → 会话索引，可按用户、按租户、按设备吊销
    登录策略（租户可覆盖）单端登录（同端类型后踢先，PC / 移动分别判定）或并发上限 2–10（默认 5）；空闲 / 绝对超时；IP 白名单（超管例外须策略显式）；上次登录提示
    密码策略强度与最小长度；锁定阈值与方式（锁账号 / 延时）；历史密码禁用最近 N 个；周期更新与站内信提前提醒；初始密码强制修改（不可取消）
    MFATOTP S1；短信 / 邮箱 OTP、Passkey、恢复码 S3；租户级强制策略；敏感操作 step-up 以 acr / amr 判定
    登录流水线密码、第三方、扫码、企业 IdP 最终构造同一「登录输入」走同一签发路径，统一审计、限流与单端策略
    日志只记 sid 哈希，不记明文 sid 与令牌
    CSRFCookie 方案上线即带 CSRF 防护与安全响应头

    #13.3.3 会话失效触发清单

    以下任一事件发生 → 服务端会话失效（或 identity_revision 递增）+ 向在线客户端推送刷新 / 登出：

    1. 用户改密、重置密码（含管理员重置）
    2. 用户被禁用、锁定、注销
    3. 租户进入宽限 / 只读 / 冻结 / 注销，或被运营方 Suspend
    4. 管理员对该用户 / 该租户执行强制下线
    5. 用户的角色、授权、组织 / 岗位归属变更（identity_revision 递增并推送，≤ 3 秒内对新请求按新权限执行；令牌本身可继续用到刷新）
    6. 第三方身份解绑、上游连接器被禁用（对应会话吊销）
    7. refresh 令牌重用检测命中
    8. 并发上限触发（踢最早会话）
    9. 后通道登出：上游 IdP 发起（入站）或 Qian 发起向下游应用传播（出站），双向

    #13.4 纵深防御分层

    ┌──────────────────────────────────────────────────────────────────────────┐

    各层的失败模式与处置：

    层典型失败处置
    Traefik证书过期、安全头缺失可观测告警；不影响鉴权正确性
    qian.gateway配置了多 issuer 过渡开关未关闭；aud 未校验；限流未挂路由生产环境以「强制装配」替代 opt-in；配置项由 Apollo 校验器拒绝不安全值

    数据引擎Filter AST 透传客户端 tenant_id；标识符未走白名单契约 lint 拒绝租户字段；SQL 生成只接受编译后模型中的标识符
    RLS新表未建策略；事务外读到空集被当成「没数据」C8 门禁；事务外读在集成测试中断言为缺陷

    非 HTTP 入口单独说明：消息消费者按消息信封 tenant_id 建作用域，缺失即进死信并告警；Saga 执行器按实例 TenantId；定时作业按作业定义的租户范围逐租户执行；Agent 调用经 MCP 门面时租户来自令牌，inputSchema 中不存在租户字段。

    #13.6 插件安全

    #13.6.1 信任等级 × 允许形态 × 沙箱 × 签名

    policy.tier谁组合包 / 声明式表面 / 无代码组件允许的 runtime.form（代码部分；原 kind）policy.sandbox 与 hooks type审核与签名运行时身份
    system平台团队（平台插件 = platform profile base 组合包）均可module / service / package / function / ui（seam Provider 组件按实现取 module / service，R28）none（MF2；service 为 workload）；hooks command / http / plugin平台密钥签名，随发行版（profile）发版宿主进程身份；policy.required: true（原 alwaysEnabled，R34）
    official平台团队业务插件均可同上同上同上同上或独立 service
    partner认证 ISV均可package / function / ui；不允许 module 进共享进程；service 仅在 S3 沙箱策略另行开放（workload）ui：worker（审核后可 none）；function：wasm；hooks http / plugin发布者认证 + 扫描 + TCK + 人工审核；cosign独立工作负载身份
    private租户自建均可package / function / ui；不允许 module、service（service 仅在 S3 沙箱策略另行开放）ui：worker | iframe；function：wasm；hooks http租户内可见；自动 TCK；租户密钥签名独立工作负载身份
    community公开社区均可；S1 只接受无代码组件（runtime 为空）同 private（S1 不接受任何代码部分）同 private；hooks http自动扫描 + TCK；「未认证」标识不进任何共享进程

    规则：

    • 第三方代码永不进共享进程；组合包与声明式表面对所有 tier 开放（应用 = 组合包 + marketplace 条目，ISV 应用即 policy.tier: partner 的组合包，R28；原「bundle 对所有 tier 开放」R22 据此改读），按 tier 收紧的是组合包内各组件的 runtime.form 与 policy.sandbox：partner / private / community 的组件不得使用 module，service 仅在 S3 沙箱策略另行开放；校验器与装载器（Resolve 阶段拒绝为非 system / official 组件加载程序集）两道检查互为冗余（specs/component-model.md §11.1）。
    • 默认强制验签：未签名或签名不符直接安装失败，不是警告。签名在清单外：代码制品 = 清单 + 文件摘要 + SBOM 打成 OCI 制品，cosign 出独立签名与证明；元数据包与 SKILL.md 用「文件 URI + SHA-256 + 字节数」清单 + 分离签名；市场文件 .qian/marketplace.json 用 Ed25519 分离签名，公钥须命中客户端信任根（specs/component-model.md §11.5）。
    • 按 digest 引用：清单里只接受 @sha256:；标签引用安装失败。
    • 审核分级：免费元数据模板快审；付费或带代码走安全审查；权限扩大、付费模式变更触发复审。
    • 工具描述哈希钉死（S3）：注册表保存已批准能力的「名称 + 描述 + 规范化 inputSchema」哈希，变更即下线待复审；schemaSha256 变即旧授权失效。
    • 发布者撤销与黑名单：命中即自动卸载并通知租户管理员。
    • 未验签市场条目只允许无代码组件（R40）：未签名市场或未命中信任根的条目需 --allow-unverified 才参与 qian add 解析，且只允许安装无代码组件（runtime 为空）、tier 最高 community；qian list 持续标记 unverified。
    • hooks command 类型仅限 system / official，argv 不经 shell（R41）：hooks.json 的 command 是 argv 数组，不经 shell 解释（无管道、重定向、通配），在受限执行器中运行（工作目录为组件目录、环境变量白名单、默认超时 30s / 上限 600s、无网络除非 policy.egress 非空）；平台宿主默认关闭 command 执行，platform profile 需显式开启，gateway / identity profile 拒绝开启；commands/*.md 的内联 shell 遵守同一规则并须被 allowed-tools 逐条覆盖，community / private 组件出现内联 shell 即校验失败。
    • 连接器 = 为某个 seam 注册 Provider 的组件（R28 / R38）：connector 不是 runtime.form；清单上 provides[] 写「注册表键:名称」（如 Identity.Connectors:oidc）向该 seam 的注册表子服务按名称注册，policy.egress[] 声明允许的出网目标（为空 = 默认拒绝出网），runtime.form 按实现取 module 或 service；出网只经出口代理，白名单来自 policy.egress（§13.8）。

    #13.6.2 反向权限审批

    清单 policy.permissions 段（原 permissions，R37）声明插件向平台申请什么，租户管理员挂载时逐项批准，升级新增即重新批准：

    段内容运行时强制点
    platform[]如 tenant:read、user:read、file:write、notify:send服务 PEP 以插件主体身份判定
    data[]{ entity, access: r / rw }数据引擎唯一入口；每插件独立 PG schema 与数据库角色，不得直连他人表
    policy.egress[]（原 permissions.egress，R28 升为 policy 顶层字段；seam Provider 组件必填）允许出网目标 <host>[:<port>]；为空 = 默认拒绝出网生成 NetworkPolicy / 出口网关规则；私网与云元数据地址默认阻断；hooks.json、.mcp.json 的 url 域名必须在其中
    secrets[]{ name, scope } 只有名字ISecretResolver 在使用点解析，永不回传明文
    ui.connectSrc[]前端允许连接的源生成 CSP connect-src；MF2 远程只能从白名单加载

    与之相对，metadata/permissions.json（原 provides.permissions，R37）是插件定义的、可被授予他人的权限点；两者都由 qian.authz 登记。

    #13.6.3 运行时强制点

    • runtime.form: service 组件：独立 K8s ServiceAccount + 含 plugin_id 的 S2S 令牌；每插件独立 Deployment、ResourceQuota、default-deny NetworkPolicy + 清单派生的放行规则；健康 = K8s 状态 + /health 双条件。
    • function（Wasm）：燃料、内存、超时限额来自清单 runtime.limits；无网络与文件系统能力，除非清单声明并被批准。
    • 事件：发布 / 订阅主题 ACL 来自 metadata/events.json（原 provides.events，R37）；越权主题在总线层拒绝。
    • 前端：system / official 以 MF2 挂载并共享 singleton 依赖；其余按 tier 走 Worker 远程渲染（白名单组件目录 = yue manifest）或 iframe（无 allow-same-origin，postMessage 握手）。
    • 「未挂载」（租户 scope 未挂载，或被 restrict 过滤）在网关路由、SDK 入口、前端外壳三处同时拦截，一律 404、与不存在无法区分（管理面 403 原因码 PLUGIN_NOT_MOUNTED 等，R32 / R48）。

    判定审计每次 Check 的 { matchedRules, missingPermissions, identityRevision }；超管旁路单独类型
    登录审计成功 / 失败、grant 类型、连接器、IP 归属、UA、设备；只记 sid 哈希
    来源自动化由能力契约的 audit.emits 与命令元数据自动记录，不靠开发者手工加特性
    保留与查询按租户与类型配置保留天数；不提供「一键清空」；IAuditReader 分平台 / 租户两种视角；跨租户只对平台超管可见
    完整性哈希链 100% 可验证是阶段退出准则（§14）；断链告警
    可观测衔接trace_id 贯通；请求 / 异常日志进可观测栈，不落业务库

    #13.10 前端安全硬线

    1. 不 eval：不用 eval / new Function 执行租户脚本；联动三层（声明式动作 → 可序列化表达式 DSL → QuickJS 沙箱，白名单 API、超时、内存上限、不暴露令牌）。
    2. 令牌不进 URL / iframe：嵌入页面、大屏、报表、外链、文件预览用一次性票据或 postMessage 握手；禁止 URL 带 token。
    3. CSP 由清单生成：connect-src / frame-src / script-src 来自清单 permissions.ui 与 MF2 远程白名单；不可信 UI 走 iframe sandbox（无 allow-same-origin）或 Worker 远程渲染。
    4. 前端裁剪只是体验层：菜单 / 按钮 / 列 / 字段隐藏只影响体验；服务端缺省拒绝是唯一防线；auth 是引擎一等字段但不参与服务端判定。
    5. 不在前端持有加密密钥；不把接口体加密当安全。
    6. 不持久化敏感字段：不把 access token、锁屏密码写入 localStorage 明文；refresh 令牌只在安全存储（HttpOnly cookie 或设备安全区）。
    7. 第三方 UI 零隔离即零信任：partner 以下的 UI 不直接 MF 挂载。
    8. 可寻址但不泄露：data-testid / data-slot 不包含业务数据。
    9. 依赖供应链：锁定版本、publint、SBOM；重型物料独立包懒加载。

    #13.11 Agent 相关威胁与防线

    威胁平台防线（确定性控制优先）阶段
    提示注入（直接 / 间接，含工具描述藏指令）所有外部内容与工具返回视为不可信数据；摄入不可信内容后对后续动作降权（高风险动作强制人工确认）；不依赖检测器S4（S1 起副作用分级就位）
    工具投毒 / rug pull已批准工具「名称 + 描述 + 规范化 schema」哈希钉死，变更即下线复审；Skills 清单摘要校验；schemaSha256 变即授权失效S3
    越权 / 混淆代理令牌受众绑定 + 禁止令牌透传；下游各跳重新验签；最小 scope 与逐步提权；按调用者权限过滤工具列表；句柄绑定主体；Agent 只拿委托人权限子集S1（令牌与权限）/ S4（工具列表过滤）
    数据外泄沙箱与连接器出网白名单 / 出口代理；字段敏感度驱动脱敏；敏感参数不入 HTTP 头；对外发送类工具默认需确认S2 / S4
    破坏性操作 / 失控循环副作用分级 + 默认策略（read 放行、write 确认、destructive 二次确认或禁止）；dryRun；软删与回收站；元数据版本回滚；调用频率上限；急停开关（按 Agent / 租户 / 工具）S1（分级）/ S4（急停）
    成本失控Higress token 限流与缓存；租户 / 应用 / Agent 预算与告警；工具列表确定性排序提高缓存命中S3
    供应链插件签名与哈希、市场条目验签（未验签只允许无代码组件，R40）、命名空间验证、安装时展示完整权限；沙箱默认最小权限；按 digest 引用S1
    第三方插件代码永不进共享进程；独立工作负载身份；独立 schema 与数据库角色；事件主题 ACL；出口 NetworkPolicy；CSP 由清单生成；Wasm 限额S1 规范 / S3 对第三方生效
    身份冒用（Agent 冒充人）Agent 主体独立 client 类型、有归属人、可吊销；act 链进令牌；审计 actor_type=agent；humanOnly 动作服务端拒绝S1 字段 / S4
    合规AI 生成内容显式 / 隐式标识；模型路由按数据驻留策略；审计留痕S4

    #13.13 关键表 DDL 片段（示意）
