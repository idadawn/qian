    #宿主与框架

    #两种模式，同一组包

    模式宿主装什么适合
    独立模式你自己的 ASP.NET Core 项目（standalone profile）Qian.Runtime + 所选组件的 Definition / Provider 包；配置走标准 IConfiguration，租户默认单租户只想用某几项能力，不部署 Qian 平台
    平台模式platform profile 的宿主base 组合包里的全部平台插件，含注册表、生命周期、能力目录三件套多租户平台本体

    两种模式下组件行为一致，由同一套 TCK 在两种模式各跑一遍保证（ADR-019）。Qian.Runtime 是组件库唯一必需的 Qian 依赖，组件之间只经 *.Abstractions 引用（依赖图门禁见 seam）。

    #五个 profile

    可部署单元是 profile。S1 随发行版交付五个：

    profile用途
    platform平台本体：base 组合包 + 前端外壳，可选模型网关；不承诺 AOT
    gateway业务 API 网关边缘，可 AOT
    identity身份服务（唯一 issuer），独立安全边界
    standalone消费者宿主安装的最小组合包，qian init --template dotnet-webapi 的默认
    minimal测试与 SDK 用的最小插件树：TCK 宿主、CLI 自身运行时

    组合包清单见 profile、组合包与 patch。

    #前端

    前端用 React + yue 组件库。外壳 qian.shell 是 MF2 宿主：插件的界面以远程模块按需加载，挂到版本化插槽上（ADR-013）。前端外壳自身也是一棵由 @qian/runtime 装载的插件树，编程模型见 前端 SDK。

    #与 Kun 的关系

    Qian 平台基于 Kun 框架构建，前端使用 yue 组件库（ADR-021）。Kun 是 .NET 10 云原生微服务开发框架，是 Qian.Runtime 与平台插件的实现依赖，以 NuGet + CalVer 锁版本消费；Kun.* 不改，它的 AddKunXxx() 模块在 Qian 里包装成插件（ADR-001、ADR-020 D20.10）。

    Kun 的文档在 SDK 部分的 Kun 框架 小节：按 KunVersion 锁定的版本从 kun 仓库镜像，与 Qian 实际依赖的 Kun 是同一版本。Kun 模块与平台插件、seam 的对应，Qian 选定的 canonical API 与禁用项，见与 Qian 的关系。
