# ADR-014 应用市场形态

> 本页由构建脚本镜像自仓库 [`docs/adr/ADR-014-marketplace.md`](https://github.com/idadawn/qian/blob/main/docs/adr/ADR-014-marketplace.md)，请修改源文件，不要改本页。

> **2026-10-06 经 ADR-020 修订。** 应用包格式 = 组件文件夹（`.qian-plugin/plugin.json` 清单 + 声明式表面 + 可选代码）+ `marketplace.json` 条目；OCI 制品只用于代码部分；S3 的商业市场（授权、计费、审核、ISV 入驻）叠在同一 `marketplace.json` 格式之上，不另起格式。D14.1 的「应用 = bundle」改读为上述格式，D14.2 两种分发、D14.3 元数据分层与可定制性、D14.4 升级与冲突处理及权益 API 的结论不变。详见 ADR-020 D20.8 与 §6。

## 1 背景与问题（Context）

应用市场本身是 S3 的普通插件，但它所依赖的「包格式、授权、隔离」必须在 S1 进内核或系统插件，否则之后几乎改不了（基线 P §0 第 9 条、§7.2）。参考平台的导出包是反例：单功能与整应用导出都不含菜单 / 权限 / 数据接口 / 字典 / 数据连接 / 业务表结构，导入不重映射内部 id 引用，导入后需人工修复（基线 P §7.1）。

业界两种分发模式：模板型（拷贝即拥有、可改、升级只能同源导入合并 / 覆盖）与商品型 / 托管型（锁定、带命名空间、可升级、订阅方在上层叠加定制）；Salesforce 非托管 vs 托管包、Dataverse 分层解决方案、ServiceNow 三方合并都是参照（基线 P §7.1）。iClaw 的注册表形状是 Package / Release / Publication / Installation 四层与 `pending → approve/sign → active` 生命周期（基线 P §8.6）。Entitled（授权，是否买了）与 Enabled（开关，是否灰度开）需分开存（基线 P §4.2）。大屏方面，参考平台嵌入的是第三方商业版大屏产品，根目录 MIT 文件与商业授权并存、边界不清，被裁定为高风险、不参考不复用（基线 D §0.3 第 1 条、附录 A）。

## 2 决策（Decision）

- 【经 ADR-020 修订：应用包格式 = 组件文件夹 + marketplace 条目】**D14.1 应用 = bundle**：`package`（模型 / 表单 / 列表 / 流程 / 菜单 / 权限模板 / 字典 / 数据接口）+ `ui` + 可选 `function / service` + 种子数据 + 迁移脚本 + 依赖清单 + **id 重映射表**。
- **D14.2 两种分发都支持**：`template`（拷贝即拥有，可改，升级只能同源导入合并 / 覆盖）与 `managed`（托管、锁定、带命名空间、可升级，租户在上层叠加定制）；**默认 `managed`，`template` 作为可选**（Q10）。
- **D14.3 元数据分层与可定制性**：有效元数据 = 系统基础层 → 按依赖拓扑排序的包层 → 租户定制层 →（S3 可选）用户个性化层，按「租户 + 版本指纹」缓存；容器型组件（表单、列表、菜单、门户）结构化合并，其余上层优先；`marketplace.manageability` 标记组件 / 属性级可定制性（`locked / tenantEditable / protected`）。
- **D14.4 升级与冲突处理**：`managed` 升级做三方比较（旧包、新包、租户层），冲突项列清单由租户「保留我的 / 采用新版 / 手工合并」；升级前快照与回滚；升级同意规则由 SemVer + 「是否新增权限 / 外发 / 密钥」决定，有新权限必须租户管理员重批；第三方推送升级不得新增权限。
- **D14.5 授权与权益 API**：授权（Entitled）在租户 / 订阅库，特性开关（Enabled）在 Apollo，分开存；S1 授权 v0 = 「租户 × 插件 × 计划」授权表（手工授予）+ 运行时权益查询 API + 授权变更事件；S3 完整 `Plan / Entitlement / Seat / Meter / Trial`，至少支持免费、买断、按组织年付、按人年付、试用、线下授权。
- **D14.6 演进路线**：S1 末（M0）「一切皆包」跑通：包格式 v0、清单 Schema、制品库（Harbor OCI）、安装 / 卸载 / 升级引擎、租户级注册表、授权 v0、CLI 打包发布、内部开发者目录；S2（M1）低代码应用可打包分发，`template / managed` 两种包、包层 / 租户层分层、同源导入升级，**平台自营应用以包形式交付**，验收「同一应用包在两个租户分别安装、各自配置、独立升级互不影响」；S3 初（M2）私有目录型市场（分类 / 搜索 / 详情含权限清单与外发域名 / 安装向导 / 试用 / 「免费 / 联系销售 / 授权码」开通 / 升级中心 / 运营审核台）；S3 中（M3）开放 ISV 与在线交易（自助入驻、命名空间预留、开发租户、发布流水线、支付与订阅、席位双轨、分成结算、评分绑定真实安装、自动化安全扫描）；S3 后 → S4（M4）质量徽章、伙伴分级、市场 API 机器可读、`role: agent` 包、Agent 生成应用的自动审核门禁。
- **D14.7 S1 必须做对的三件事**：包格式与可定制性契约；升级与冲突处理；授权与权益 API。
- **D14.8 签名与审核**：按信任等级（ADR-002）强制验签；审核分级（免费元数据模板快审，付费或带代码走安全审查，权限扩大触发复审）；已批准能力的「名称 + 描述 + 规范化 inputSchema」哈希钉死，变更即下线待复审（S3）；发布者撤销与黑名单自动卸载；上架闸门 = TCK 全绿。
- **D14.9 功能编码与跨应用**（Q20）：「租户.应用.功能」命名空间化稳定编码 + id 重映射表；一个功能只归属一个应用，其他应用通过「跨应用引用」挂菜单。
- **D14.10 流程资产作为商品**（Q27）：流程模板、决策表节点包为 S3 市场商品；流程层用「启用 / 停用」避免与市场「上架 / 下架」撞名。
- **D14.11 大屏**（Q31）：延后到 S3 可选，不复用参考平台大屏源码，只消费内核数据接口与分享链接，优先由应用市场生态提供。
- **D14.12 S3 不开放第三方 `service` 上架**（Q9），只开放 `package / function / connector / 受限 ui`。
- **D14.13 市场兼任私有能力注册中心**：S3 预留、S4 必做；对外接口形态兼容官方 MCP Registry 的 OpenAPI 与 `server.json`；「应用上架」与「MCP Server 发布」在 S3 合成同一个 publish 动作；Qian 注册表是真相源，向 iClaw / Nacos 的注册是经 adapter 的投影。

## 3 理由（Rationale）

- 包格式、升级语义与权益 API 是「做错了之后几乎改不了」的契约，必须在 S1 以内部开发者为用户先跑通（基线 P §7.2）。
- 默认 `managed` 使升级与 ISV 知识产权保护成为默认路径，`template` 服务于「拿来改」的内部场景。
- 授权与开关分开存，是因为两者变更频率、权威与审计要求不同（基线 P §4.2）。
- 平台自营应用吃自己的狗粮，是验证包格式最可靠的手段。

## 4 备选方案与放弃原因（Alternatives）

- **只支持 template**：无法升级、无法保护 ISV 资产。放弃。
- **只支持 managed**：内部快速定制场景受阻。放弃。
- **市场能力做进内核**：市场是 S3 普通插件，可替换为内网目录。放弃。
- **直接合并进 iClaw 插件市场**：iClaw 的市场与 MCP Catalog 仍是设计态；是否合并待拍板（见 ADR-016）。

## 5 后果与代价（Consequences）

- 正面：S2 起每个低代码应用天然可分发；升级有确定的冲突处理语义；S4 Agent 生成应用直接产出 `package` 走同一门禁。
- 负面：三方合并与逐租户升级在大量租户下没有完美方案；id 重映射与命名空间化编码增加设计器与导入导出复杂度；审核流水线是 S3 的持续运营成本。
- 配套：`qian.entitlement` 系统插件（S1）；`qian.metadata` 的分层与 manageability（S2）；`qian.marketplace`、`qian.billing`（S3）；计量表从第一天带租户 / 项目双键。

## 6 对各阶段的影响

- **S1**：bundle 格式 v0、授权 v0 与权益查询 API、制品库、安装 / 升级引擎、CLI 打包、内部目录。
- **S2**：`template / managed`、分层与 manageability、同源导入升级、id 重映射、自营应用打包。
- **S3**：私有目录市场 → ISV 开放与交易；三方合并冲突预检；Plan / Seat / Meter / Trial；工具描述哈希钉死；用户个性化层可选。
- **S4**：市场 API 机器可读、私有 MCP registry、`role: agent` 包、Agent 生成应用审核门禁。

## 7 待确认事项

- 共享 / 专属部署是否作为套餐差异售卖（决策清单 D14 需拍板项，Q1–Q18 未给默认）。
- 市场购买的 `managed` 应用是否禁止复制 / 导出（基线列为 S3 可选，未裁决）。
- 定价与分成细则属 S3 产品决策。
- Qian 应用市场与 iClaw 插件市场是否合成一个注册表（见 ADR-016 §7）。
