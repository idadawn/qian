# ADR-012 流程引擎

> 本页由构建脚本镜像自仓库 [`docs/adr/ADR-012-workflow-engine.md`](https://github.com/idadawn/qian/blob/main/docs/adr/ADR-012-workflow-engine.md)，请修改源文件，不要改本页。

## 1 背景与问题（Context）

参考平台是「.NET 业务编排 + Java Flowable 令牌推进」双进程双库：Flowable 只回答「当前在哪、下一步能去哪」，条件全在 .NET 算，跳转靠改引擎内部实体，失败靠补偿对齐；真正「引擎」相关代码 .NET 侧不到 500 行 + Java 1.5k 行，其余 2.6 万行全是审批域业务——**换引擎的成本远小于重写审批域**（基线 W §6.1）。外部候选：Elsa 3.9 刚加 User Tasks，不含会签 / 加签 / 退回 / 撤回 / 抄送，Studio 是 Blazor；Flowable 8 需 JVM 与 70 张引擎表；Camunda 8 生产需商业许可，与私有化交付冲突；Temporal / Dapr 要求确定性代码，承载元数据驱动审批等于再造解释器（基线 W §6.1）。

参考平台 14 处必须修正的做法：兜底落全局 admin；会签两类阈值都未达即停滞；转审改写流转记录原处理人；超时转审取后端返回顺序第一人；条件判定拼 SQL 到租户库、公式交内嵌 V8 当任意 JS；节点 JSON 无 schema、属性面板 1.88 万行手写；已发布版本只靠前端约束；技术栈差异泄漏到 UI；决策流入参出参一律字符串；公有变量全局可写；外部回调匿名 + 随机串弱校验；流程「上架 / 下架」与市场撞名；任务流程集合语义隐式；删除数据节点无条件即全表删除（基线 W §0.4）。多副本下参考平台依赖进程内事件总线、本机自调用、非原子缓存锁、内存延时队列（基线 W §6.2）。Kun 的 Saga 是代码定义的技术性长事务，不能当业务流程引擎（基线 K §3.1 第 6 条）。bpmn-js 要求水印可见（基线 W §6.11）。

## 2 决策（Decision）

- **D12.1 自研 .NET 轻量审批内核**作为 S2 插件 `qian.workflow`：节点树 JSON 保存时编译为内部有向图；令牌推进 + 持久化；排他 / 包容 / 并行网关，默认分支一律是 **else 分支**；单库单事务；条件走内存表达式引擎；复用 Saga 的状态机命名与 Outbox；借鉴 warm-flow / FlowLong 的 7–8 张表模型。Elsa 3 只做 S1 末 PoC 对照；Flowable 只作「BPMN 合规」可选适配器挂在 `IFlowEngine` 之下。
- **D12.2 一套 JSON 定义、两种视图**：简单流程与标准流程合并为同一运行时与同一定义；S2 只交付瀑布 / 纵向节点树视图设计器（DOM 自绘，对 Agent 生成最友好），属性面板按 schema 自动生成；自由画布（React Flow）S3 可选；不用 bpmn-js；BPMN 只作导出器且不早于 S3（Q22）。
- **D12.3 流程整体属于 S2**；S1 只交付硬性前置：组织模型（岗位、责任岗位、上下级、组织类型、第 N 级责任人查询契约）、事件总线 Outbox、按业务键可取消的可靠延时调度、表达式 / 条件引擎规范（JSON AST）、消息模板注册、元数据版本化契约、鉴权资源 `workflow:{key}:launch`、文件存储、回调入口。
- **D12.4 S2 最小集**：基线 W §2.6 的最小集全部必做，并按 Q14 把**子流程**与**限时 / 超时 / 催办**升为必做；加签 / 减签、候选人、会签延后计算、办理节点、选择分支保持可选。
- **D12.5 拒绝后继续流转**：S3；S2 在动作枚举中预留（Q24）。
- **D12.6 审批人兜底链**：节点指定异常处理人 → 租户管理员角色 → 「无法提交」结构化错误；不再兜底到全局管理员（Q25）；组织变更由组织插件发事件、流程订阅后主动预警。
- **D12.7 Agent 代办身份**（Q26）：委托模型区分本人 / Agent / 系统三类 actor；Agent 有效权限 = 委托人权限 ∩ 授予 scope；签名类动作标 `humanOnly`；转审、协办、撤销在 S4 前对 Agent 禁止。
- **D12.8 命名与市场**（Q27）：流程层用「启用 / 停用」替代「上架 / 下架」；流程模板、决策表节点包作为 S3 市场商品。
- **D12.9 自动化与决策**（Q28）：自动化（任务流程）S2 可选、S3 必做；决策引擎 S3 可选；任务流程动作显式声明 `cardinality: single|each|batch`，破坏性动作声明 `destructive` 并提供试运行与影响行数预估。
- **D12.10 定义可校验、版本不可变**：每种节点类型发布 JSON Schema + `uiMeta`，保存走 `:validate` 返回结构化错误（字段路径 + 错误码）；版本三态 设计中 → 启用中 → 已归档，只有设计中可编辑，后端拒绝其它版本写入；在途实例绑定发起时版本。
- **D12.11 审批域规则**：或签 = 首个终结动作结束节点；会签阈值按人数或比例，两阈值都不可达时发 `node.stalled` 转人工，不得静默停滞；撤回 ≠ 撤销 ≠ 催办；退回三模式 × 四目标需路径快照；流转记录只追加、带 actor 类型，转审保留委派链；上级责任人按岗位链推导而非直接上级；超时转审用明确排序或轮询策略。
- **D12.12 多副本运行时**：Outbox + 平台调度 + 乐观并发（节点级版本号）或分布式锁；不用本机自调用；执行节点经内部服务契约与身份传递调用。
- **D12.13 表达式**：条件 JSON AST + 强类型内存求值 + 可扩展函数注册表（起步集 SUM / SUBTRACT / PRODUCT / DIVIDE / COUNT）；后端脚本如需用 Jint 并设限额；前端表达式用 QuickJS 沙箱；公有变量只读，写入走显式状态存储；决策流入参出参必须有类型。
- **D12.14 外部节点与回调契约**：`{correlationId, outcome: approved|rejected|error, fields{}, actor}`，经网关暴露，带租户路由、签名或令牌、幂等键、超时策略；这也是 S4 Agent 充当审批者的标准姿势。
- **D12.15 工作流即能力**：发布的流程作为意图级能力登记；人工节点 = Operation/Task `input_required`；`GET /workitems/{id}/actions` 返回带 `inputSchema / preconditions / humanOnly` 的动作，`POST` 带 `idempotencyKey`；按钮显隐由动作前置条件统一计算并经 API 返回。

## 3 理由（Rationale）

- 「中国式审批」的工作量在审批域（会签 / 或签 / 加签 / 退回 / 转审 / 委托 / 撤回 / 抄送）而不在引擎，任何外部引擎都要在其上再造这一层（基线 W §6.1、§6.10）。
- 一套 JSON 定义避免「切换」单向与两套引擎漂移；纵向节点树是 Agent 生成最友好的形态（基线 W §0.3 第 9 条；基线 U §4）。
- 流程归 S2 由阶段退出标准决定：S1 验收不需要审批流（基线 W §0.2）。
- 子流程与超时催办升为必做：国内审批高频，且时效能力依赖 S1 的可靠调度，正好验证前置能力。

## 4 备选方案与放弃原因（Alternatives）

- **Elsa 3 作主引擎**：缺审批域原语、Blazor Studio 与 React 栈割裂。只作 PoC 对照。
- **Flowable 8 / Camunda 8**：JVM 独立服务与大量引擎表 / 商业许可。Flowable 仅作可选 BPMN 适配器。
- **Temporal / Dapr Workflow**：确定性代码模型不适合元数据驱动审批。放弃。
- **Saga 当流程引擎**：代码定义、步骤不可变、无人工任务 / 分支 / 版本。放弃。
- **bpmn-js 画布**：许可证要求水印可见。放弃。

## 5 后果与代价（Consequences）

- 正面：引擎与审批域同栈、同库、同事务；定义 Schema 化压缩设计器工作量并成为 S4 生成前提；动作即工具。
- 负面：自研审批域大（对标可精简到 1.2–1.5 万行）、引擎中（5–8k 行含测试）、设计器大；逆向操作交叉语义（退回 / 撤回 / 撤销 / 拒绝续流 × 子流程 / 加签 / 计时器）是最易出 bug 区域，需要场景回归集与属性测试；S2 流程域至少是一个 3–4 人团队数个迭代的主线。
- 配套：S1 组织模型必须预留责任岗位链与查询契约，否则 S2 动态审批人做不出来；表单字段类型族契约；工作台四列表 + 详情页（S2），面向客户完整工作台 S3。

## 6 对各阶段的影响

- **S1**：只交付前置能力（D12.3）；Elsa PoC 在 S1 末。
- **S2**：审批内核最小集 + 子流程 + 超时催办；节点树设计器；工作台四列表；通知六状态；领域事件。
- **S3**：拒绝续流、归档、签收、委托、撤销申请、SLA 自动处置、决策、自由流、批量审批、BPMN 导出、自由画布、流程模板上架。
- **S4**：AI 建流程只生成「设计中」草稿经 `:validate`；Agent 作审批人解析器 / 外部审批者 / 事件消费者 / 自动化动作。

## 7 待确认事项

- 合流语义（并行 / 包容合流 + 退回 + 加签嵌套）与幂等重放的测试策略，是否引入属性测试。
- 多副本下计时器重置与「正在审批中」互斥：乐观并发 vs 分布式锁。
- 责任岗位链、组织类型、第 N 级责任人的查询性能（S1 组织插件需确认）。
- 外部回调鉴权方式（签名 vs 令牌）、重放窗口、超时后处置。
- 会签百分比取整规则与两阈值不可达时的默认第三结局。
- 在途实例是否需支持迁移到新版本（本期不做，需确认无硬性需求）。
