#9.0 目标与退出标准

#9.0.1 目标

把 S2 的「平台运营方帮租户装应用」变成租户自助：租户能从应用市场选购并开通应用、自助配置身份源与品牌；ISV 能上架；平台能计量计费。市场形态按 ADR-014 演进：S3 初私有目录型（M2）→ S3 中开放 ISV 与在线交易（M3）。

#9.0.2 退出标准（ADR-018）

  1. 一个新租户从自助申请 → 审核通过 → 自动开通 → 租户管理员登录 → 在应用市场选购一个 managed 应用 → 试用 → 开通 → 应用在该租户可用，全程无平台运营方人工介入（审核可自动）。
  2. 该租户管理员自助配置一个企业 OIDC 身份源（含邮箱域 HRD）与品牌（LOGO、名称、登录页主题），其成员用企业账号登录并看到租户品牌。
  3. 市场中至少一个受邀 ISV 的应用经审核台上架；应用升级时，已安装租户收到升级中心的冲突预检报告并完成升级或回滚。
  4. 计量：租户当月的席位、API 调用、模型用量（若接入）在用量视图可见，与账单脚本输出一致。

#9.0.4 S3 的横切约束

  • 市场、权益、隔离三者中，包格式与可定制性契约、升级与冲突处理、授权与权益 API 在 S1/S2 已定且之后几乎改不了（ADR-014，经 ADR-020 修订）；S3 只在其上加 UI 与交易，不改契约。按 ADR-020 D20.8：应用包格式 = 组件文件夹 + marketplace 条目，OCI 制品只用于代码部分；商业市场（授权、计费、审核、ISV 入驻）叠在 .qian/marketplace.json 之上，不另起格式；授权状态机只管「买没买」，「开没开」由租户 scope patch 表达（§07 7.14）。
  • 所有面向客户的入口（市场、自助、工作台、开放 API、分享链接）都走 §07 的统一鉴权与审计；匿名访问只能经能力令牌，没有免鉴权资源类型。
  • 第三方代码永不进共享进程（ADR-002）；对第三方生效的运行时强制点（独立工作负载身份、独立 schema 与数据库角色、事件主题 ACL、出口 NetworkPolicy、CSP）在 S3 首次被真实第三方触发，S1 的规范在此验收。
  • 租户主数据权威归 Qian（Q15）；凡与 iClaw 共用的设施（Higress、运维侧 Authentik）只共用数据面与运维面，不共用租户模型。

#9.1 应用市场：私有目录型 → ISV 开放（P0 · S3）

#设计理念

市场本身是普通组件；它依赖的「包格式、授权、隔离」在 S1/S2 已定：应用包格式 = 组件文件夹 + marketplace 条目，OCI 制品只用于代码部分（ADR-020 D20.8 对 ADR-014 的修订）；S1 的目录市场是 git 仓库里的 .qian/marketplace.json（§07 7.2.4），S3 的商业市场（授权、计费、审核、ISV 入驻）叠在同一份文件之上：商业字段（价格、套餐、席位、审核状态）由 qian.marketplace 以条目 name@version 为外键存平台库，不写进 marketplace.json，不另起格式（R36）。S3 初先做私有目录型（租户自助浏览与安装、受邀 ISV 线下结算），S3 中再开放 ISV 自助入驻与在线交易。第三方任意代码容器（service）本期不上架，只开放 package / function / connector / 受限 ui（Q9）。

#范围与边界

目录与详情（M2，P0）

  • ✅ 分类/标签/搜索/精选；详情页：截图、示例数据预览、权限清单（反向权限 permissions.platform/data/egress/secrets）、外发域名、兼容性（engines 区间）、版本日志、价格结构、ISV 信息、评分（M3）。目录 API 机器可读（S4 Agent 检索）。
  • ✅ 自营应用与平台能力包（流程模板、决策表节点包、打印模板包）同样作为商品上架，走同一流水线（补充裁决 Q27）。
  • ✅ 租户私有市场（ADR-020 D20.8）：S3 默认平台托管——租户上传组件文件夹，平台生成其私有 marketplace.json（格式与官方市场相同）；租户自带 git 仓库为 S3 可选（R36）；qian.marketplace 聚合官方 / 租户私有 / 社区三类来源并标注来源，租户管理员决定信任哪些市场；私有市场里的组件不经平台审核台，但同样过校验器与验签。
  • ✅ policy.authentication: ON_USE 的连接器组件：安装时不要求凭据，首次使用时由租户管理员在 qian.identity 连接器设置卡（ui 表面，R36）于租户 scope 填入 secretRef（ON_INSTALL 的组件在安装向导即要求）；凭据永不出现在 marketplace 条目与组件文件夹中。

安装向导与试用（P0）

  • ✅ 安装向导：依赖包展示与自动安装、所需反向权限逐项批准、外发域名确认、成员与数据范围初始授权；安装到租户复用 §08 8.10 链路。
  • ✅ 试用：按包配置天数一键开通，到期自动降级或停用；「先在沙箱租户试装」P2。
  • ✅ 三种开通方式（M2）：免费 / 联系销售 / 授权码（线下）；在线支付与订阅为 M3。

升级中心（P0）

  • ✅ 新版本提示与更新日志；三方合并冲突预检报告（旧包 × 新包 × 租户层，列出冲突项，租户按「保留我的 / 采用新版 / 手工合并」处理）；升级前快照；计划升级窗口；失败回滚（修订回切 + 前向兼容数据）。
  • ✅ 升级同意规则：新增反向权限或付费模式变更 → 必须租户管理员重批；无新增 → ISV 可推送（全部 / 灰度 / 指定租户），官方插件借 Apollo 灰度 + 租户批次。
  • ✅ 禁止复制/导出 managed 应用（ISV 知识产权保护选项，P2）。

审核台与发布者认证（P0 / M3 P1）

  • ✅ 平台运营审核台：自动扫描结果（清单校验、依赖、安全扫描、TCK、性能基线）、人工审核清单、驳回理由模板、复审触发（权限扩大、付费变更）；分级审核（免费元数据模板快审，带代码走安全审查）。
  • ✅ 发布者认证（M3）：企业/个人实名、开发者协议、命名空间预留、开发租户与沙箱、CLI 发布流水线（构建 → 自动校验 → 提交审核 → 上架；上架后版本不可改）。
  • ✅ 工具描述哈希钉死：注册表保存已批准能力的「名称 + 描述 + 规范化 inputSchema」哈希，变更即下线待复审（防 rug pull）；强制验签不变。
  • ✅ 发布者撤销与黑名单自动卸载；强制下架与安全补丁强制升级。

席位与权益（M3，P0 模型 / P1 交易）

  • ✅ Plan / Entitlement / Seat / Meter / Trial 完整模型（S1 v0 升级）：免费、买断、按组织年付、按人年付、试用、线下授权；席位双轨（平台席位 + 应用席位），按部门或用户组动态分配；权益 API（有效、席位、功能开关、用量额度）与变更事件（开通、续费、到期、退款、席位变化）；Entitled（权益，qian.entitlement 状态机只管「买没买、能不能」）与 Enabled（租户 scope 是否挂载，scope patch）继续分开存：权益到期或撤销触发的「停用」= qian.lifecycle 自动写一条卸载该租户 scope 挂载条目的 patch，重新开通 = 重新挂载（ADR-020 D20.5、§07 7.14）。
  • ✅ ISV 侧：定价配置（改价与付费模式变更复审）、版本安装分布与升级失败视图、安装量/活跃度/收入分析；分成规则、对账单、结算周期（细则属产品决策，本章不裁决）。
  • ✅ 评分评价只对真实安装/购买的租户开放；工单直达 ISV。
  • ❌ 第三方任意代码 service 上架（Q9）；充值/兑换码；私有化租户的离线包 + 授权文件（P2，随私有化交付方案）；质量徽章/广告位/伙伴分级（P2）。

#技术落点 / 插件化定位

qian.marketplace（可替换）+ qian.entitlement + qian.billing；商业字段（价格、套餐、席位、审核状态、ISV、评分）由 qian.marketplace 以 .qian/marketplace.json 条目 name@version 为外键存平台库，不写进 marketplace.json、不复制条目字段，官方 / 私有 / 社区市场文件仍是目录的真相源（§07 7.2.4，R36）；注册表形状对齐 iClaw 的 Package / Release / Publication / Installation 四层与 pending → approve/sign → active（ADR-016）；S3 预留 server.json 兼容字段，S4 市场兼任私有 MCP registry（「应用上架」与「MCP Server 发布」合成同一 publish 动作）。

#Agent 契约

市场 API 返回机器可读包摘要（能力清单、权限、价格结构、试用、兼容性、评分）；Agent 只能提议安装/升级，付费与权限动作永远需要租户管理员确认。

#验收标准

  • 租户管理员在目录搜索到应用 → 详情页看到完整反向权限与外发域名 → 安装向导逐项批准 → 试用 7 天 → 到期自动停用 → 输入授权码开通恢复。测法：端到端 + 时钟注入。

#9.11 服务端 PDF 与大屏（P2 · S3）

  • 服务端 PDF（P2，补充裁决 Q33） ✅ 无头浏览器或 PDF 库做 HTML→PDF 作为 qian.print 的服务端渲染提供者（归档、邮件、Agent 自检需要）；K3s 资源与冷启动成本在 S3 评估后决定是否启用；服务端出图只用跨平台图形库并有失败告警。❌ 把浏览器打印下线。
  • 大屏（P2，补充裁决 Q31） ✅ 若做：React 栈重新选型，集成宽松许可的开源大屏或自研轻量查看器；只消费平台数据接口与分享链接；组件配置 = 声明式绑定 + 受限表达式（禁函数字符串）；地图数据走 qian.geo 平台级共享；分享与访问密码走 qian.share-link。❌ 不复用参考平台大屏源码（许可证高风险）；大屏自有数据库数据源与任意 SQL；用户自写 Vue/HTML 代码组件（HTML 仅 iframe 沙箱 + 声明式参数可选）。
  • 验收 - [ ] （若启用 PDF）同一打印模板浏览器打印与服务端 PDF 版式一致（视觉回归阈值内）。 - [ ] （若做大屏）大屏数据集只能选择已启用的数据接口，SQL 文本不可用。

#9.12 计量计费（P0 模型 · S3）

#范围与边界

  • ✅ 计量事件（S1 qian.observability 计量事件规范的 S3 落地）：统一以租户 / 项目双键计量——tenant_id 必填、project_id? 可选（对齐 iClaw S2S claim 形状，ADR-016），再细分 plugin_id / principal_kind(user|service|agent) / capability_id；计量维度：席位（用户数）、存储、API 调用、Operation 运行、模型用量（§10.5 的消费者用量按租户归集）。
  • ✅ 聚合与账单：计量事件进时序/日志栈 → 按天聚合 → 与套餐配额比对 → 预算告警 → 周账单/月结；Usage Ledger 是否与 iClaw 共用待 S3 拍板（Q15），本章先按「Qian 自有 Ledger + 对账接口」写。
  • ✅ 配额执行：超额策略按套餐配置（告警 / 限流 / 只读）；配额口径与 9.2 一致。
  • ✅ 结算：ISV 分成规则、对账单、结算周期；在线支付与发票对接 P2（国内增值税发票流程属推断，待产品决策）。
  • ❌ 充值与兑换码；按用户级 AppSecret 计量。

#验收标准

  • 租户 T 当月 API 调用 12,345 次、模型 token 1.2M：用量视图、计量事件聚合、账单脚本三者一致（差异 < 1%）。测法：注入已知流量后对账。
  • 项目维度计量：同一租户两个 project_id 的用量可分别查询，缺省无 project 的调用归入租户级。测法：接口测试。
  • 超出套餐 API 配额后按策略返回 429 并发告警事件。测法：压测。

不做理由
第三方任意代码容器（service）上架Q9：审核与运维量级不可控；只开放 package / function / connector / 受限 ui；service 仅 private 租户专属部署可用
每租户 issuer / 自定义登录域改 issuerQ4：单 issuer；自定义域只换登录页宿主
用户级 AppSecret 与「公有」免鉴权开放接口补充裁决 Q35：统一应用级客户端凭据；匿名只经能力令牌
参考平台大屏源码复用、大屏自有库与任意 SQL、用户自写 Vue 组件许可证高风险；多租户安全；React 栈
旧版报表设计器（两套设计器、直连任意库）不维护两套；PaaS 不允许插件直连任意库
原生 App本期不做；H5/PWA 为主，小程序与 App 以壳嵌 H5
内部 IM、自研服务器监控非平台主线；多副本下单机指标无意义

在途流程实例迁移新版本、隔离策略在线迁移需求不明；是否作付费服务待拍板
