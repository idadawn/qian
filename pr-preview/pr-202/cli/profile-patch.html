Markdown 链接

#7.1 分层模型与叠加顺序

运行中的 Qian 是一棵插件树，由启动时按序叠加的层组成，后层覆盖前层（D20.7）：

层序层来源内容
0…n组合包层profile bundles[] 按列出顺序，每个组合包一层组合包的 config/qian.patch.yml（以插入条目为主）
n+1profile patchprofiles/<name>/qian.patch.yml本 profile 的替换 / 禁用 / 插入
n+2home patch$QIAN_HOME/qian.patch.yml（默认 ~/.qian/qian.patch.yml）开发者本机或节点级覆盖
n+3CLI overlay--patch <file>（可重复，按出现顺序）一次性覆盖（CI、故障演练）
运行中租户 scope patch数据库表（§7.6）租户 scope 的条目（启用 / 禁用 / 定制）

叠加规则：条目身份 = (scope, id)；后层同身份记录替换整个 config（不深合并——改一个字段就把整个 config 写一遍，这保证 dump-config 的任何条目都能原样复制成一条 patch）；后层给出 plugin 时替换组件（Provider 替换），省略则沿用；disabled: true 使条目从树中移除，更后的层可再 disabled: false；插入新条目时 plugin 必填、config 可为 {}（由 configSchema 的 default 补齐）；层叠完成后统一 Resolve（§5.6），层序只影响覆盖关系不影响挂载顺序；每条记录带来源 layer，dump-config 原样打印。

#7.2 profile 文件 profiles/<name>/qian.profile.yml

name: platform
description: 平台宿主：base 组合包 + shell 组合包 + 可选 model-gateway 组合包（R31）；不承诺 AOT
bundles:                                   # 按序叠加；可带 range，解析结果写进 .qian/lock.json
  - qian.bundle.base@^1
  - qian.bundle.shell@^1
  - qian.bundle.model-gateway@^1           # 可选；其条目默认 disabled，需在 profile patch 里启用
patch: ./qian.patch.yml                    # profile 自己的 patch（可省略）
hmr:
  surfaces: true                           # 声明式表面运行中重载（S1 支持）
  code: false                              # 代码热装卸（S2 可选；S1 校验器拒绝 true）
build:
  aot: false                               # gateway profile 为 true（D20.10）；为 true 时树中不得出现 hmr.code、function 形态与非 AOT 组件
hooks:
  allowCommand: true                       # hooks.json 的 command 类型是否执行（默认 false，§11.4）
health:
  readyRequiresTiers: [system]             # 这些 tier 的条目 Failed 时 /readyz 失败

name 与目录名一致，也是 qian --profile <name> 的参数；profile 之间不继承（与 scope 同一哲学），共用内容放组合包。build.aot / hmr / health / hooks.allowCommand 四个字段已裁决保留（R41）。

#7.3 组合包的声明方式

组合包是组件，随 NuGet / npm 包分发，包内放在 qian/ 内容目录；CLI 与装载器扫描引用的包找到 qian/.qian-plugin/plugin.json。

<!-- Qian.Bundle.Base.csproj（NuGet 载体） -->
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <PackageId>Qian.Bundle.Base</PackageId>
    <Version>1.0.0</Version>
    <QianComponentRoot>.</QianComponentRoot>          <!-- Qian.Runtime.Sdk 目标：把组件文件夹打进包的 qian/ 并校验清单 -->
    <IncludeBuildOutput>false</IncludeBuildOutput>    <!-- 组合包无代码 -->
  </PropertyGroup>
  <ItemGroup>
    <PackageReference Include="Qian.Runtime" Version="1.0.0" />
    <PackageReference Include="Qian.Tenancy" Version="1.0.0" />
    <PackageReference Include="Qian.Files" Version="1.0.0" />
    <!-- …与 plugin.json runtime.nuget[] 一致；源生成器比对，漂移即构建失败 -->
  </ItemGroup>
  <ItemGroup>
    <QianComponentFile Include=".qian-plugin/**;config/**;skills/**;assets/**;README.md;AGENTS.md" />
  </ItemGroup>
</Project>
// package.json（npm 载体：前端组合包或声明式组件）
{ "name": "@qian/bundle-shell-base", "version": "1.0.0",
  "files": [".qian-plugin", "config", "skills", "ui", "assets", "README.md", "AGENTS.md"],
  "qian": { "component": ".qian-plugin/plugin.json" },
  "peerDependencies": { "@qian/runtime": "^1" },
  "dependencies": { "@qian/shell": "^1.0.0", "@qian/files-client": "^1.0.0" } }

#7.4 patch 条目格式 qian.patch.yml

一份 patch 文件是条目数组，每条按 https://qian.dev/schemas/patch/v2 校验。

字段类型必填说明
id^[a-z][a-z0-9.-]*$是条目 id；与 scope 构成身份
scopeglobal 或 <kind>:<id>否，默认 global文件 patch 允许写租户 scope（开发与演练）；生产的租户 scope 条目以数据库为准
plugin<component-id>[@<version>]插入时是省略版本 = lock 中已解析版本
configobject插入时是整个配置对象（整体替换）
disabledboolean否从树中移除
notestring否说明，dump-config 原样打印

示例（profiles/platform/qian.patch.yml：生产换 OSS、启用模型网关、给某租户独立的 S3 桶）：

- id: files
  config:
    storage: { kind: oss, bucket: qian-prod, endpoint: "https://oss-cn-hangzhou.example.internal",
               accessKey: "secretRef://platform/oss/access-key", secretKey: "secretRef://platform/oss/secret-key" }
    quota: { perTenantBytes: 53687091200 }
  note: 生产用 OSS；配额 50 GiB
- id: model-gateway
  disabled: false
- id: files
  scope: tenant:t-001
  plugin: qian.files
  config:
    storage: { kind: s3, bucket: t-001-files, endpoint: "https://s3.example.internal",
               accessKey: "secretRef://tenant/t-001/s3/access-key", secretKey: "secretRef://tenant/t-001/s3/secret-key" }
  note: 租户 t-001 要求数据落自己的桶（租户 scope 遮蔽全局 files）

#7.6 租户 scope patch 的数据库表形态

租户层存放在 qian.registry 拥有的 PG schema plugin_qian_registry，一行 = 一条 patch 记录，按同一份 patch/v2 Schema 校验（应用层 IPatchValidator，与文件 patch 共用实现）：

CREATE TABLE plugin_qian_registry.scope_patches (
  tenant_id       text        NOT NULL,            -- RLS 键；app / agent-session scope 也归属某租户（lineage）
  scope           text        NOT NULL,            -- 'tenant:t-001' | 'app:crm-7' | 'agent-session:s-9'
  entry_id        text        NOT NULL,
  plugin          text        NULL,                -- 组件 id（插入 / 替换 Provider 时非空）
  plugin_version  text        NULL,
  config          jsonb       NULL,                -- 整个 config；NULL = 沿用全局条目 config
  disabled        boolean     NOT NULL DEFAULT false,
  note            text        NULL,
  revision        integer     NOT NULL DEFAULT 1,  -- 乐观并发
  updated_by      text        NOT NULL,
  updated_at      timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (tenant_id, scope, entry_id)
);
-- RLS：tenant_id = NULLIF(current_setting('app.current_tenant_id', true), '')（Kun RLS 拦截器装配，ADR-004）

qian.registry 在租户上下文建立时把该租户的行叠为运行中的最后一层，并发出 registry/entry-mounted / registry/entry-disabled。租户挂载状态只存这张表，不再有 v1 的 Enabled / Disabled 状态机（R34）；「买没买、能不能」留在 qian.entitlement：写入前调用 ctx.Entitlement().CheckAsync(tenant, plugin)，未授权返回 NOT_ENTITLED；policy.required: true 的组件拒绝写入 disabled: true。写入路径：管理面 PUT /api/registry/tenants/{tenant}/patches/{scope}/{entry}（幂等，带 revision，§9.5）与 CLI qian add --scope tenant:<id>，两者已由 S1-RT-029 接入单条写入（R86）：正文为 {revision, patch}，目标租户只取路径；平台主体经超管旁路审计，租户需 qian.registry:scope:write（默认 Owner）且权益端口缺席时 fail-closed；CLI 每次只操作一个条目，过期修订 409 CONFLICT 不自动重试。管理面 403 的 pointer 以逻辑文档 registry/scope-patches.json 为前缀：#/n 是该 scope patch 行按条目标识排序后的序号，无该行时指向文档根 #，被 profile 某层禁用时指向该层文件位置（R87）。注册表是运行态的真相源，组件文件夹是分发形态，二者共用校验器（R35）。

#7.7 S1 五个 profile 的组合包清单（R31 落位表）

组合包数量与边界由组合包定义而不是决策（D20.7）；下表是 R31 给出的落位。规范术语：「平台插件」= policy.tier: system 的组件，「系统插件」只作别名。

profile组合包组合包内容（条目 → 组件）备注
platformqian.bundle.base + qian.bundle.shell + 可选 qian.bundle.model-gatewaybase：原 18 个平台插件按 seam 拆包——registry、lifecycle、capabilities、hooks、tenancy、identity → qian.identity.client、authz、data、files、config → qian.config.apollo、events、audit、observability、notify + 三个渠道、scheduler、realtime、entitlement（§7.3），并携带平台运维技能 / 命令 / 钩子表面；shell：shell → qian.shell（yue 外壳静态制品与外壳 API）；model-gateway：model-gateway → qian.model-gateway（P1，默认 disabled: true）不承诺 AOT
gatewayqian.bundle.gatewaygateway → qian.gateway、identity → qian.identity.client（Cookie 换 S2S、JWKS）、config → qian.config.apollo、observability、audit可 AOT：build.aot: true
identityqian.bundle.identity-serveridentity → qian.identity.server（可嵌入 OpenIddict，唯一 issuer）、identity.connector.oidc、identity.connector.wecom（连接器组件，经 ctx.IdentityConnectors() 注册 oidc / wecom，R28 / R38）、tenancy、data、config → qian.config.apollo、events、audit、files（头像，可选）独立安全边界

minimalqian.bundle.minimal测试与 SDK 基准宿主，仅 Qian.Runtime 与声明式表面装载器；组合包初始 patch 为空，无默认业务组件（S1-DEC-012，2026-10-09 确认）TCK 宿主、CLI 自身运行时

minimal 的 config、observability、hooks、docs 均为按需添加的组件，不进入默认组合包；表面装载器不因解析 hook 声明而依赖业务 hook Provider。该口径与 PRD §7.0.4 及 S1-RT-002 验收一致，裁决记录见 ADR-020 §7.1。

平台插件三件套 qian.registry / qian.lifecycle / qian.capabilities 的包名与服务键为 Qian.Registry（ctx.Registry）、Qian.Lifecycle（ctx.Lifecycle）、Qian.Capabilities（ctx.Capabilities），只进 platform profile（base 组合包），不供消费者独立安装（R34）；其它 profile 由 Qian.Runtime 的装载器直接从文件 patch 装树，没有数据库注册表与租户 scope patch。

S2 新增 profile lowcode（含 qian.bundle.lowcode 与 qian.bundle.file-preview）与 workflow（qian.bundle.workflow）（R31；ADR-020 §6）。前端外壳自身也是一棵由 @qian/runtime 装载的插件树（D20.2），其 profile 随 qian.bundle.shell 内置。
