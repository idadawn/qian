First NeuroAgent-integration-ready Kun release — 2026-04-23

本文档是 GitHub Release 文案的 authoring source。主控在打 tag 时可直接将本文件内容粘到 Release body。CHANGELOG.md §[0.1.0-phase1] 与本文档互为补充：CHANGELOG 面向所有历史 的细粒度条目，Release notes 面向本次 tag 的消费者沟通。

#✨ Highlights

  • 10 个新 Phase 1 模块 落地并进入 CI AOT 矩阵：Kun.Storage / Kun.Identity / Kun.MultiTenancy / Kun.Audit / Kun.RateLimit / Kun.Caching / Kun.Observability / Kun.Configuration / Kun.Sandbox，以及 Kun.Security 的增强（trace_id claim 传播、IOutboxWriter 适配）。
  • 18 模块 AOT 一致性审计通过：所有 IsAotCandidate=true 模块 dotnet publish -p:PublishAot=true -p:TreatWarningsAsErrors=true 零 trim/AOT warning（见 docs/architecture/AOT-audit-2026-04-23.md）。CI 以矩阵 job 分别验证每个模块并 附加 sample-aot-integration job 做 Kun.Sample.Minimal 的 native publish + run 冒烟。
  • NeuroAgent Phase 1 依赖满足：消费侧 neuroagent-csharp 只需锚定 0.1.0-phase1 的 Kun.* 即可获得沙箱 / 审计 / 零信任 / 多租户 / 限流 / 缓存 / 工件存储 / 可观测性 / OIDC 客户端 / 强类型配置能力（详见下方"Known-Good 组合"）。
  • Kun.Sandbox 与 E2B v2 兼容：SandboxCreateOptions 字段名与 JSON 线序匹配 E2B POST /v2/sandboxes 协议；backend selector 一行切换 UseSupervisor / UseE2BCloud（Phase 2+ 占位）/ UseInMemory（单元测试用）。
  • Directory.Build.props 重构：csproj 侧只需声明 <IsAotCandidate>true|false</IsAotCandidate> 单一开关，其余 trim/AOT 属性全部集中继承。

完整模块清单与 ADR 索引见 docs/whitepaper.md §13 与 docs/architecture/module-map.md。

#🔄 Breaking Changes

本次 tag 属于 pre-release，对已有 API 的契约变更如下：

  • Kun.Saga: IsAotCandidate 从 true 降为 false。原因：Persistence/Ef/*.cs 透传 Kun.EntityFrameworkCore → ILC 暴露 IL2091 / IL2060 / IL2026 / IL3050。
    • 消费方影响：如果你的服务之前依赖 Kun.Saga 作为 AOT 候选并开启了 <PublishTrimmed>true</PublishTrimmed>，现在 Kun.Saga.dll 不再被 trim， 你的 publish 产物会变大若干 MB。
    • 迁移：无需改代码；等 Phase 2 的 Kun.Saga.EntityFrameworkCore 子模块拆出后 （跟踪编号 P2-KN-Saga-EF-Split），Kun.Saga 核心会恢复 AOT 候选状态。
  • Kun.Dapper: 显式 IsAotCandidate=false（此前字段缺失）。
    • 消费方影响：语义化修复，实际构建行为无变化（字段缺失时默认即为 false）。
    • 迁移：无需操作。
  • Directory.Build.props：csproj 侧重复声明的 <IsTrimmable> / <IsAotCompatible> / <EnableTrimAnalyzer> / <EnableAotAnalyzer> / <EnableSingleFileAnalyzer> / <EnableDynamicLoading> 不再被允许；现只保留 <IsAotCandidate>true|false</IsAotCandidate> 这一单一开关。
    • 消费方影响：如果你基于 Kun 模板复制过这些字段到下游 csproj，可以删除。
    • 迁移：检查下游 csproj，保留 <IsAotCandidate>，删除其余 AOT 相关属性。

#🗺️ Migration Guide — 从 main 切到 develop 消费 Kun 的用户

对于已经在消费 Kun main 分支（1.0.0 M6 系列）且打算迁到 0.1.0-phase1 的下游：

  1. 包版本对齐： 
    <!-- Directory.Packages.props in consumer repo -->
<PackageVersion Include="Kun.Core"   Version="0.1.0-phase1" />
<PackageVersion Include="Kun.Mediator" Version="0.1.0-phase1" />
<!-- … 所有 Kun.* 都锁到同一版本，不要混用 -->
  2. 新增 Phase 1 模块的 csproj 引用（按需）： 
    <ProjectReference Include="...Kun.Sandbox..." />
<ProjectReference Include="...Kun.Audit..." />
<ProjectReference Include="...Kun.Identity..." />
    NuGet 消费者改用 <PackageReference> 即可。
  3. 组合根更新：按 README 最小集成示例 的顺序装配 AddKunObservability → AddKunServiceAuthentication + AddKunSecurity → AddKunAudit().UseEventBus() → AddKunSandbox(...)。
  4. Saga 消费方：如之前开启了 PublishTrimmed，注意 Kun.Saga.dll 不再 trim； 如果非 AOT 路径，无需操作。
  5. CI AOT 矩阵对齐（可选）：如果消费方也跑 AOT 矩阵，把新的 10 个 AOT 候选模块 列入本地矩阵以保持一致性。

#🚧 Known Limitations

  • E2BCloudSandboxProvider 为 Phase 2+ 占位：构造成功，调用 CreateAsync 抛 NotImplementedException。生产路径请使用 UseSupervisor。
  • Kun.Saga 暂非 AOT 候选（见上 Breaking Changes）。P2-KN-Saga-EF-Split 解决。
  • NuGet.org 正式发版未执行：本 tag 通过 GitHub Release prerelease 通道分发； NuGet.org push 走人工节奏（主控审核 + 手工 dotnet nuget push），不在本 tag 的自动化链路里。
  • .NET Aspire Dashboard 的 service-discovery env vars 未在 CI 中装配， 因此 Kun.Sample.Tests 在 CI 里被过滤；本地 dotnet run --project samples/Kun.Sample.AppHost 可跑。
  • Kun.Sample.Catalog 为 IsAotCandidate=false（使用了 MapCommand<T,R> + WriteAsJsonAsync<T>）；AOT canary 是 Kun.Sample.Minimal，由 tests/Kun.Integration.AotTests 在 CI 中做 native publish + run 冒烟。
  • release.yml 对 -phase1 后缀的 prerelease 识别目前仅匹配 -(alpha|beta|rc)； 主控在 Release 页面需手动勾选 "Set as a pre-release"（或后续 PR 放宽正则）。
